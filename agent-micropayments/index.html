Foundations

What Are Agent Micropayments?

Agent micropayments are sub-cent, programmatic transfers between autonomous systems — no human approval, no invoice cycle, no bank wire. They enable AI agents to buy and sell services at machine speed.

⚡

Instant Finality

Transactions settle in under 500ms. An agent can pay for an API call and receive the result in the same request cycle — no async confirmation dance required.

🔬

Sub-Cent Granularity

Bill for exactly what is used. A 1,000-token LLM inference costs $0.0003; a weather API lookup costs $0.0001. Micropayments make these economics viable at scale.

🤖

Machine-to-Machine

No human in the loop. Agents negotiate, pay, and verify entirely programmatically using signed requests and escrow-backed receipts.

📦

Batch Aggregation

Purple Flea batches micro-transfers to amortize per-transaction overhead. 100 sub-cent payments aggregate into one settled transfer, reducing fees to near zero.

🔒

Trustless Escrow

Funds are locked in escrow until service delivery is confirmed. Neither party can rug the other — the contract releases on proof of fulfillment.

🔄

Streaming Payments

Pay-as-you-stream: funds drip per second, per token, or per compute unit while a long-running job executes. Cancel at any time; unused balance refunds instantly.

Purple Flea Escrow

Trustless Escrow for Micropayment Batching

Individual sub-cent transfers are expensive to secure individually. Purple Flea escrow batches micropayments into settled transfers while guaranteeing delivery on both sides of the transaction.

1

Buyer Locks Funds

Agent deposits credits into escrow. Funds are locked; seller can see the commitment before serving.

2

Service Executes

Seller delivers the service — API response, data stream, or compute result. Each unit is logged with a receipt hash.

3

Batch Aggregation

100 to 10,000 micro-deliveries are aggregated into a single settlement event to minimize overhead.

4

Proof Submission

Seller submits a signed proof-of-delivery bundle. Purple Flea verifies the receipt merkle root.

5

Funds Released

Escrow releases payment to seller minus 1% fee. 15% of that fee goes to the referring agent automatically.

Architecture

Payment Channel Patterns

Choose the right pattern for your agent's interaction model. Purple Flea supports all major micropayment architectures out of the box with no custom integration required.

📡

Request-Response (Pay-Per-Call)

The simplest pattern: buyer sends a signed micropayment token with each API request. The server verifies the token, processes the request, and records the payment. Best for stateless services with well-defined per-call pricing where low overhead matters.

Stateless Low Overhead
🌊

Payment Streaming (Drip Billing)

Buyer opens a payment channel with a deposit. Funds drip to the seller in real time as a service is consumed — per token generated, per second of compute, per byte transferred. The channel closes when funds are exhausted or the buyer explicitly cancels.

Real-Time Cancellable
📦

Batch Escrow (Commit-Reveal)

Buyer commits a lump sum to escrow upfront. Seller delivers a batch of services and submits a proof bundle. Escrow releases the proportional payment, and unused balance refunds automatically. Best for high-volume, high-frequency micro-deliveries where atomicity is required.

High Volume Trustless
🤝

Subscription Channel (Prepaid Credits)

Buyer purchases a block of credits upfront. Each service call debits from the credit pool. Credits never expire; unused credits can be withdrawn at any time. Simplifies budget management for agents with predictable, recurring workloads across multiple providers.

Budget-Friendly Non-Expiring
🔀

Multi-Party Split (Revenue Sharing)

A single payment fans out to multiple recipients in one atomic transaction. Used for agent networks where an orchestrator pays a pool of specialist agents simultaneously, or for referral splits at time of settlement — all in a single escrow release call.

Atomic Splits Multi-Recipient
Code Example

Python MicropaymentAgent Class

A drop-in Python class for agents that need to buy and sell services using Purple Flea micropayments. Handles escrow creation, batch tracking, and settlement automatically.

Python micropayment_agent.py 
import httpx
import asyncio
from dataclasses import dataclass, field
from decimal import Decimal
from typing import Optional

PURPLE_FLEA_BASE = "https://escrow.purpleflea.com"

@dataclass
class EscrowBatch:
    escrow_id: str
    seller_agent_id: str
    balance: Decimal
    per_unit_rate: Decimal
    units_used: int = 0
    receipts: list = field(default_factory=list)

    def can_afford(self, units: int = 1) -> bool:
        return self.balance >= self.per_unit_rate * units

    def record_usage(self, units: int, receipt_hash: str):
        self.units_used += units
        self.balance -= self.per_unit_rate * units
        self.receipts.append(receipt_hash)


class MicropaymentAgent:
    """
    AI agent that buys and sells services via Purple Flea micropayments.
    Supports batch escrow, per-call billing, and streaming payment channels.
    """

    def __init__(self, agent_id: str, token: str):
        self.agent_id = agent_id
        self.token = token
        self.client = httpx.AsyncClient(
            base_url=PURPLE_FLEA_BASE,
            headers={"Authorization": f"Bearer {token}"},
            timeout=10.0
        )
        self._active_batches: dict[str, EscrowBatch] = {}

    # Buying Services

    async def open_batch(
        self,
        seller_agent_id: str,
        budget_usdc: str = "0.50",
        batch_limit: int = 5000,
        service_type: str = "api_calls",
        expiry_seconds: int = 3600
    ) -> EscrowBatch:
        """Lock funds in escrow for a batch of micropayments."""
        r = await self.client.post("/escrow/create", json={
            "seller_agent_id": seller_agent_id,
            "amount_usdc": budget_usdc,
            "batch_limit": batch_limit,
            "service_type": service_type,
            "expiry_seconds": expiry_seconds,
        })
        r.raise_for_status()
        data = r.json()
        batch = EscrowBatch(
            escrow_id=data["escrow_id"],
            seller_agent_id=seller_agent_id,
            balance=Decimal(data["amount"]),
            per_unit_rate=Decimal(data["per_unit_rate"]),
        )
        self._active_batches[seller_agent_id] = batch
        return batch

    async def pay_for_service(
        self,
        seller_agent_id: str,
        units: int = 1,
        metadata: Optional[dict] = None
    ) -> str:
        """Debit the escrow batch and get a signed payment token."""
        batch = self._active_batches.get(seller_agent_id)
        if not batch:
            batch = await self.open_batch(seller_agent_id)
        if not batch.can_afford(units):
            raise ValueError(f"Insufficient escrow balance for {units} units")
        r = await self.client.post("/escrow/debit", json={
            "escrow_id": batch.escrow_id,
            "units": units,
            "metadata": metadata or {},
        })
        r.raise_for_status()
        token = r.json()["payment_token"]
        batch.record_usage(units, r.json()["receipt_hash"])
        return token

    # Selling Services

    async def verify_payment_token(self, token: str) -> dict:
        """Verify an inbound payment token before serving the request."""
        r = await self.client.post("/escrow/verify-token", json={"token": token})
        r.raise_for_status()
        return r.json()

    async def submit_proof_bundle(self, escrow_id: str, receipts: list) -> dict:
        """Submit proof-of-delivery bundle to release escrow funds."""
        r = await self.client.post("/escrow/settle", json={
            "escrow_id": escrow_id,
            "receipts": receipts,
        })
        r.raise_for_status()
        return r.json()

    # Balance Management

    async def get_balance(self) -> dict:
        r = await self.client.get(f"/agent/{self.agent_id}/balance")
        r.raise_for_status()
        return r.json()

    async def close_batch(self, seller_agent_id: str) -> dict:
        """Close an active batch; unused balance refunds automatically."""
        batch = self._active_batches.pop(seller_agent_id, None)
        if not batch:
            return {"status": "no_active_batch"}
        r = await self.client.post("/escrow/close", json={"escrow_id": batch.escrow_id})
        r.raise_for_status()
        return r.json()

    async def __aenter__(self):
        return self

    async def __aexit__(self, *args):
        await self.client.aclose()


# Usage Example
async def example():
    async with MicropaymentAgent("agent_abc123", "your_token_here") as agent:
        # Open a $0.50 escrow batch with a data seller
        batch = await agent.open_batch(
            seller_agent_id="data_seller_001",
            budget_usdc="0.50",
            batch_limit=5000,
            service_type="price_feed"
        )
        print(f"Opened escrow {batch.escrow_id}, balance: {batch.balance} USDC")

        # Call the paid API 1000 times
        for i in range(1000):
            token = await agent.pay_for_service("data_seller_001", units=1)
            # Pass token in your API request header:
            # response = await data_api.get("/price", headers={"X-Payment": token})

        # Close batch and refund unused balance
        result = await agent.close_batch("data_seller_001")
        print(f"Batch closed. Refund: {result['refund_usdc']} USDC")

if __name__ == "__main__":
    asyncio.run(example())
