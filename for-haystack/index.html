Overview

Financial infrastructure that fits your pipeline

Haystack by Deepset is the leading open-source framework for building RAG pipelines and AI agent systems. Every Purple Flea integration inherits ComponentBase, meaning your components serialize to YAML, connect through Haystack's typed socket system, and run in any Haystack executor — local, Docker, or cloud.

Quick Start

From zero to on-chain trades in 20 lines

This example creates a Haystack pipeline that runs a wallet creation step in parallel with a perpetual trading step, then collects both results into a single structured output dictionary. All component parameters are type-checked by Haystack before execution.

pipeline_example.py 
import os
from haystack import Pipeline
from haystack.components.generators import OpenAIGenerator
from purpleflea.haystack import WalletComponent, TradingComponent, CasinoComponent

# Instantiate Purple Flea components
wallet  = WalletComponent(api_key=os.getenv("PURPLE_FLEA_API_KEY"))
trading = TradingComponent(api_key=os.getenv("PURPLE_FLEA_API_KEY"))

# Build and wire the pipeline
pipeline = Pipeline()
pipeline.add_component("wallet", wallet)
pipeline.add_component("trading", trading)

# Run: wallet creation + long ETH-PERP in one call
result = pipeline.run({
    "wallet":  {"action": "create"},
    "trading": {
        "market":   "ETH-PERP",
        "side":     "long",
        "size_usd": 100
    }
})

print(result["wallet"]["address"])
print(result["trading"]["fill_price"])

RAG + Finance

Ground trades in retrieved knowledge

Combine Haystack's native document retrieval with Purple Flea's trading components to build data-driven agent strategies. A BM25 or dense retriever can fetch the latest market commentary, earnings reports, or on-chain analytics, then pass a structured summary downstream to TradingComponent as a trading signal.

Because Haystack pipelines are fully serializable, you can store a "RAG-guided trading pipeline" as a YAML file, version it in git, and deploy it to any Haystack executor without code changes. Parameters like leverage and slippage tolerance stay in the YAML; secrets stay in environment variables.

This architecture means your agent is not just reacting to prompts — it is retrieving vetted documents, reasoning over them with an LLM, and executing financial operations in a single coherent pipeline run with full auditability.

rag_trading.py 
from haystack.components.retrievers import \
    InMemoryBM25Retriever
from haystack.components.builders import \
    PromptBuilder
from purpleflea.haystack import TradingComponent

p = Pipeline()
p.add_component("retriever", retriever)
p.add_component("builder",   prompt_builder)
p.add_component("llm",       llm)
p.add_component("trading",   trading)

# Wire: docs → prompt → LLM → trade
p.connect("retriever.documents",
          "builder.documents")
p.connect("builder.prompt",
          "llm.prompt")
p.connect("llm.trade_params",
          "trading.params")
Serialization

Ship pipelines as YAML

Haystack's pipeline serialization works seamlessly with Purple Flea components. Save your trading or casino pipeline as a YAML config file, check it into source control, and load it on any machine with Pipeline.load().

Note: Secrets like api_key are resolved from environment variables at load time — they are never written into the YAML file. Use env_vars: [PURPLE_FLEA_API_KEY] in the component block to declare the binding.
trading_pipeline.yml 
version: "2.0"
components:
  wallet:
    type: purpleflea.haystack.WalletComponent
    env_vars: [PURPLE_FLEA_API_KEY]
    init_params:
      default_currency: "ETH"
  trading:
    type: purpleflea.haystack.TradingComponent
    env_vars: [PURPLE_FLEA_API_KEY]
    init_params:
      default_leverage: 3
      slippage_bps: 15
connections:
  - sender:   "wallet.address"
    receiver: "trading.funding_address"
metadata:
  name: "purple-flea-trading-pipeline"
  version: "1.0.0"
