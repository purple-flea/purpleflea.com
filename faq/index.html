The casino currently offers four provably fair games:

  • Coin Flip — 50/50, pays 1.95x. The simplest game, ideal for testing strategies.
  • Crash — multiplier grows from 1x and can crash at any point. Cash out before crash to win.
  • Dice — roll over/under a target number. Configurable house edge via target selection.
  • Roulette — European-style single-zero roulette. Bet on numbers, colors, rows, or columns.

All games accept bets from $0.01 USDC. Full game docs: Casino API Reference.

Every casino outcome uses a commit-reveal scheme with HMAC-SHA256:

  1. Before your bet, the server commits to a server seed by publishing its SHA-256 hash
  2. You optionally provide a client seed (or the server generates one)
  3. The outcome is HMAC-SHA256(server_seed, client_seed + nonce), reduced to game range
  4. After the bet, the server reveals the raw server_seed
  5. You can verify: recompute the HMAC and confirm it matches the published hash

Every bet response includes a proof object with all values needed to verify. Verify any historical bet:

GET https://casino.purpleflea.com/api/v1/verify/:bet_id

Wallets 4 questions

The Wallet API generates HD BIP-39 wallets and derives addresses for: Ethereum, Base, Arbitrum, Polygon, BNB Chain, Solana, Bitcoin (BIP-84 native SegWit), and Tron. All addresses are derived from a single BIP-39 mnemonic using chain-specific derivation paths.

Cross-chain swaps are supported via Wagyu aggregator, which routes through 1inch, Paraswap (EVM), Jupiter (Solana), Li.Fi, and 0x Protocol.

The Wallet API is a non-custodial HD wallet generator. When you call POST /v1/wallet/create, the server generates a BIP-39 mnemonic and returns it to you in the response. The server does not store your private keys or mnemonic after generation — you must save them securely.

For signing and broadcasting transactions, you provide the private key (or the server can sign transiently in memory if you send the key in the request). See the Wallet API docs for security architecture details.

BIP-44 derivation paths are used per chain:

  • Ethereum / EVM: m/44'/60'/0'/0/0
  • Bitcoin (SegWit): m/84'/0'/0'/0/0
  • Solana: m/44'/501'/0'/0'
  • Tron: m/44'/195'/0'/0/0

All EVM chains (Ethereum, Base, Arbitrum, Polygon, BNB) share the same private key and address from the m/44'/60'/0'/0/0 path. See the BIP-39 for AI Agents guide for full derivation details.

Use the swap endpoint:

POST https://wallet.purpleflea.com/v1/swap
Body: {"from_chain":"ethereum","to_chain":"solana","from_token":"USDC","to_token":"USDC","amount":"100","slippage":0.5}

The API returns the best route across all aggregators, estimated output, and gas costs. Confirm with a POST /v1/swap/confirm call. Full swap docs: Cross-Chain Swap API.

MCP & Technical 4 questions

MCP (Model Context Protocol) is a standard developed by Anthropic that lets AI frameworks — Claude, LangChain, CrewAI, AutoGen, and others — call external tools natively as if they were built-in capabilities.

Purple Flea's Faucet and Escrow services expose StreamableHTTP MCP endpoints at /mcp. Add the URL to your MCP client config and the AI framework discovers available tools automatically — no manual API integration needed.

Both servers are listed on Smithery for one-click installation.

Add this to your claude_desktop_config.json (found at ~/Library/Application Support/Claude/ on macOS):

{
  "mcpServers": {
    "purpleflea-faucet": {
      "url": "https://faucet.purpleflea.com/mcp"
    },
    "purpleflea-escrow": {
      "url": "https://escrow.purpleflea.com/mcp"
    }
  }
}

Restart Claude Desktop. Both MCP servers appear in the tools list. You can then ask Claude to "claim the faucet for agent ag_xxx" or "create an escrow for 5 USDC" and it will call the API automatically.
