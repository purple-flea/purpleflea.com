Structured Products for AI Agents: Principal Protection Meets DeFi Yield

March 6, 2026 · 12 min read · Purple Flea Research

Most DeFi products force a binary choice: take full market risk, or stay in stablecoins and earn yield. Structured products break this tradeoff. They allow an agent to say: "I want at least 80% of my capital back no matter what, but I also want upside if ETH goes up 30%." This is the core promise of principal protection combined with conditional upside — a combination that traditional banks have sold to retail investors for decades, now available on-chain.

For AI agents managing treasury, structured products solve a critical problem: how to deploy capital productively without catastrophic downside. A multi-agent DAO with a 10,000 USDC treasury cannot afford a 60% drawdown. A principal-protected note with partial upside participation is a rational alternative to pure stablecoin parking.

What Are Structured Products?

A structured product is a packaged combination of a risk-free (or near-risk-free) component and a derivative component. The risk-free component provides the floor on returns. The derivative component provides the conditional upside. Classic structure:

Product Value = Floor Component + Upside Component Floor Component: Zero-coupon bond or lending protocol deposit Grows to guarantee minimum payout at maturity Upside Component: Call option (or option spread) Pays if underlying rises above strike at maturity

In traditional finance, the risk-free component is a government bond. In DeFi, it is a lending protocol deposit (Aave, Compound, Morpho) earning 4–8% APY. This yield funds the purchase of the upside component — the call option. The math: if a 1-year deposit earns 8%, you have 8% of notional to spend on the call. That 8% buys you substantial upside participation at current IV levels.

On-Chain DeFi Implementations

Structured products have moved on-chain through several mechanisms:

  • Vault-based structures: Smart contract vaults that split deposits between a yield strategy and an options purchase. Ribbon, Structured, and Opyn all have vault templates.
  • Escrow-based structures: Two-party arrangements where collateral is locked in escrow with conditional release rules. This is what Purple Flea Escrow enables — trustless maturity settlement between counterparties.
  • Token wrappers: ERC-20 tokens representing a structured note, tradeable on secondary markets before maturity. Adds liquidity but increases complexity.

Product Types

Principal-Protected Note

Floor: 80–100% of notional

Deposit earns yield to fund a call option. At maturity, receive floor + % of upside if asset rose.

Autocallable

Early recall if barrier hit

If underlying reaches the barrier (e.g., spot +20%) on any observation date, note is recalled early and coupon is paid. Else continue to maturity.

Shark Note

Boosted return below barrier

Receive 2-3x upside participation if asset stays below upper barrier. Above barrier, participation is capped (the "shark fin"). Good for range-bound expectations.

Principal-Protected Note (PPN)

Example: 1-year ETH PPN with 80% floor and 100% upside participation.

  • Deposit 1,000 USDC
  • 800 USDC goes into Aave at 8% APY → grows to 864 USDC at maturity (the floor)
  • 200 USDC buys an ETH call option with 1-year expiry, strike at current spot
  • If ETH is up 40% at maturity: receive 864 (floor) + 400 USDC (40% × 1,000 notional) = 1,264 USDC
  • If ETH is down 50% at maturity: receive 864 USDC (floor protected)

The agent never receives less than 864 USDC (86.4% of initial deposit), regardless of ETH's performance. The downside protection comes at no cost beyond foregone stablecoin yield on the 200 USDC spent on the call.

Autocallable Note

An autocallable note has observation dates (e.g., monthly). On each date, if the underlying is above the barrier (typically 100–120% of initial spot), the note is "called" — the investor receives principal plus a coupon. If not triggered, the note continues to the next observation date.

Autocallables typically pay higher coupons than PPNs because the issuer benefits from early recall in favorable markets. The tradeoff is complexity: the pricing involves barrier options (knock-outs), which require more sophisticated models.

Shark Note

The shark note provides leveraged participation below an upper barrier and no participation above it. If an agent expects ETH to rise 15–25% but not more, a shark note extracts maximum value from that range:

  • Below barrier (e.g., spot +30%): 2.5x participation rate. ETH up 20% → note pays 50% return.
  • Above barrier: return is capped at 2.5× × barrier level. ETH up 60% → note still pays 75%.
  • If ETH is flat or down: floor protects principal (subject to floor percentage).

Pricing Model

The Black-Scholes framework prices the option component. Key inputs:

Black-Scholes Call Price (simplified): C = S·N(d1) - K·e^(-rT)·N(d2) d1 = [ln(S/K) + (r + σ²/2)·T] / (σ·√T) d2 = d1 - σ·√T Where: S = current spot price K = strike price r = risk-free rate (lending protocol APY) σ = implied volatility (from options market) T = time to maturity in years N = cumulative standard normal distribution

For perpetual-funded products, the funding rate adds an additional cost component. If you are hedging via Hyperliquid perps (Purple Flea's perp infrastructure), the funding rate — typically 0.01–0.05% per 8 hours — must be factored into the total hedge cost over the product's tenor.

Python — Structured Product Pricer
import numpy as np
from scipy.stats import norm
from dataclasses import dataclass
from typing import Optional

@dataclass
class StructuredProductSpec:
    notional: float        # Total deposit (USDC)
    floor_pct: float       # e.g. 0.80 for 80% floor
    participation: float   # e.g. 1.0 for 100% participation
    tenor_years: float     # e.g. 1.0 for 1 year
    lending_apy: float     # e.g. 0.08 for 8%
    spot: float            # Current asset price
    strike: Optional[float] = None  # Defaults to ATM
    implied_vol: float = 0.80      # ETH IV, typically 70-120%
    risk_free: float = 0.05


def bs_call_price(S, K, T, r, sigma) -> float:
    """Standard Black-Scholes call price."""
    if T <= 0:
        return max(S - K, 0)
    d1 = (np.log(S / K) + (r + 0.5 * sigma**2) * T) / (sigma * np.sqrt(T))
    d2 = d1 - sigma * np.sqrt(T)
    return S * norm.cdf(d1) - K * np.exp(-r * T) * norm.cdf(d2)


def price_ppn(spec: StructuredProductSpec) -> dict:
    """
    Price a principal-protected note.
    Returns allocation split and expected payoff scenarios.
    """
    if spec.strike is None:
        spec.strike = spec.spot

    # Floor component: how much to deposit in lending to grow to floor
    # floor_notional * (1 + lending_apy) ^ tenor = floor_pct * notional
    floor_required = spec.notional * spec.floor_pct
    floor_deposit = floor_required / ((1 + spec.lending_apy) ** spec.tenor_years)
    option_budget = spec.notional - floor_deposit

    # Option cost for 1 unit of underlying
    option_price_per_unit = bs_call_price(
        S=spec.spot,
        K=spec.strike,
        T=spec.tenor_years,
        r=spec.risk_free,
        sigma=spec.implied_vol,
    )

    # Units of option we can buy with option_budget
    option_units = option_budget / option_price_per_unit
    effective_participation = option_units / (spec.notional / spec.spot)

    # Payoff scenarios
    scenarios = {}
    for pct_change in [-0.5, -0.3, -0.1, 0.0, 0.15, 0.30, 0.50, 1.0]:
        final_spot = spec.spot * (1 + pct_change)
        floor_value = floor_deposit * ((1 + spec.lending_apy) ** spec.tenor_years)
        option_payoff = max(final_spot - spec.strike, 0) * option_units
        total_payout = floor_value + option_payoff
        net_return = (total_payout - spec.notional) / spec.notional
        scenarios[f"{pct_change:+.0%}"] = {
            "payout_usdc": round(total_payout, 2),
            "net_return": f"{net_return:+.1%}",
        }

    return {
        "floor_deposit": round(floor_deposit, 2),
        "option_budget": round(option_budget, 2),
        "option_units": round(option_units, 4),
        "effective_participation": f"{effective_participation:.0%}",
        "scenarios": scenarios,
    }


def price_autocallable(
    notional: float,
    barrier_pct: float,
    coupon_pct: float,
    observation_dates: int,
    spot: float,
    sigma: float,
    risk_free: float = 0.05,
) -> dict:
    """
    Simplified autocallable pricing via Monte Carlo.
    barrier_pct: e.g. 1.20 for 20% above spot
    coupon_pct: e.g. 0.15 for 15% annual coupon
    """
    barrier = spot * barrier_pct
    dt = 1.0 / observation_dates
    n_simulations = 50000
    payoffs = []

    for _ in range(n_simulations):
        path = spot
        called = False
        for t in range(1, observation_dates + 1):
            path *= np.exp(
                (risk_free - 0.5 * sigma**2) * dt +
                sigma * np.sqrt(dt) * np.random.normal()
            )
            if path >= barrier:
                # Called early: return notional + coupon
                coupon = notional * coupon_pct * (t / observation_dates)
                payoffs.append(notional + coupon)
                called = True
                break
        if not called:
            # At maturity: return notional if above 80% floor
            final_floor = notional * 0.80
            payoffs.append(max(path / spot * notional, final_floor))

    expected_payoff = np.mean(payoffs)
    return {
        "expected_payoff": round(expected_payoff, 2),
        "expected_return": f"{(expected_payoff / notional - 1):+.1%}",
        "p_called": f"{sum(1 for p in payoffs if p > notional) / n_simulations:.1%}",
    }

Issuance via Purple Flea Escrow

Purple Flea's Escrow service is purpose-built for structured product issuance between agents. The mechanics for a two-agent structured note:

  1. Buyer agent deposits notional into Escrow — funds are locked at POST /api/v1/escrow/create with a maturity condition attached.
  2. Issuer agent deploys the collateral — lends the floor component to a protocol, buys the option with the remainder. Issuer's address and conditions are recorded in the escrow contract.
  3. Maturity event triggers settlement — an oracle provides the final price. If conditions are met, escrow releases according to payoff formula. If not, floor is returned to buyer. 1% fee applies to total settlement volume.
  4. Referral commission — any agent that introduced the counterparties earns 15% of the 1% fee as referral commission on settlement.

const ESCROW_API = "https://escrow.purpleflea.com/api/v1";

async function issueStructuredNote({
  buyerAddress,
  issuerAddress,
  notionalUsdc,
  floorPct,          // e.g. 0.80
  participationPct,  // e.g. 1.0
  tenorDays,         // e.g. 365
  underlyingAsset,   // e.g. "ETH"
  apiKey,
}) {
  const maturityDate = new Date();
  maturityDate.setDate(maturityDate.getDate() + tenorDays);

  const payload = {
    buyer: buyerAddress,
    issuer: issuerAddress,
    amount: notionalUsdc,
    currency: "USDC",
    product_type: "structured_note",
    terms: {
      floor_pct: floorPct,
      participation_pct: participationPct,
      underlying: underlyingAsset,
      maturity: maturityDate.toISOString(),
      settlement_oracle: "purpleflea_price_oracle",
    },
    auto_settle: true,
  };

  const res = await fetch(`${ESCROW_API}/create`, {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(payload),
  });

  const data = await res.json();
  console.log(`Escrow created: ${data.escrow_id}`);
  console.log(`Deposit address: ${data.deposit_address}`);
  console.log(`Maturity: ${data.terms.maturity}`);
  return data;
}

Agent Use Case: Multi-Agent DAO Treasury

Multi-agent DAOs pool capital across multiple agents for collective investment. Treasury management is a critical function: how do you allocate funds productively without risking the collective's operating budget?

A structured product allocation framework for a 50,000 USDC DAO treasury:

TrancheAmountProduct TypeExpected Return
Safety (40%)20,000 USDCAave stablecoin yield6–8% APY
Protected (35%)17,500 USDCPPN — 80% floor + ETH upside−14% to +60%
Growth (20%)10,000 USDCAutocallable — 20% barrier10–25% if called
Speculative (5%)2,500 USDCShark note — range-bound−100% to +150%

The safety tranche never loses money. The protected tranche limits downside to 14% of its allocation. Growth and speculative tranches carry full risk but represent a small fraction of total NAV. In the worst case (all risky tranches to zero), the DAO retains 82% of its treasury.
