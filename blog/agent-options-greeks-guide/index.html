Options Greeks for AI Agents: Delta, Gamma, Theta, Vega, and Rho Explained

Options greeks are the sensitivity measures that tell you exactly how an options position's value changes as market conditions evolve. For an AI agent managing a portfolio of positions — whether pure options, synthetic options constructed from perpetuals, or hybrid structures — understanding the greeks is the difference between controlled, hedged exposure and an account that gets liquidated on a volatility spike. This guide covers all five greeks with agent-specific implementation guidance.

Why Options Greeks Matter for AI Agents

An AI agent trading options without understanding greeks is like flying a plane without an altimeter. The position has value now, but without knowing how fast that value is changing — and in which direction — you cannot manage risk systematically. Greeks provide the mathematical framework for quantifying exposure at any moment.

For agent portfolios, the greeks matter in three specific ways:

  • Hedging decisions: How many shares of the underlying must you hold to be delta-neutral? If you hold 10 call options and the delta is 0.4, you need to short 4 units of the underlying to be flat directional exposure.
  • Scenario analysis: What happens to your portfolio if the underlying drops 10%? If volatility spikes 5 points? If 30 days pass? Greeks give you the first-order answer to all of these questions.
  • P&L attribution: When your options position makes or loses money, you need to know which greek was responsible. Was it a directional move (delta), a volatility change (vega), or time decay (theta)? Without attribution, you cannot improve your strategy.

Delta: The Hedge Ratio

Delta (Δ) measures how much an option's price changes for a $1 change in the underlying's price. A call option with Δ = 0.60 gains $0.60 in value for every $1 increase in the underlying. A put option with Δ = -0.35 loses $0.35 in value for every $1 increase (equivalently, gains $0.35 for every $1 decrease).

Δ = ∂V / ∂S    |    Call: 0 ≤ Δ ≤ 1    |    Put: -1 ≤ Δ ≤ 0

Delta also represents the probability that the option expires in-the-money under the risk-neutral measure (a rough but useful heuristic). An at-the-money option has Δ ≈ 0.50, meaning it has roughly a 50% chance of expiring in the money.

Delta-Neutral Strategies for Agents

A delta-neutral portfolio has zero net delta — the position does not benefit or lose from small directional moves in the underlying. This is the foundational hedging strategy for options market makers and premium sellers.

To delta-hedge a position:

  1. Calculate the total portfolio delta: sum each position's delta weighted by quantity and contract size
  2. Determine the offsetting hedge: if portfolio delta is +2.5, short 2.5 units of the underlying
  3. Rebalance as delta changes: delta is not constant — it changes as the underlying moves (this rate of change is gamma)

For an agent, delta-hedging frequency is a strategy parameter. Continuous hedging maintains perfect delta-neutrality but incurs transaction costs on every rebalance. Threshold hedging only rebalances when net delta exceeds a defined band (e.g., ±0.10), reducing costs while accepting some directional exposure within the band.

Option Type Moneyness Typical Delta Hedge Required
Call Deep in-the-money 0.90 – 1.00 Short ~1 unit underlying
Call At-the-money 0.45 – 0.55 Short ~0.5 units underlying
Call Out-of-the-money 0.05 – 0.30 Short ~0.1–0.3 units
Put Deep in-the-money -0.90 – -1.00 Long ~1 unit underlying
Put At-the-money -0.45 – -0.55 Long ~0.5 units underlying
Put Out-of-the-money -0.05 – -0.30 Long ~0.1–0.3 units

Gamma: Second-Order Risk

Gamma (Γ) measures how fast delta changes as the underlying moves. It is the second derivative of option value with respect to the underlying price — the acceleration of delta.

Γ = ∂Δ / ∂S = ∂²V / ∂S²    |    Always positive for long options

High gamma means your delta changes rapidly as the underlying moves. This matters for hedging: a position with high gamma requires frequent rebalancing to stay delta-neutral. At-the-money options near expiry have the highest gamma — small moves in the underlying cause large swings in delta.

Gamma Scalping for Agents

Gamma scalping is a strategy that profits from high realized volatility. The agent holds a long gamma position (long options) and continuously rehedges the delta. Each rehedge locks in a small profit from the underlying's moves. The strategy profits when realized volatility exceeds implied volatility (the vol priced into the option premium).

The gamma scalping P&L per rehedge cycle:

P&L per cycle ≈ ½ × Γ × (ΔS)²

Where ΔS is the move in the underlying since last rehedge. The strategy wins when the sum of these quadratic gains exceeds the theta decay (time value lost per day).

For an agent implementing gamma scalping:

  • Buy at-the-money straddles (long call + long put at same strike) to maximize gamma with minimal directional bias
  • Set a rehedge trigger based on delta drift exceeding a threshold (e.g., ±0.05)
  • Track cumulative gamma scalping P&L versus cumulative theta paid to assess strategy health
  • Close the position if realized vol consistently runs below implied vol — the theta bleed will not be covered

Key Relationship: Long gamma is the opposite of long theta. You cannot be both long gamma and long theta simultaneously in an options position. Market makers who sell premium (short gamma) collect theta but take gamma risk. Buyers of options (long gamma) pay theta but benefit from large moves.

Theta: Time Decay

Theta (Θ) measures how much an option's value decreases as one day passes, all else equal. It is always negative for long options (you lose time value as expiry approaches) and always positive for short options (you gain as the option you sold decays).

Θ = ∂V / ∂t    |    Typically expressed as $ lost per day

Theta decay is not linear — it accelerates as expiry approaches. An option with 30 days to expiry decays faster than the same option with 60 days to expiry. The decay curve follows roughly the square root of time to expiry.

How Agents Earn Theta by Selling Options

Selling options (writing covered calls, selling puts, or selling straddles/strangles) generates theta income. The seller receives the premium upfront and profits if the underlying does not move enough to overcome the premium received.

Common theta-positive strategies for agents:

  • Covered call: Hold the underlying long, sell an out-of-the-money call. Earns theta while capping upside. Suited to range-bound markets.
  • Cash-secured put: Hold collateral, sell an out-of-the-money put. Earns theta while obligating purchase of the underlying at a lower price. Suited to bullish agents with target entry prices.
  • Iron condor: Sell an OTM call spread and an OTM put spread simultaneously. Earns theta from both sides with defined maximum loss.
  • Short strangle: Sell an OTM call and OTM put. Maximum theta collection but unlimited theoretical risk on both sides.

The risk to theta-positive strategies is gamma — a large, fast move in the underlying erodes the collected premium and can result in losses that exceed the theta earned. This is the fundamental options tradeoff: premium sellers earn theta but pay gamma.

Strategy Theta Gamma Max Profit Max Loss
Long Call Negative Positive Unlimited Premium paid
Short Call Positive Negative Premium received Unlimited
Long Put Negative Positive Strike - Premium Premium paid
Short Strangle High Positive High Negative Total premium Unlimited
Iron Condor Positive Negative Net premium Defined (spread width)
Long Straddle Negative High Positive Unlimited Total premium paid

Vega: Volatility Exposure

Vega (ν) measures how much an option's price changes for a 1-percentage-point change in implied volatility. An option with vega = $0.25 gains $0.25 in value for every 1% increase in implied volatility. Long options are always long vega; short options are always short vega.

ν = ∂V / ∂σ    |    Long options: ν > 0    |    Short options: ν < 0

Trading Implied vs Realized Volatility

The most sophisticated options strategy is trading the gap between implied volatility (what the market prices into options) and realized volatility (what actually occurs). This gap — the volatility risk premium — historically runs positive in equity markets: implied vol tends to exceed realized vol on average, making premium selling profitable over long time horizons.

In crypto, the vol risk premium is less stable but still present. The key metrics for agents:

  • Implied Volatility (IV): The volatility implied by current option prices using the Black-Scholes model. This is the market's forward-looking estimate.
  • Realized Volatility (RV): The actual volatility of the underlying measured over a recent historical window (typically 30-day, 60-day, or 90-day).
  • IV - RV spread: When this spread is wide (IV much higher than RV), premium selling is attractive — the market is overpricing options relative to what actual volatility will be.
  • IV Rank (IVR): Where current IV sits relative to its 52-week range. IVR > 50% suggests elevated IV and favors premium selling strategies.

Agent Strategy: An agent that continuously tracks IV and RV for each market can automatically deploy short vega strategies when IV>RV by a threshold, and long vega strategies when vol is suppressed. This systematic approach removes the discretionary guesswork from vol trading.

Rho: Interest Rate Sensitivity

Rho (ρ) measures an option's sensitivity to interest rate changes. In traditional finance, rho matters because options are priced relative to risk-free rates — higher rates increase call values (via the carry cost on the underlying) and decrease put values.

ρ = ∂V / ∂r    |    Calls: ρ > 0    |    Puts: ρ < 0

In crypto, rho is generally the least important of the five greeks for several reasons:

  • Crypto options typically have short maturities (days to weeks), limiting rate sensitivity
  • Crypto risk-free rates are denominated in stablecoins or native tokens, not central bank policy rates
  • Rate movements have minimal impact on short-dated option prices compared to volatility or directional moves

However, rho becomes relevant for long-dated crypto options (90+ days) and when trading calendar spreads where the term structure of rates differs across expiries. For most agent strategies operating on daily to weekly timeframes, rho can safely be deprioritized.

Portfolio Greeks: Aggregation and P&L Attribution

A real agent does not hold a single option in isolation — it holds a portfolio of positions across multiple instruments, strikes, and expiries. Portfolio-level greeks are the sum of individual position greeks, weighted by position size.

The portfolio greek calculation:

Portfolio Δ = Σ (position_i × Δ_i × contract_size_i)

The same aggregation applies to gamma, theta, and vega. The resulting portfolio greeks tell you:

  • Portfolio Delta: Net directional exposure. If +50, you gain $50 for every $1 increase in the underlying (all else equal).
  • Portfolio Gamma: How fast your delta changes. High portfolio gamma means your hedge needs frequent adjustment.
  • Portfolio Theta: Daily time decay of the entire portfolio. Positive = earning time decay; negative = paying it.
  • Portfolio Vega: Total sensitivity to a 1% change in implied volatility across all positions.

P&L Attribution

The total P&L of an options portfolio over a time period can be decomposed into greek contributions:

ΔP&L ≈ Δ × ΔS + ½Γ × (ΔS)² + Θ × Δt + ν × Δσ

This decomposition is invaluable for strategy analysis. If your portfolio lost $500 yesterday, was it because the underlying moved against your delta ($300 loss), volatility collapsed against your long vega ($150 loss), and theta bleed ($50 loss)? Attribution answers this question and guides strategy adjustment.

Python: GreeksCalculator with Black-Scholes

Black-Scholes Greeks Calculator Python 
"""
Black-Scholes Options Greeks Calculator for AI Agents
Computes delta, gamma, theta, vega, rho for calls and puts.
Includes portfolio aggregation and P&L attribution.
"""
import math
from dataclasses import dataclass, field
from typing import List, Literal, Dict
from functools import cached_property

def norm_cdf(x: float) -> float:
    """Standard normal CDF using math.erf."""
    return (1.0 + math.erf(x / math.sqrt(2.0))) / 2.0

def norm_pdf(x: float) -> float:
    """Standard normal PDF."""
    return math.exp(-0.5 * x * x) / math.sqrt(2.0 * math.pi)

@dataclass
class OptionGreeks:
    """Stores all greeks for a single option."""
    delta: float
    gamma: float
    theta: float     # Per calendar day
    vega: float      # Per 1% change in vol
    rho: float       # Per 1% change in rate
    price: float

class GreeksCalculator:
    """
    Black-Scholes greeks calculator.

    Assumptions: European options, no dividends, continuous compounding.
    Suitable for crypto options approximation.
    """

    @staticmethod
    def d1(S: float, K: float, T: float, r: float, sigma: float) -> float:
        """Black-Scholes d1 parameter."""
        return (math.log(S / K) + (r + 0.5 * sigma**2) * T) / (sigma * math.sqrt(T))

    @staticmethod
    def d2(d1_val: float, sigma: float, T: float) -> float:
        """Black-Scholes d2 parameter."""
        return d1_val - sigma * math.sqrt(T)

    def compute(
        self,
        S: float,           # Current underlying price
        K: float,           # Strike price
        T: float,           # Time to expiry in years (e.g., 30/365)
        r: float,           # Risk-free rate (e.g., 0.05 for 5%)
        sigma: float,       # Implied volatility (e.g., 0.80 for 80%)
        option_type: Literal["call", "put"] = "call"
    ) -> OptionGreeks:
        if T <= 0:
            raise ValueError("Time to expiry must be positive")
        if sigma <= 0:
            raise ValueError("Implied volatility must be positive")

        sqrt_T = math.sqrt(T)
        d1 = self.d1(S, K, T, r, sigma)
        d2 = self.d2(d1, sigma, T)
        disc = math.exp(-r * T)

        if option_type == "call":
            price = S * norm_cdf(d1) - K * disc * norm_cdf(d2)
            delta = norm_cdf(d1)
            rho = K * T * disc * norm_cdf(d2) / 100
        else:
            price = K * disc * norm_cdf(-d2) - S * norm_cdf(-d1)
            delta = norm_cdf(d1) - 1.0
            rho = -K * T * disc * norm_cdf(-d2) / 100

        # Gamma is same for calls and puts
        gamma = norm_pdf(d1) / (S * sigma * sqrt_T)

        # Theta: first term is common, sign flips on last term
        theta_common = -(S * norm_pdf(d1) * sigma) / (2 * sqrt_T)
        if option_type == "call":
            theta = (theta_common - r * K * disc * norm_cdf(d2)) / 365
        else:
            theta = (theta_common + r * K * disc * norm_cdf(-d2)) / 365

        # Vega: per 1% change in vol
        vega = S * norm_pdf(d1) * sqrt_T / 100

        return OptionGreeks(
            delta=delta, gamma=gamma, theta=theta,
            vega=vega, rho=rho, price=price
        )

@dataclass
class PortfolioPosition:
    instrument: str
    option_type: Literal["call", "put", "underlying"]
    quantity: float          # Positive = long, negative = short
    contract_size: float     # Units of underlying per contract
    # Option parameters (None for underlying)
    strike: float = 0.0
    expiry_days: float = 0.0
    implied_vol: float = 0.0
    greeks: OptionGreeks = None

class PortfolioGreeksManager:
    """
    Aggregates greeks across a portfolio of options + underlying.
    Provides P&L attribution and hedge recommendations.
    """
    def __init__(self, risk_free_rate: float = 0.05):
        self.positions: List[PortfolioPosition] = []
        self.calc = GreeksCalculator()
        self.r = risk_free_rate

    def add_option(self, pos: PortfolioPosition, underlying_price: float):
        if pos.option_type != "underlying":
            T = pos.expiry_days / 365
            pos.greeks = self.calc.compute(
                S=underlying_price,
                K=pos.strike,
                T=T,
                r=self.r,
                sigma=pos.implied_vol,
                option_type=pos.option_type
            )
        self.positions.append(pos)

    def portfolio_greeks(self) -> Dict[str, float]:
        """Compute net portfolio greeks across all positions."""
        total = {"delta": 0.0, "gamma": 0.0, "theta": 0.0, "vega": 0.0, "rho": 0.0}
        for pos in self.positions:
            scale = pos.quantity * pos.contract_size
            if pos.option_type == "underlying":
                total["delta"] += scale * 1.0   # Underlying has delta=1
            elif pos.greeks:
                total["delta"] += scale * pos.greeks.delta
                total["gamma"] += scale * pos.greeks.gamma
                total["theta"] += scale * pos.greeks.theta
                total["vega"] += scale * pos.greeks.vega
                total["rho"] += scale * pos.greeks.rho
        return total

    def hedge_recommendation(self, underlying_price: float) -> str:
        """Generate a plain-English hedge recommendation."""
        greeks = self.portfolio_greeks()
        delta = greeks["delta"]
        hedge_units = abs(delta) / 1  # 1 unit of underlying = delta 1

        if abs(delta) < 0.05:
            return "Portfolio is delta-neutral. No hedge required."
        direction = "short" if delta > 0 else "long"
        hedge_usd = hedge_units * underlying_price
        return (
            f"Portfolio delta: {delta:+.3f}. "
            f"Hedge: {direction} {hedge_units:.4f} units "
            f"(${hedge_usd:,.2f}) of underlying."
        )

    def pnl_attribution(self, dS: float, d_sigma: float, dt_days: float) -> Dict[str, float]:
        """First-order P&L attribution by greek."""
        g = self.portfolio_greeks()
        attribution = {
            "delta_pnl": g["delta"] * dS,
            "gamma_pnl": 0.5 * g["gamma"] * dS**2,
            "theta_pnl": g["theta"] * dt_days,
            "vega_pnl":  g["vega"] * d_sigma * 100,  # d_sigma as decimal
        }
        attribution["total_pnl"] = sum(attribution.values())
        return attribution

# --- Example Usage ---
if __name__ == "__main__":
    manager = PortfolioGreeksManager(risk_free_rate=0.05)
    underlying_price = 65_000.0  # BTC at $65,000

    # Long 2 call options, strike $68k, 30 days, IV=85%
    manager.add_option(PortfolioPosition(
        instrument="BTC-CALL-68000-30D",
        option_type="call", quantity=2, contract_size=1,
        strike=68_000, expiry_days=30, implied_vol=0.85
    ), underlying_price)

    # Short 1 put option, strike $60k, 30 days, IV=90%
    manager.add_option(PortfolioPosition(
        instrument="BTC-PUT-60000-30D",
        option_type="put", quantity=-1, contract_size=1,
        strike=60_000, expiry_days=30, implied_vol=0.90
    ), underlying_price)

    greeks = manager.portfolio_greeks()
    print("Portfolio Greeks:")
    for k, v in greeks.items():
        print(f"  {k:8s}: {v:+.4f}")

    print()
    print(manager.hedge_recommendation(underlying_price))

    print()
    print("P&L Attribution (BTC -$2,000, IV +3%, 1 day):")
    attr = manager.pnl_attribution(dS=-2000, d_sigma=0.03, dt_days=1)
    for k, v in attr.items():
        print(f"  {k:15s}: ${v:+,.2f}")

Integration with Purple Flea: Perpetuals-Based Synthetic Options

Purple Flea's perpetual futures markets do not currently offer options contracts directly, but an agent can construct synthetic options positions using perpetuals and dynamic delta-hedging. This is the same technique used by options market makers to replicate options payoffs using the underlying.

Replicating a Long Call with Perpetuals

The Black-Scholes model provides the theoretical foundation: a long call option can be replicated by a dynamic portfolio of the underlying (held in proportion to delta) and a risk-free bond. In practice with perpetuals:

  1. Determine target delta: Use GreeksCalculator.compute() with your target strike and expiry to get the current delta of the synthetic call.
  2. Size the perpetual position: Buy delta × notional units of the perpetual. This is your synthetic long call position.
  3. Rebalance as delta changes: As the underlying price moves, recalculate delta and adjust the perpetual position size. This is the dynamic hedging that replicates the option's convexity.
  4. Pay/receive funding: Perpetuals have a funding rate that acts as the carry cost. Factor this into your synthetic premium calculation.
Synthetic Call Replication — Purple Flea Perpetuals Python 
import asyncio
import aiohttp
from greeks_calculator import GreeksCalculator  # from above

class SyntheticCallAgent:
    """
    Replicates a long call option using Purple Flea perpetuals
    via continuous delta-hedging. The agent dynamically adjusts
    the perpetual position as delta changes.

    The 'premium' is the initial capital locked up; the synthetic
    call profits if the underlying exceeds the target level.
    """
    REHEDGE_DELTA_BAND = 0.02  # Rehedge when delta drifts by 0.02
    PF_API = "https://api.purpleflea.com"

    def __init__(
        self,
        api_key: str,
        market: str,          # e.g., "BTC-PERP"
        notional_usd: float,  # Total capital to deploy
        strike: float,        # Target price level
        expiry_days: float,   # How many days to hold
        implied_vol: float,   # Estimated volatility for delta calc
    ):
        self.api_key = api_key
        self.market = market
        self.notional_usd = notional_usd
        self.strike = strike
        self.expiry_days = expiry_days
        self.implied_vol = implied_vol
        self.calc = GreeksCalculator()
        self._current_delta: float = 0.0
        self._position_units: float = 0.0
        self._days_elapsed: float = 0.0

    def _compute_target_delta(self, current_price: float) -> float:
        T = max((self.expiry_days - self._days_elapsed) / 365, 1/365)
        greeks = self.calc.compute(
            S=current_price, K=self.strike,
            T=T, r=0.05, sigma=self.implied_vol,
            option_type="call"
        )
        return greeks.delta

    async def _get_position(self, session: aiohttp.ClientSession) -> dict:
        async with session.get(
            f"{self.PF_API}/trading/positions/{self.market}",
            headers={"Authorization": f"Bearer {self.api_key}"}
        ) as r:
            return await r.json()

    async def _adjust_position(self, session: aiohttp.ClientSession, target_units: float, current_price: float):
        delta_units = target_units - self._position_units
        if abs(delta_units) < 0.001:
            return
        side = "buy" if delta_units > 0 else "sell"
        async with session.post(
            f"{self.PF_API}/trading/orders",
            json={
                "market": self.market, "side": side,
                "type": "market", "qty": abs(delta_units)
            },
            headers={"Authorization": f"Bearer {self.api_key}"}
        ) as r:
            result = await r.json()
            if result.get("status") == "filled":
                self._position_units = target_units
                print(f"Rehedged: {side} {abs(delta_units):.4f} units @ {current_price:,.2f}")

    async def rehedge_once(self, current_price: float):
        target_delta = self._compute_target_delta(current_price)
        target_units = target_delta * (self.notional_usd / current_price)

        if abs(target_delta - self._current_delta) >= self.REHEDGE_DELTA_BAND:
            print(f"Delta drift: {self._current_delta:.3f} → {target_delta:.3f}")
            async with aiohttp.ClientSession() as session:
                await self._adjust_position(session, target_units, current_price)
            self._current_delta = target_delta

# --- Main Execution ---
async def main():
    agent = SyntheticCallAgent(
        api_key="your_pf_api_key",
        market="BTC-PERP",
        notional_usd=10_000,
        strike=70_000,
        expiry_days=30,
        implied_vol=0.85
    )

    # Run rehedge check every 60 seconds
    while True:
        async with aiohttp.ClientSession() as session:
            async with session.get("https://api.purpleflea.com/trading/ticker/BTC-PERP") as r:
                data = await r.json()
                current_price = data["last_price"]
        await agent.rehedge_once(current_price)
        await asyncio.sleep(60)

if __name__ == "__main__":
    asyncio.run(main())

Sensitivity Analysis: Testing Your Position

Before deploying any greek-sensitive strategy, run a sensitivity analysis — compute how the portfolio P&L would change across a range of scenarios. The following scenarios are the minimum required for any options strategy:

Scenario Underlying Move Vol Move Time Expected P&L Driver
Large rally +20% -10 pts (vol crush) +1 day Delta gain, vega loss
Crash -20% +20 pts (vol spike) +1 day Delta loss, vega gain
Chop ±2% Flat +7 days Theta bleed
Vol expansion only Flat +15 pts +1 day Pure vega gain/loss
Vol collapse only Flat -15 pts +1 day Pure vega loss/gain

Warning: The Black-Scholes model assumes log-normal price distribution and constant volatility. Real crypto markets exhibit heavy tails, volatility clustering, and discontinuous jumps. Use Black-Scholes greeks as a guide, not gospel — stress test your positions against tail scenarios that Black-Scholes would consider impossibly rare.
