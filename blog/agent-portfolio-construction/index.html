Portfolio Construction for Multi-Strategy AI Trading Agents

Running a single trading strategy is easy. Running ten strategies that don't eat each other alive is a discipline. This guide covers the quantitative toolkit for building robust multi-strategy AI agent portfolios: mean-variance optimization, risk parity, regime-aware allocation, correlation monitoring, and transaction cost-aware rebalancing — all wired into Purple Flea's trading and wallet APIs.

1. Portfolio Construction Principles

A multi-strategy AI agent is not just a collection of trading bots running in parallel — it is a portfolio. The same principles that govern institutional quantitative funds apply: diversification, correlation management, and disciplined rebalancing. Ignore them and your strategies will cluster around the same trades, amplifying drawdowns instead of smoothing them.

Diversification Beyond Asset Classes

For AI trading agents, diversification has three orthogonal dimensions: strategy (trend-following vs. mean-reversion vs. arbitrage), time horizon (HFT scalpers vs. 4-hour DCA vs. weekly momentum), and market regime sensitivity (strategies that profit in trending markets vs. ranging markets). True diversification requires low correlation across all three dimensions simultaneously.

  • Strategy diversification: Mix momentum, carry, mean-reversion, and volatility strategies so that at least one performs well in any macro regime.
  • Time-horizon diversification: Combine high-frequency scalpers with slower swing strategies. They share little correlation even in the same market.
  • Market diversification: Spread across BTC, ETH, and altcoin markets. Correlations rise in crises but remain low during normal periods.

Correlation is the Enemy of Diversification

Two trend-following strategies on the same market with different parameters are not diversified — they are correlated. The pairwise correlation matrix of your strategy returns is the primary diagnostic tool. Keep average pairwise correlation below 0.4. When correlations spike above 0.7 during market stress, reduce position sizes across all correlated strategies proportionally.

Key insight: Correlation is not static. Two strategies with a 3-month correlation of 0.2 can reach 0.8 during a market crash when all momentum strategies stop working simultaneously. Build your portfolio for the correlation structure you will face in the worst 5% of market conditions, not the median.

Rebalancing: The Free Lunch That Requires Discipline

Rebalancing drifting strategy allocations back to target weights systematically sells outperformers and buys underperformers — a form of automatic contrarian bet. Academic evidence shows rebalancing adds 0.5–1% annualized to multi-asset portfolios. For AI agents with multiple strategies, the effect is larger because strategy performance is more mean-reverting than asset prices.

2. Mean-Variance Optimization for Strategy Allocation

Markowitz mean-variance optimization (MVO) finds the allocation vector w that maximizes the Sharpe ratio of the portfolio given expected returns and the covariance matrix of strategy returns. For AI agents, "expected returns" are estimated from historical strategy performance, and the covariance matrix is computed from rolling return windows.

The Optimization Problem

Given N strategies with expected excess returns μ (over risk-free rate) and covariance matrix Σ, we solve:

maximize: w' * mu - (lambda / 2) * w' * Sigma * w
subject to: sum(w) = 1
            w_i >= 0 (long-only constraint)
            w_i <= max_weight (concentration limit)

Where lambda is the risk-aversion parameter. Higher lambda means more weight on variance reduction relative to return maximization. For AI agents running live capital, start with lambda = 2–4 to produce conservative allocations.

Python portfolio/optimizer.py 
import numpy as np
from scipy.optimize import minimize
from typing import List, Dict, Optional
import requests, os, logging

logger = logging.getLogger(__name__)


class AgentPortfolioOptimizer:
    """
    Quantitative portfolio optimizer for multi-strategy AI trading agents.

    Supports:
      - Mean-variance optimization (maximize Sharpe)
      - Risk parity allocation
      - Regime-aware weight adjustment
      - Transaction cost-aware rebalancing
      - Purple Flea API integration for live execution
    """

    def __init__(
        self,
        strategies: List[str],
        max_weight: float = 0.40,
        min_weight: float = 0.02,
        risk_aversion: float = 2.0,
        lookback_days: int = 90,
        api_key: str = None,
    ):
        """
        Args:
            strategies:    list of strategy identifiers
            max_weight:    maximum allocation to any single strategy (default 40%)
            min_weight:    minimum allocation (avoids tiny positions)
            risk_aversion: lambda for MVO (higher = more conservative)
            lookback_days: rolling window for return estimation
            api_key:       Purple Flea API key (falls back to env var)
        """
        self.strategies    = strategies
        self.n             = len(strategies)
        self.max_weight    = max_weight
        self.min_weight    = min_weight
        self.risk_aversion = risk_aversion
        self.lookback_days = lookback_days
        self.api_key       = api_key or os.getenv("PURPLE_FLEA_API_KEY")
        self.base_url      = os.getenv("PURPLE_FLEA_BASE_URL", "https://purpleflea.com/api")

    def optimize(
        self,
        returns: np.ndarray,
        rf_rate: float = 0.0,
    ) -> Dict[str, float]:
        """
        Mean-variance optimization: find weights that maximize Sharpe ratio.

        Args:
            returns: (T x N) array of daily strategy returns
            rf_rate: daily risk-free rate (default 0)

        Returns:
            dict mapping strategy name to optimal weight
        """
        mu    = returns.mean(axis=0) - rf_rate          # excess returns
        sigma = np.cov(returns.T)                        # covariance matrix
        lam   = self.risk_aversion

        def neg_utility(w):
            port_return   = w @ mu
            port_variance = w @ sigma @ w
            return -(port_return - (lam / 2) * port_variance)

        def neg_sharpe(w):
            port_return = w @ mu
            port_vol    = np.sqrt(w @ sigma @ w)
            if port_vol < 1e-10:
                return 0
            return -port_return / port_vol

        constraints = [
            {"type": "eq", "fun": lambda w: np.sum(w) - 1}
        ]
        bounds = [(self.min_weight, self.max_weight)] * self.n
        w0     = np.ones(self.n) / self.n

        result = minimize(
            neg_sharpe,
            w0,
            method="SLSQP",
            bounds=bounds,
            constraints=constraints,
            options={"maxiter": 1000, "ftol": 1e-9},
        )

        if not result.success:
            logger.warning(f"MVO optimization did not converge: {result.message}")
            # Fall back to equal weight
            weights = np.ones(self.n) / self.n
        else:
            weights = result.x
            weights = np.clip(weights, self.min_weight, self.max_weight)
            weights /= weights.sum()  # renormalize after clipping

        return dict(zip(self.strategies, weights.tolist()))

    def risk_parity(self, returns: np.ndarray) -> Dict[str, float]:
        """
        Risk parity allocation: each strategy contributes equally to portfolio volatility.
        Inverse-volatility approximation, then refined with ERC (equal risk contribution).

        Useful when expected returns are unreliable -- allocates purely on risk.
        """
        sigma = np.cov(returns.T)

        def risk_contribution(w):
            port_vol   = np.sqrt(w @ sigma @ w)
            marginal_rc = sigma @ w
            rc          = w * marginal_rc / port_vol
            return rc

        def erc_objective(w):
            """Minimize sum of squared differences between risk contributions."""
            rc     = risk_contribution(w)
            target = rc.sum() / self.n
            return np.sum((rc - target) ** 2)

        constraints = [
            {"type": "eq", "fun": lambda w: np.sum(w) - 1}
        ]
        bounds = [(self.min_weight, self.max_weight)] * self.n
        w0     = np.ones(self.n) / self.n

        # Warm-start with inverse-volatility weights
        vols   = np.sqrt(np.diag(sigma))
        iv_w   = (1.0 / vols) / (1.0 / vols).sum()
        iv_w   = np.clip(iv_w, self.min_weight, self.max_weight)
        iv_w  /= iv_w.sum()

        result = minimize(
            erc_objective,
            iv_w,
            method="SLSQP",
            bounds=bounds,
            constraints=constraints,
            options={"maxiter": 1000, "ftol": 1e-9},
        )

        weights = result.x if result.success else iv_w
        weights = np.clip(weights, self.min_weight, self.max_weight)
        weights /= weights.sum()
        return dict(zip(self.strategies, weights.tolist()))

    def rebalance(
        self,
        current_weights: Dict[str, float],
        target_weights: Dict[str, float],
        total_portfolio_value: float,
        drift_threshold: float = 0.03,
        transaction_cost_bps: float = 10.0,
    ) -> Dict[str, float]:
        """
        Transaction cost-aware rebalancing.
        Only rebalances a strategy when its drift exceeds the threshold.

        Args:
            current_weights:       current weight of each strategy
            target_weights:        target weight of each strategy
            total_portfolio_value: total capital in USD
            drift_threshold:       only rebalance if abs(current - target) > threshold (default 3%)
            transaction_cost_bps:  one-way transaction cost in basis points (default 10bps)

        Returns:
            dict of trade sizes (positive = buy, negative = sell) per strategy in USD
        """
        trades      = {}
        total_cost  = 0.0

        for strategy in self.strategies:
            current = current_weights.get(strategy, 0.0)
            target  = target_weights.get(strategy, 0.0)
            drift   = abs(current - target)

            if drift < drift_threshold:
                logger.debug(f"{strategy}: drift {drift:.3f} below threshold, skipping")
                trades[strategy] = 0.0
                continue

            # Check if rebalance is worth it after transaction costs
            trade_size    = (target - current) * total_portfolio_value
            cost          = abs(trade_size) * (transaction_cost_bps / 10000)
            benefit_est   = drift ** 2 * total_portfolio_value * 0.01

            if cost > benefit_est:
                logger.debug(f"{strategy}: cost {cost:.2f} > benefit {benefit_est:.2f}, skipping")
                trades[strategy] = 0.0
            else:
                trades[strategy] = trade_size
                total_cost += cost
                logger.info(f"{strategy}: rebalance {trade_size:+.2f} USD (drift={drift:.3f})")

        logger.info(f"Total rebalancing cost: {total_cost:.2f} USD")
        return trades

3. Risk Parity Across Strategies

Mean-variance optimization is powerful but sensitive to input estimates. Small errors in expected returns produce wildly different allocations — the classic "garbage in, garbage out" problem. Risk parity is the alternative: allocate so that each strategy contributes equally to total portfolio volatility, ignoring expected returns entirely.

When to Prefer Risk Parity

Use risk parity when you have less than 12 months of strategy return history, when markets are in transition (regime change), or when your strategies have wildly different volatility profiles. A 5% annual-vol DCA strategy and a 60% annual-vol options-selling strategy should never receive equal capital allocations — risk parity automatically scales them proportionally.

Strategy Annual Vol Equal Weight Inv-Vol Weight ERC Weight
BTC Trend Following 45% 20% 11.2% 12.1%
ETH Mean Reversion 38% 20% 13.2% 13.8%
DCA Accumulation 15% 20% 33.5% 31.2%
Crypto Carry Trade 22% 20% 22.8% 23.4%
Stat Arb BTC/ETH 18% 20% 27.8% 27.5%

Notice how equal weighting overallocates to high-volatility strategies. The BTC trend strategy gets 20% despite being 3x more volatile than the DCA strategy. Risk parity corrects this, giving the DCA strategy 3x more capital — ensuring both contribute roughly equal volatility to the overall portfolio.

Rule of thumb: Use equal risk contribution (ERC) when strategies have correlations above 0.2. Use inverse-volatility when they are largely uncorrelated. Pure inverse-volatility ignores co-movements and will under-diversify in a correlated downturn.

4. Correlation Matrix Management

Strategies that appear uncorrelated over a full market cycle can become highly correlated during specific regimes. Your portfolio optimizer should track the rolling 30-day correlation matrix and trigger alerts or automatic reductions when correlations spike.

    def correlation_matrix(self, returns: np.ndarray) -> np.ndarray:
        """Compute Pearson correlation matrix of strategy returns."""
        return np.corrcoef(returns.T)

    def detect_correlation_spike(
        self,
        returns: np.ndarray,
        spike_threshold: float = 0.65,
        affected_frac: float = 0.4,
    ) -> dict:
        """
        Detect when a significant fraction of strategy pairs breach a
        correlation threshold -- a sign of regime stress.

        Args:
            returns:         (T x N) return matrix
            spike_threshold: pairwise correlation above this is "high"
            affected_frac:   alert if this fraction of pairs are spiked

        Returns:
            {
                "spiked": bool,
                "high_pairs": [(strat_a, strat_b, corr), ...],
                "avg_correlation": float,
                "recommended_action": str
            }
        """
        corr   = self.correlation_matrix(returns)
        pairs  = []
        total  = 0
        high   = 0

        for i in range(self.n):
            for j in range(i + 1, self.n):
                total += 1
                c = corr[i, j]
                if abs(c) >= spike_threshold:
                    high += 1
                    pairs.append((self.strategies[i], self.strategies[j], c))

        frac   = high / total if total > 0 else 0
        avg    = (corr.sum() - self.n) / (self.n * (self.n - 1)) if self.n > 1 else 0
        spiked = frac >= affected_frac

        action = "none"
        if spiked:
            action = "reduce_all_positions_by_30_percent"
        elif frac > 0.2:
            action = "reduce_correlated_positions_by_15_percent"

        return {
            "spiked":             spiked,
            "high_pairs":         pairs,
            "avg_correlation":    round(avg, 4),
            "fraction_spiked":    round(frac, 4),
            "recommended_action": action,
        }

    def decorrelate_weights(
        self,
        weights: Dict[str, float],
        returns: np.ndarray,
        max_pairwise_corr: float = 0.6,
        reduction_factor: float = 0.7,
    ) -> Dict[str, float]:
        """
        Reduce weights of highly correlated strategy pairs.
        Iteratively identifies the highest-corr pair and reduces
        the smaller strategy's weight until all pairs are below threshold.
        """
        w    = {s: weights[s] for s in self.strategies}
        corr = self.correlation_matrix(returns)
        modified = True
        iterations = 0

        while modified and iterations < 20:
            modified   = False
            iterations += 1
            for i in range(self.n):
                for j in range(i + 1, self.n):
                    c = corr[i, j]
                    if abs(c) > max_pairwise_corr:
                        # Reduce the smaller-weight strategy
                        si, sj = self.strategies[i], self.strategies[j]
                        if w[si] <= w[sj]:
                            w[si] *= reduction_factor
                        else:
                            w[sj] *= reduction_factor
                        modified = True
                        logger.info(f"Decorrelated {si}/{sj}: corr={c:.3f}, reduced weight")

        # Renormalize
        total = sum(w.values())
        return {s: v / total for s, v in w.items()}

5. Regime-Aware Allocation

Different market regimes favor different strategy types. A pure trend-following strategy earns its best returns during persistent bull or bear markets. Mean-reversion strategies thrive in low-volatility, ranging markets. Volatility strategies collect premium in calm conditions but blow up in crashes. A regime-aware portfolio adjusts weights as market conditions change.

Defining Regimes Quantitatively

Avoid subjective regime labels. Use quantitative signals that can be computed deterministically from market data:

  • Trend signal: 50-day EMA above/below 200-day EMA (golden/death cross).
  • Volatility regime: 20-day realized vol relative to its 252-day percentile (low/medium/high vol).
  • Correlation regime: Average pairwise correlation of crypto top-10 (dispersed/clustered).
  • Funding rate signal: Perpetual futures funding rate > 0.01% per hour = crowded longs.

def detect_regime(
    prices: np.ndarray,
    vol_percentile_thresh_low: float = 0.33,
    vol_percentile_thresh_high: float = 0.80,
) -> Regime:
    """
    Classify current market regime from price series.

    Args:
        prices: 1D array of closing prices (most recent last), min 252 days
    """
    returns = np.diff(np.log(prices))

    # Trend: 50d EMA vs 200d EMA
    ema50  = _ema(prices, 50)[-1]
    ema200 = _ema(prices, 200)[-1]
    is_bull = ema50 > ema200

    # Volatility: 20d realized vol vs 252d percentile
    vol_20d  = returns[-20:].std() * np.sqrt(252)
    vol_hist = np.array([returns[i:i+20].std() * np.sqrt(252)
                         for i in range(len(returns) - 20)])
    vol_pct  = (vol_hist < vol_20d).mean()

    # Crisis detection: vol above 80th pct + sharp drawdown
    drawdown = (prices[-1] - prices[-20:].max()) / prices[-20:].max()
    if vol_pct > vol_percentile_thresh_high and drawdown < -0.15:
        return Regime.CRISIS

    if is_bull:
        if vol_pct > vol_percentile_thresh_high:
            return Regime.RANGING_HIGH
        return Regime.BULL_TRENDING
    else:
        if vol_pct < vol_percentile_thresh_low:
            return Regime.RANGING_LOW
        return Regime.BEAR_TRENDING


def _ema(prices: np.ndarray, period: int) -> np.ndarray:
    alpha = 2 / (period + 1)
    ema   = np.zeros_like(prices)
    ema[0] = prices[0]
    for i in range(1, len(prices)):
        ema[i] = alpha * prices[i] + (1 - alpha) * ema[i - 1]
    return ema
Caution on regime trading: Regime signals have significant lag. By the time a "bear trending" regime is confirmed, much of the trend may already be over. Use regime weights as gentle tilts (multipliers in the 0.5–1.5 range) rather than binary on/off switches. Hard-switching strategies off causes large rebalancing costs and performance chasing.

6. Transaction Cost-Aware Rebalancing

Rebalancing costs money. Every trade incurs the bid-ask spread, exchange fees, and market impact. For an AI agent running on Purple Flea's trading API, transaction costs are approximately 10–15 basis points per round trip. A naive rebalancer that targets exact weights daily will bleed the portfolio in trading costs.

The Drift-Threshold Rule

Only rebalance a strategy position when its actual weight drifts more than a threshold from the target. The optimal threshold balances the cost of drift (sub-optimal allocation) against the cost of transacting (fees). Academic research suggests 3–5% threshold bands for quarterly rebalancing in equity portfolios. For AI agent crypto strategies with higher volatility, 5–8% bands are appropriate.

Python portfolio/rebalancer.py 
import numpy as np
from typing import Dict, List, Tuple
import logging

logger = logging.getLogger(__name__)


class CostAwareRebalancer:
    """
    Rebalances agent strategy allocations only when drift exceeds a
    threshold and the expected benefit exceeds the transaction cost.
    """

    def __init__(
        self,
        drift_threshold: float = 0.05,
        transaction_cost_bps: float = 12.0,
        min_trade_usd: float = 10.0,
    ):
        self.drift_threshold      = drift_threshold
        self.transaction_cost_bps = transaction_cost_bps
        self.min_trade_usd        = min_trade_usd

    def compute_trades(
        self,
        current_values: Dict[str, float],
        target_weights: Dict[str, float],
    ) -> List[Tuple[str, float]]:
        """
        Compute which strategies need rebalancing and by how much.

        Args:
            current_values: current dollar value allocated to each strategy
            target_weights: desired weight for each strategy (sum to 1)

        Returns:
            list of (strategy, trade_usd) where positive = add capital, negative = withdraw
        """
        total      = sum(current_values.values())
        current_w  = {s: v / total for s, v in current_values.items()}
        trades     = []
        skipped    = 0
        executed   = 0

        for strategy, target_w in target_weights.items():
            current_w_s = current_w.get(strategy, 0.0)
            drift       = target_w - current_w_s
            drift_abs   = abs(drift)

            if drift_abs < self.drift_threshold:
                skipped += 1
                continue

            trade_usd = drift * total
            cost      = abs(trade_usd) * self.transaction_cost_bps / 10_000

            if abs(trade_usd) < self.min_trade_usd:
                logger.debug(f"{strategy}: trade too small ({trade_usd:.2f}), skip")
                skipped += 1
                continue

            # Benefit approximation: drift squared times portfolio size
            # This is a heuristic; proper calculation requires Sigma
            benefit = drift_abs ** 2 * total * 0.015

            if cost > benefit:
                logger.debug(
                    f"{strategy}: cost {cost:.2f} > benefit {benefit:.2f} USD, skip"
                )
                skipped += 1
                continue

            trades.append((strategy, trade_usd))
            executed += 1
            logger.info(
                f"Rebalance {strategy}: {trade_usd:+.2f} USD "
                f"(drift={drift_abs:.3f}, cost={cost:.2f})"
            )

        logger.info(
            f"Rebalance: {executed} trades, {skipped} skipped. "
            f"Total trades: {sum(abs(t) for _, t in trades):.2f} USD"
        )
        return trades

    def optimal_threshold(
        self,
        annual_vol: float,
        annual_drift_cost: float = 0.005,
        transaction_cost_pct: float = 0.0012,
    ) -> float:
        """
        Analytically compute the optimal drift threshold.

        Uses the Dybvig (2005) closed-form approximation:
            threshold = sqrt(3 * TC * sigma^2 / drift_cost)

        Args:
            annual_vol:          annualized strategy return volatility
            annual_drift_cost:   cost of being 1% off-target per year (default 50bps)
            transaction_cost_pct: one-way transaction cost as fraction (default 12bps)

        Returns:
            Optimal threshold as a fraction (e.g. 0.05 = 5%)
        """
        daily_vol   = annual_vol / np.sqrt(252)
        daily_drift = annual_drift_cost / 252
        threshold   = np.sqrt(3 * transaction_cost_pct * daily_vol ** 2 / daily_drift)
        return float(np.clip(threshold, 0.02, 0.15))

            resp.raise_for_status()
            daily_pnl = resp.json()["daily_pnl"]
            returns_matrix.append(daily_pnl)

        return np.array(returns_matrix).T  # (T x N)

    def fetch_current_allocations(self) -> Dict[str, float]:
        """Get current USD value allocated to each strategy from wallet API."""
        resp = requests.get(
            f"{PURPLE_FLEA_API}/wallet/strategy-allocations",
            headers=self._headers,
            timeout=10,
        )
        resp.raise_for_status()
        return resp.json()["allocations"]  # {strategy_id: usd_value}

    def fetch_market_prices(self, market: str = "BTC-USDC", days: int = 252) -> np.ndarray:
        """Fetch BTC price series for regime detection."""
        resp = requests.get(
            f"{PURPLE_FLEA_API}/markets/{market}/ohlcv",
            params={"days": days, "interval": "1d"},
            headers=self._headers,
            timeout=15,
        )
        resp.raise_for_status()
        candles = resp.json()["candles"]
        return np.array([c["close"] for c in candles])

    def run_rebalance_cycle(self) -> dict:
        """
        Full portfolio rebalance cycle:
        1. Fetch returns and current allocations
        2. Detect market regime
        3. Compute optimal weights (MVO or risk parity)
        4. Apply regime tilts
        5. Check correlation and decorrelate if needed
        6. Execute rebalancing trades via Purple Flea API
        """
        logger.info("Starting portfolio rebalance cycle")
        timestamp = datetime.now(timezone.utc).isoformat()

        # Step 1: Data
        returns    = self.fetch_strategy_returns()
        alloc      = self.fetch_current_allocations()
        prices     = self.fetch_market_prices()
        total      = sum(alloc.values()) or self.total_capital_usd

        # Step 2: Regime
        regime = detect_regime(prices)
        logger.info(f"Detected regime: {regime.value}")

        # Step 3: Optimize
        if self.rebalance_mode == "risk_parity":
            base_weights = self.optimizer.risk_parity(returns)
        else:
            base_weights = self.optimizer.optimize(returns)

        # Step 4: Apply regime tilts
        regime_weights = {}
        for strategy, w in base_weights.items():
            stype      = self.strategy_types.get(strategy, "default")
            multiplier = DEFAULT_REGIME_TABLE.get_multiplier(stype, regime)
            regime_weights[strategy] = w * multiplier

        # Renormalize
        total_rw = sum(regime_weights.values())
        regime_weights = {s: v / total_rw for s, v in regime_weights.items()}

        # Step 5: Decorrelate
        spike_check = self.optimizer.detect_correlation_spike(returns)
        if spike_check["spiked"]:
            logger.warning(f"Correlation spike: {spike_check['recommended_action']}")
            regime_weights = self.optimizer.decorrelate_weights(regime_weights, returns)

        # Step 6: Execute rebalancing
        current_w = {s: v / total for s, v in alloc.items()}
        trades = self.rebalancer.compute_trades(alloc, regime_weights)
        executed = []
        for strategy, trade_usd in trades:
            result = self._execute_allocation_trade(strategy, trade_usd)
            executed.append(result)

        return {
            "timestamp":      timestamp,
            "regime":          regime.value,
            "target_weights":  regime_weights,
            "trades_executed": executed,
            "corr_spike":      spike_check["spiked"],
        }

    def _execute_allocation_trade(self, strategy: str, trade_usd: float) -> dict:
        """
        Move capital to/from a strategy bucket via Purple Flea wallet API.
        Positive = allocate more capital; negative = withdraw.
        """
        action = "allocate" if trade_usd > 0 else "deallocate"
        resp = requests.post(
            f"{PURPLE_FLEA_API}/wallet/strategy-allocations",
            json={
                "strategy": strategy,
                "action":   action,
                "amount":   abs(trade_usd),
            },
            headers=self._headers,
            timeout=15,
        )
        resp.raise_for_status()
        result = resp.json()
        logger.info(f"Executed: {action} {abs(trade_usd):.2f} USD for {strategy}")
        return result

8. Bringing It All Together

The full portfolio management loop for a multi-strategy AI agent combines all the components above into a single orchestration script. Run this on a schedule — daily, or every 4 hours — to maintain optimal allocations as market conditions evolve.

Python portfolio/run_portfolio.py 
import logging, os
from portfolio.live_manager import LivePortfolioManager

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)


# Define strategies and their types for regime adjustment
STRATEGIES = [
    "btc-trend-daily",
    "eth-mean-reversion",
    "btc-dca-4h",
    "btc-eth-stat-arb",
    "perp-funding-carry",
]

STRATEGY_TYPES = {
    "btc-trend-daily":  "trend_following",
    "eth-mean-reversion": "mean_reversion",
    "btc-dca-4h":       "dca_accumulation",
    "btc-eth-stat-arb": "stat_arbitrage",
    "perp-funding-carry":"stat_arbitrage",
}


def main():
    manager = LivePortfolioManager(
        strategies=STRATEGIES,
        strategy_types=STRATEGY_TYPES,
        total_capital_usd=float(os.getenv("PORTFOLIO_CAPITAL", "10000")),
        rebalance_mode="mvo",
    )

    result = manager.run_rebalance_cycle()

    logger.info(f"Rebalance complete:")

    for s, w in result["target_weights"].items():
        logger.info(f"    {s}: {w:.1%}")
    logger.info(f"  Trades executed: {len(result['trades_executed'])}")
    return result


if __name__ == "__main__":
    main()

9. Portfolio Performance Metrics

Track these metrics weekly to monitor whether your portfolio construction is working as intended. Red flags: correlation above 0.6 on more than 30% of strategy pairs, Sharpe below 0.5, or maximum drawdown exceeding 20%.

Metric Target Warning Zone How to Compute
Portfolio Sharpe > 1.0 < 0.5 Annualized return / annualized vol
Max Drawdown < 15% > 25% (peak - trough) / peak value
Avg Pairwise Corr < 0.35 > 0.6 Mean of off-diagonal correlation matrix
Effective N > 3.5 < 2.0 1 / sum(w^2) — diversification ratio
Calmar Ratio > 0.5 < 0.2 Annual return / max drawdown
Turnover (monthly) < 20% > 50% Sum of absolute weight changes / 2

10. Conclusion

Portfolio construction is the difference between a collection of trading bots and a fund. Mean-variance optimization finds the theoretically optimal strategy weights. Risk parity handles the estimation uncertainty inherent in short return histories. Regime-aware allocation tilts exposure toward strategies suited for the current market environment. Correlation monitoring prevents the illusion of diversification from masking hidden crowding.

The AgentPortfolioOptimizer class above is a complete starting point. Wire it to Purple Flea's trading API for live execution, schedule it via Celery Beat for automated rebalancing, and instrument the key metrics to know when your portfolio construction is drifting from its intended risk profile.

The goal is not to maximize returns in isolation — it is to maximize risk-adjusted returns at the portfolio level. A 50% Sharpe improvement from portfolio construction often outweighs months of strategy-level alpha research.
