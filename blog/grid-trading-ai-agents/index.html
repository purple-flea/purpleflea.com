Grid Trading for AI Agents:
Earn From Volatility Without
Predicting Direction

March 4, 2026 Purple Flea Team 8 min read

Most trading strategies require your agent to predict whether price will go up or down. That is a hard problem. Grid trading sidesteps it entirely: instead of predicting direction, you profit from price bouncing around within a range.

The core idea is simple. Place buy orders at evenly spaced prices below the current market price, and sell orders at evenly spaced prices above it. When price drops and triggers a buy, a corresponding sell is placed above it. When price rises and triggers that sell, the cycle repeats. Each round trip through the grid captures the step size as profit.

How Grid Trading Works

Imagine BTC is trading at $85,000. You set up a grid with $1,000 step size from $80,000 to $90,000. Here is what the order book looks like:

SELL $90,000 ——— 0.001 BTC
SELL $89,000 ——— 0.001 BTC
SELL $88,000 ——— 0.001 BTC
SELL $87,000 ——— 0.001 BTC
SELL $86,000 ——— 0.001 BTC
► CURRENT: $85,000
BUY $84,000 ——— 0.001 BTC
BUY $83,000 ——— 0.001 BTC
BUY $82,000 ——— 0.001 BTC
BUY $81,000 ——— 0.001 BTC
BUY $80,000 ——— 0.001 BTC

When BTC drops to $84,000, the buy triggers. Your agent immediately places a sell at $85,000. When BTC bounces back to $85,000, the sell triggers — capturing a $1,000 step profit on 0.001 BTC = $1.00 per round trip, minus fees. With 10 levels in a volatile market, you might complete 20 round trips per day.

Setting Grid Parameters

Parameter What It Controls Starting Point
grid_low Bottom of the grid range Recent 30-day low minus 5%
grid_high Top of the grid range Recent 30-day high plus 5%
num_levels Number of grid lines 10–20 levels
capital_per_level USDC allocated per grid level Total capital / num_levels
order_type Limit (maker) vs market (taker) Always limit — saves on fees

Python Implementation Using the Purple Flea Trading API

Python — Grid trading bot
import requests
import time
import logging
from dataclasses import dataclass
from typing import List

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(message)s")

TRADING_API = "https://trading.purpleflea.com"

@dataclass
class GridConfig:
    market: str
    grid_low: float    # lowest buy price
    grid_high: float   # highest sell price
    num_levels: int    # number of grid lines each side
    capital_usd: float # total capital to deploy
    api_key: str

    @property
    def step_size(self) -> float:
        return (self.grid_high - self.grid_low) / self.num_levels

    @property
    def capital_per_level(self) -> float:
        return self.capital_usd / self.num_levels

    @property
    def levels(self) -> List[float]:
        return [
            round(self.grid_low + i * self.step_size, 2)
            for i in range(self.num_levels + 1)
        ]


class GridBot:
    def __init__(self, config: GridConfig):
        self.config = config
        self.headers = {"Authorization": f"Bearer {config.api_key}"}
        self.open_orders: dict = {}  # level_price -> order_id

    def get_mark_price(self) -> float:
        r = requests.get(
            f"{TRADING_API}/v1/markets/{self.config.market}",
            headers=self.headers,
        )
        return float(r.json()["mark_price"])

    def place_limit_order(self, side: str, price: float, size: float) -> str:
        r = requests.post(
            f"{TRADING_API}/v1/orders",
            json={
                "market": self.config.market,
                "side": side,
                "type": "limit",
                "price": price,
                "size": size,
                "post_only": True,  # always maker to minimize fees
            },
            headers=self.headers,
        )
        r.raise_for_status()
        order_id = r.json()["order_id"]
        logging.info(f"Placed {side} limit at ${price:,.2f} (size={size:.6f})")
        return order_id

    def initialize_grid(self):
        """Place initial buy orders below current price, sell orders above."""
        current = self.get_mark_price()
        logging.info(f"Initializing grid. Mark price: ${current:,.2f}")

        for level in self.config.levels:
            size = self.config.capital_per_level / level
            if level < current:
                oid = self.place_limit_order("buy", level, size)
                self.open_orders[level] = oid
            elif level > current:
                oid = self.place_limit_order("sell", level, size)
                self.open_orders[level] = oid

    def check_fills_and_reorder(self):
        """Check which orders filled and place the counterpart order."""
        r = requests.get(
            f"{TRADING_API}/v1/orders?status=filled&market={self.config.market}",
            headers=self.headers,
        )
        filled = r.json().get("orders", [])

        for order in filled:
            fill_price = float(order["price"])
            fill_size  = float(order["size"])
            fill_side  = order["side"]

            # Place the counterpart at the next grid level
            if fill_side == "buy":
                counter_price = fill_price + self.config.step_size
                counter_side  = "sell"
            else:
                counter_price = fill_price - self.config.step_size
                counter_side  = "buy"

            if self.config.grid_low <= counter_price <= self.config.grid_high:
                oid = self.place_limit_order(counter_side, counter_price, fill_size)
                self.open_orders[counter_price] = oid

            profit = self.config.step_size * fill_size
            logging.info(f"Filled {fill_side} @ ${fill_price:,.2f}. Est round-trip profit: ${profit:.4f}")

    def run(self, poll_interval: int = 30):
        """Main loop. Polls every poll_interval seconds."""
        self.initialize_grid()
        print(f"Grid active on {self.config.market}: ${self.config.grid_low:,} - ${self.config.grid_high:,}")
        while True:
            try:
                self.check_fills_and_reorder()
            except Exception as e:
                logging.error(f"Error in grid loop: {e}")
            time.sleep(poll_interval)

if __name__ == "__main__":
    config = GridConfig(
        market="BTC-PERP",
        grid_low=80_000,

    )

Expected Returns Calculation

Before deploying real capital, calculate expected returns mathematically:

Python — Grid return calculator
def calculate_grid_returns(
    capital: float,
    grid_low: float,
    grid_high: float,
    num_levels: int,
    trades_per_day: float,
    fee_pct: float = 0.0002,  # 0.02% maker fee
) -> dict:
    step_size = (grid_high - grid_low) / num_levels
    avg_price = (grid_high + grid_low) / 2
    step_pct  = step_size / avg_price

    # Gross profit per round trip (1 buy + 1 sell)
    gross_per_rt = step_pct * (capital / num_levels)

    # Fee cost per round trip (entry + exit)
    fee_per_rt = fee_pct * 2 * (capital / num_levels)

    net_per_rt = gross_per_rt - fee_per_rt
    daily_profit = net_per_rt * trades_per_day
    annual_profit = daily_profit * 365
    annual_return_pct = annual_profit / capital * 100

    return {
        "step_pct": step_pct * 100,
        "net_per_round_trip": net_per_rt,
        "daily_profit": daily_profit,
        "annual_profit": annual_profit,
        "annual_return_pct": annual_return_pct,
    }

# BTC grid: $80k–$90k, 10 levels, $1,000 capital, 5 round trips/day
r = calculate_grid_returns(
    capital=1000, grid_low=80_000, grid_high=90_000,
    num_levels=10, trades_per_day=5
)
print(f"Step size:            {r['step_pct']:.2f}%")
print(f"Net per round trip:   ${r['net_per_round_trip']:.4f}")
print(f"Daily profit:         ${r['daily_profit']:.2f}")
print(f"Annual return:        {r['annual_return_pct']:.1f}%")
# Step size:          1.18%
# Net per round trip: $0.1140
# Daily profit:       $0.57
# Annual return:      20.9%

Managing Grid Positions Automatically

A running grid needs monitoring for two failure modes:

  • Price breaks out of range: If BTC moves from $85,000 to $95,000, all your sell orders have triggered but none of your buy orders have — you are out of position at the top. Detect this and either stop the grid or recenter it around the new price.
  • Price collapses through the range: All buy orders have triggered but no sells — you are fully long at the bottom. This is the main risk of grid trading: you can accumulate a large unhedged long if price falls far enough.
Python — Range check and automatic shutdown
def check_grid_health(bot: GridBot) -> bool:
    """Returns True if grid is healthy, False if should stop."""
    current = bot.get_mark_price()
    cfg = bot.config

    if current > cfg.grid_high:
        logging.warning(f"Price ${current:,.0f} broke above grid high ${cfg.grid_high:,.0f}. Stopping.")
        return False

    if current < cfg.grid_low:
        logging.warning(f"Price ${current:,.0f} broke below grid low ${cfg.grid_low:,.0f}. Stopping.")
        return False

    return True

def cancel_all_grid_orders(bot: GridBot):
    """Cancel all open orders for this market."""
    r = requests.delete(
        f"{TRADING_API}/v1/orders?market={bot.config.market}",
        headers=bot.headers,
    )
    r.raise_for_status()
    logging.info("All grid orders cancelled.")

When Grid Trading Works Best

Grid trading is a mean-reversion strategy. It works best when:

  • Markets are ranging. When BTC oscillates between $80k and $90k for weeks, the grid captures every bounce. In a one-directional trend, the grid accumulates an unhedged position in the trend's direction.
  • Volatility is moderate. You need enough price movement to trigger fills, but not so much that price breaks out of the grid immediately.
  • Fees are low. The per-trade profit margin of a grid is thin (0.5–2% of step size). High fees eat the margin quickly. Use Purple Flea's 0.02% maker fee with post_only: true orders.
