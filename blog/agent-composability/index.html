01

The Composability Principle

Composability is the property of a system whose components can be combined to produce new behaviors. A composable financial system is one where the output of one operation can be the input to another, and where combining operations produces emergent capabilities not present in any single operation.

This is not a new idea. Unix pipelines are composable: cat file | sort | uniq | wc -l combines four simple tools into a data pipeline. TCP/IP is composable: HTTP runs on TCP, HTTPS adds TLS on top, WebSockets add bidirectionality on top of that. Every major infrastructure advance in computing has been a composability advance.

Purple Flea is designed to be a composable financial primitive library. The six services — Casino, Trading, Wallet, Domains, Faucet, Escrow — are not independent products. They are building blocks. The interesting agent behaviors emerge from using them in combination.

The Core Insight

Simple + Simple = Complex. A bet is trivial. A transfer is trivial. An escrow is a conditional transfer. A conditional transfer on the outcome of a bet is a prediction market. The same primitive components, differently composed, produce qualitatively different capabilities.

Composition Patterns: Pipeline, Parallel, Conditional, Recursive

There are four fundamental patterns for composing operations. Understanding these patterns gives you a vocabulary for describing and building any complex agent behavior.

Pattern 1: Pipeline (Sequential)

Each operation feeds its output into the next. The final result depends on the entire chain completing successfully. Failure at any step halts the pipeline.

python 
async def pipeline(*ops) -> OpResult:
    """Run operations sequentially; each receives previous result."""
    result = OpResult(OpStatus.OK, {})
    for op in ops:
        result = await op(result)
        if not result.ok:
            return result  # fail fast
    return result

# Example: faucet → bet → transfer winnings
result = await pipeline(
    lambda _: pf.claim_faucet("agent_123"),
    lambda prev: pf.bet(prev.get("amount", 10), "coin_flip"),
    lambda prev: pf.transfer("treasury_agent", prev.get("pnl", 0))
        if prev.get("outcome") == "win"
        else lambda prev: OpResult(OpStatus.OK, {"skipped": True})
)

Pattern 2: Parallel (Concurrent)

Multiple operations run concurrently. Useful when operations are independent and you want to minimize total execution time. Results are collected and aggregated.

python 
import asyncio

async def parallel(*ops) -> list:
    """Run all operations concurrently, collect all results."""
    return await asyncio.gather(*[op() for op in ops], return_exceptions=True)

# Example: hedge a bet by placing both sides simultaneously
# (on different services/counterparties)
results = await parallel(
    lambda: pf.bet(50, "coin_flip", "heads"),       # main bet
    lambda: pf.create_escrow(hedge_partner, 45, "tails")  # hedge
)
main_result, hedge_result = results

Pattern 3: Conditional (Branching)

The next operation is chosen based on the outcome of the previous one. This is how agents implement strategy adaptation and risk management.

python 
async def conditional(op, on_success, on_failure) -> OpResult:
    """Branch based on op outcome."""
    result = await op()
    if result.ok:
        return await on_success(result)
    else:
        return await on_failure(result)

# Example: bet, then reinvest or cut losses
result = await conditional(
    op=lambda: pf.bet(20),
    on_success=lambda r: pf.bet(r.get("balance") * 0.1),   # reinvest 10%
    on_failure=lambda _: pf.transfer("cold_storage", remaining_balance)  # cut loss
)

Pattern 4: Recursive (Self-Referential)

An operation calls a composed version of itself. This is how agents implement compounding strategies, agent spawning, and network-building behaviors. Handle with care — unbounded recursion is a bug.

python 
async def recursive_compound(balance: float, target: float,
                              depth: int = 0, max_depth: int = 10):
    """Compound winnings until target balance reached."""
    if balance >= target or depth >= max_depth:
        return balance

    bet_size = balance * 0.1  # 10% Kelly-inspired fraction
    result = await pf.bet(bet_size)

    new_balance = balance + result.get("pnl", 0)
    if new_balance < 1.0: return new_balance  # ruin guard

    return await recursive_compound(new_balance, target, depth + 1, max_depth)

Python: Building a Composable Agent Toolkit

A full composable agent toolkit wraps the primitives, implements the patterns, and provides a declarative interface for describing strategies as compositions.

python 
# agent_toolkit.py — composable strategy builder
from typing import Callable, Any, List
import asyncio

Step = Callable[[OpResult], OpResult]  # type alias

class Strategy:
    """Fluent builder for composing agent strategies."""

    def __init__(self, pf: PurpleFlеaPrimitives, name: str = "unnamed"):
        self.pf = pf
        self.name = name
        self._steps: List[Step] = []
        self._on_error: Step = lambda r: r  # default: propagate error

    def then(self, step: Step) -> "Strategy":
        self._steps.append(step)
        return self

    def on_error(self, handler: Step) -> "Strategy":
        self._on_error = handler
        return self

    def if_ok(self, step: Step) -> "Strategy":
        """Only run step if previous result was successful."""
        async def conditional_step(prev: OpResult) -> OpResult:
            if prev.ok: return await step(prev)
            return prev
        return self.then(conditional_step)

    async def run(self, initial: OpResult = None) -> OpResult:
        result = initial or OpResult(OpStatus.OK, {})
        for step in self._steps:
            try:
                result = await step(result)
            except Exception as e:
                result = OpResult(OpStatus.FAILED, {}, str(e))
                result = await self._on_error(result)
                break
        return result

# Usage: declarative strategy composition
pf = PurpleFlеaPrimitives("pf_live_your_api_key")

compounding_strategy = (
    Strategy(pf, "compound_on_win")
    .then(lambda _: pf.bet(10.0))
    .if_ok(lambda r: pf.bet(r.get("balance") * 0.1))  # reinvest
    .if_ok(lambda r: pf.transfer("savings", r.get("balance") * 0.2))  # save 20%
    .on_error(lambda e: print(f"Strategy failed: {e.error}") or e)
)

Orchestration Layer: Coordinating Composed Behaviors

Complex agents need an orchestration layer that schedules strategies, manages state across strategy runs, handles inter-strategy dependencies, and enforces global risk constraints.

python 
# orchestrator.py — coordinate multiple strategies with shared state
import asyncio
from datetime import datetime
from typing import Dict, List

class AgentOrchestrator:
    def __init__(self, pf: PurpleFlеaPrimitives):
        self.pf = pf
        self.strategies: List[tuple] = []  # (strategy, interval_seconds)
        self.state: Dict = {"total_pnl": 0.0, "run_count": 0}
        self.global_max_loss = 50.0  # stop all strategies if total loss exceeds this
        self.running = False

    def add(self, strategy: Strategy, interval: float = 60.0):
        self.strategies.append((strategy, interval))
        return self

    async def _run_strategy(self, strategy: Strategy, interval: float):
        while self.running:
            if self.state["total_pnl"] < -self.global_max_loss:
                print(f"Global loss limit hit. Pausing {strategy.name}")
                break

            result = await strategy.run()
            pnl = result.get("pnl", 0)
            self.state["total_pnl"] += pnl
            self.state["run_count"] += 1
            await asyncio.sleep(interval)

    async def run(self):
        self.running = True
        tasks = [self._run_strategy(s, i) for s, i in self.strategies]
        await asyncio.gather(*tasks)

Error Propagation in Composed Operations

In a composed strategy, errors in early steps can invalidate later steps. Proper error handling in composed operations is critical — both for safety (avoiding partial execution that leaves funds in inconsistent state) and for debuggability.

Error Type Composition Behavior Recovery Strategy
Network timeout Step returns FAILED; pipeline halts Retry with exponential backoff
Insufficient balance Step returns FAILED with balance data Reduce bet size or abort
API rate limit 429 response; step FAILED Wait and retry after backoff
Partial execution Step 2 failed after step 1 succeeded Compensating transaction to restore state
Logic error in strategy Exception raised in step fn Catch at orchestrator level, alert operator
The Partial Execution Problem

If a composed operation partially executes (step 1 sends funds, step 2 fails to create escrow), your agent may be in an inconsistent state with funds neither in the original wallet nor safely in escrow. Always design composed operations to either complete fully or be fully reversible. Escrow's conditional release mechanism is precisely designed to handle this.

The Financial DAG: Representing Strategies as Directed Acyclic Graphs

For complex strategies with branching paths and parallel operations, a directed acyclic graph (DAG) representation is more expressive than a linear pipeline. Each node is a primitive operation; each edge is a dependency. Nodes with no incoming edges execute first; nodes with multiple incoming edges wait for all predecessors.

python 
# dag_strategy.py — represent complex strategies as DAGs
import asyncio
from typing import Dict, Set, List, Callable

class DAGNode:
    def __init__(self, name: str, op: Callable):
        self.name = name
        self.op = op
        self.deps: Set[str] = set()
        self.result: OpResult = None

class FinancialDAG:
    def __init__(self):
        self.nodes: Dict[str, DAGNode] = {}

    def add(self, name: str, op: Callable, deps: List[str] = None):
        node = DAGNode(name, op)
        node.deps = set(deps or [])
        self.nodes[name] = node
        return self

    async def execute(self) -> Dict[str, OpResult]:
        completed: Set[str] = set()
        running: Dict[str, asyncio.Task] = {}

        async def run_node(name: str):
            node = self.nodes[name]
            dep_results = {d: self.nodes[d].result for d in node.deps}
            node.result = await node.op(dep_results)
            completed.add(name)

        while len(completed) < len(self.nodes):
            ready = [
                name for name, node in self.nodes.items()
                if name not in completed
                and name not in running
                and node.deps.issubset(completed)
            ]
            for name in ready:
                running[name] = asyncio.create_task(run_node(name))
            if running:
                done, _ = await asyncio.wait(running.values(),
                                                 return_when=asyncio.FIRST_COMPLETED)
                for task in done:
                    finished = [n for n, t in running.items() if t is task][0]
                    del running[finished]

        return {n: node.result for n, node in self.nodes.items()}

# Example: arbitrage DAG
dag = (
    FinancialDAG()
    .add("get_price_a", lambda _: pf.trade("BTC/USDC", "quote", 0))
    .add("get_price_b", lambda _: pf.trade("BTC/USDC", "quote_alt", 0))
    .add("compute_arb", lambda deps: compute_spread(deps),
         deps=["get_price_a", "get_price_b"])

         deps=["compute_arb"])

Testing Composed Behaviors

Testing composed strategies requires both unit testing of individual operations and integration testing of composed behaviors. The key challenge is that composed behaviors have emergent properties that neither component has in isolation.

python 
# test_compositions.py — unit and integration tests for composed strategies
import pytest
from unittest.mock import AsyncMock, MagicMock

class MockPrimitives:
    """Controllable mock of Purple Flea primitives for testing."""
    def __init__(self, bet_outcome: str = "win", balance: float = 100.0):
        self.balance = balance
        self.bet_outcome = bet_outcome
        self.calls = []

    async def bet(self, amount: float, *args) -> OpResult:
        self.calls.append({"op": "bet", "amount": amount})
        pnl = amount if self.bet_outcome == "win" else -amount
        self.balance += pnl
        return OpResult(OpStatus.OK, {"pnl": pnl, "balance": self.balance,
                                        "outcome": self.bet_outcome})

    async def transfer(self, to: str, amount: float) -> OpResult:
        self.calls.append({"op": "transfer", "to": to, "amount": amount})
        return OpResult(OpStatus.OK, {"tx_id": "mock_tx"})

    transfer_calls = [c for c in mock.calls if c["op"] == "transfer"]
