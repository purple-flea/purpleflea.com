1. AMM Fundamentals: x*y=k, StableSwap, and Concentrated Liquidity

Before deploying capital, an LP agent needs to understand what invariant it is operating against. Every AMM design is just a different choice of invariant curve — the equation that must hold true before and after every swap.

The Constant Product Market Maker (x*y=k)

Uniswap V2 and the original Uniswap V1 use the constant product invariant. If a pool holds x units of token A and y units of token B, then after any trade the product must stay constant:

x · y = k
Constant Product Invariant — Uniswap V2

When a trader buys dy of token B by selling dx of token A, the pool must satisfy (x + dx)(y - dy) = k. Solving for dy:

dy = y − k / (x + dx) = (y · dx) / (x + dx)
Output amount given input dx, ignoring fees

The spot price at any point is simply the ratio y/x. As you buy more of token B, y decreases and x increases, so price rises — this is the automatic price discovery mechanism. The entire price curve from zero to infinity is always covered, but capital utilization is very low because most liquidity sits at extreme prices that are rarely reached.

The StableSwap Invariant (Curve Finance)

For assets that should trade near parity (USDC/USDT, stETH/ETH, DAI/USDC), the constant product curve is wasteful — it prices in huge slippage even for small deviations. Curve's StableSwap invariant blends a constant product curve with a constant sum curve (x + y = k), using an amplification parameter A to control the blend:

A · nn · ∑xi + D = A · nn · D + Dn+1 / (nn · ∏xi)
StableSwap Invariant — Curve Finance (n assets, amplification A)

When A is large, the curve behaves like x + y = k (constant sum, zero slippage near parity). When A = 0, it collapses to the constant product curve. In practice A is set in the hundreds to thousands, giving near-zero slippage when assets are at parity and increasing slippage as they depeg. This dramatically increases capital efficiency for stable pairs at the cost of higher slippage during de-peg events.

Concentrated Liquidity (Uniswap V3)

V3 virtualizes liquidity. Instead of spreading capital across [0, ∞], each LP picks a price range [Pa, Pb]. The pool tracks a global liquidity value L, and the reserve relationship becomes:

(x + L/√Pb) · (y + L·√Pa) = L2
Virtual Reserves Invariant — Uniswap V3

This means a $10,000 position in a 10%-wide range around the current price contributes the same depth as roughly $400,000 in a V2 pool — a 40x capital efficiency gain for that price band. The efficiency multiplier is approximately 1 / (1 - √(P_a/P_b)).

import math

def v3_capital_efficiency(p_lower: float, p_upper: float) -> float:
    """
    Returns the capital efficiency multiplier of a V3 position
    relative to a full-range V2 position.

    Example: p_lower=2800, p_upper=3200 around p=3000
    """
    sqrt_ratio = math.sqrt(p_lower / p_upper)
    efficiency = 1 / (1 - sqrt_ratio)
    return round(efficiency, 1)

def calc_v3_amounts(capital_usd: float, p_current: float,
                    p_lower: float, p_upper: float) -> tuple:
    """
    Given total USD capital and price range, calculate the ETH and USDC
    amounts to deposit in a V3 position.

    Uses the V3 virtual reserve formulas at the current price midpoint.
    """
    sqrt_p  = math.sqrt(p_current)
    sqrt_pa = math.sqrt(p_lower)
    sqrt_pb = math.sqrt(p_upper)

    # Liquidity L that uses all capital when centered
    # Derived from: capital = value_of_x + value_of_y
    # value_of_x = L * (1/sqrt_p - 1/sqrt_pb) * p_current
    # value_of_y = L * (sqrt_p - sqrt_pa)
    L = capital_usd / (
        sqrt_p - sqrt_pa + p_current * (1/sqrt_p - 1/sqrt_pb)
    )

    eth_amount  = L * (1/sqrt_p - 1/sqrt_pb)
    usdc_amount = L * (sqrt_p - sqrt_pa)

    return round(eth_amount, 5), round(usdc_amount, 2)

3. Impermanent Loss: Formula Derivation and Worked Examples

Impermanent loss (IL) is the opportunity cost of being an LP compared to simply holding the two assets. It is called "impermanent" because if price returns to your entry point, the loss disappears — but if you exit while price is away from entry, it crystallizes into a realized loss.

Derivation for a Full-Range (V2-Style) Position

Suppose you enter a pool at price P0 with normalized capital split 50/50. Let r = Pt/P0 be the price ratio at time t. The value of your LP position relative to entry is:

VLP = 2 · √r      Vhold = 1 + r
Normalized LP value vs hold value at price ratio r (entry = 1+1 = 2)
IL(r) = (VLP − Vhold) / Vhold = (2√r − 1 − r) / (1 + r)
Impermanent Loss formula — full range position

Key observations from this formula: IL is always negative (LP value ≤ hold value for r ≠ 1), IL is symmetric (same loss at r=2 as at r=0.5), and IL grows with the square root of the price ratio — meaning a 4x move causes more than a 2x move's IL.

import math

def il_full_range(r: float) -> float:
    """
    IL for a full-range (V2) LP position.
    r = p_current / p_entry (price ratio)
    Returns IL as a fraction — negative means loss vs hold.
    """
    return (2 * math.sqrt(r) - 1 - r) / (1 + r)

IL for Concentrated V3 Positions

For V3, the IL calculation is more complex because the position becomes single-sided when price exits the range. When price is within range [Pa, Pb], the V3 IL is amplified compared to V2 by approximately 1 / (1 - √(Pa/Pb)). When price exits the range, the LP holds 100% of one asset and earns no further fees until price returns.

def il_v3(p_entry: float, p_current: float,
          p_lower: float, p_upper: float) -> dict:
    """
    Calculate V3 impermanent loss compared to holding.
    Works for both in-range and out-of-range scenarios.

    Returns a dict with IL percentage, position status, and asset breakdown.
    """
    sqrt_entry   = math.sqrt(p_entry)
    sqrt_current = math.sqrt(p_current)
    sqrt_lower   = math.sqrt(p_lower)
    sqrt_upper   = math.sqrt(p_upper)

    # Liquidity constant (normalized, entry capital = 1.0)
    L = 1.0 / (sqrt_entry - sqrt_lower + (p_entry - p_lower) / sqrt_entry)

    # Value of position at current price
    if p_current <= p_lower:
        # Fully converted to token0 (e.g., ETH) — price fell below range
        eth_amount  = L * (1/sqrt_lower - 1/sqrt_upper)
        usdc_amount = 0
        lp_value_usd = eth_amount * p_current
        status = "out-of-range-low (100% ETH)"

    elif p_current >= p_upper:
        # Fully converted to token1 (e.g., USDC) — price rose above range
        eth_amount  = 0
        usdc_amount = L * (sqrt_upper - sqrt_lower)
        lp_value_usd = usdc_amount
        status = "out-of-range-high (100% USDC)"

    else:
        # In range — standard V3 position math
        eth_amount  = L * (1/sqrt_current - 1/sqrt_upper)
        usdc_amount = L * (sqrt_current - sqrt_lower)
        lp_value_usd = eth_amount * p_current + usdc_amount
        status = "in-range"

    # Hold value: same initial ETH and USDC amounts at current price
    # At entry: eth_entry = L*(1/sqrt_entry - 1/sqrt_upper), usdc_entry = L*(sqrt_entry - sqrt_lower)
    eth_entry  = L * (1/sqrt_entry - 1/sqrt_upper)
    usdc_entry = L * (sqrt_entry - sqrt_lower)
    hold_value = eth_entry * p_current + usdc_entry

    il = (lp_value_usd - hold_value) / hold_value

    return {
        "status":     status,
        "lp_value":   round(lp_value_usd, 6),
        "hold_value": round(hold_value, 6),
        "il_pct":     round(il * 100, 3),
        "eth":        round(eth_amount, 6),
        "usdc":       round(usdc_amount, 6),
    }

# Worked example: ETH/USDC position, entry at $3000, range [2700, 3300]
entry_price = 3000
p_low, p_high = 2700, 3300

print("Price   Status                 LP Value   Hold Value    IL")
print("-" * 65)
for p in [2500, 2700, 2850, 3000, 3150, 3300, 3500]:

    print(f"${p:<6} {res['status']:<26} {res['lp_value']:.4f}    {res['hold_value']:.4f}  {res['il_pct']:>6.2f}%")

4. Fee APY Calculation and Breakeven Analysis

IL only hurts you if you exit while in an IL position. The real question is whether fee income exceeds IL over your holding period. A position with 5% IL but 200% annualized fee APY will be profitable if held for more than ~9 days.

def fee_apr(daily_volume_usd: float, tvl_usd: float,
            fee_tier: float, position_fraction: float) -> float:
    """
    Estimate fee APR for a V3 position.

    position_fraction: fraction of in-range liquidity your position represents.
    For concentrated positions, this is higher than your TVL share.
    """
    daily_fees = daily_volume_usd * fee_tier * position_fraction
    return (daily_fees / tvl_usd) * 365

def breakeven_days(il_fraction: float, daily_fee_rate: float) -> float:
    """
    How many days of fee collection to recover a given IL loss?
    il_fraction: e.g. 0.05 for 5% IL
    daily_fee_rate: daily fees / position_value
    """
    if daily_fee_rate <= 0:
        return float('inf')
    return abs(il_fraction) / daily_fee_rate

def position_pnl_analysis(
    capital_usd: float,
    il_pct: float,
    daily_volume: float,
    pool_tvl: float,
    fee_tier: float,
    concentration_multiplier: float,
    days_held: int
) -> dict:
    """
    Full P&L analysis for a V3 LP position.
    concentration_multiplier: capital efficiency vs V2 (e.g. 16 for 10% range)
    """
    position_fraction = (capital_usd * concentration_multiplier) / pool_tvl
    daily_fee_income  = daily_volume * fee_tier * position_fraction
    total_fees        = daily_fee_income * days_held
    il_loss           = capital_usd * (il_pct / 100)
    net_pnl           = total_fees + il_loss  # il_loss is negative
    breakeven         = breakeven_days(il_pct / 100, daily_fee_income / capital_usd)

    return {
        "daily_fee_income":        round(daily_fee_income, 2),
        "total_fees_collected":    round(total_fees, 2),
        "il_loss_usd":            round(il_loss, 2),
        "net_pnl_usd":            round(net_pnl, 2),
        "fee_apr_pct":            round((daily_fee_income * 365 / capital_usd) * 100, 1),
        "breakeven_days":         round(breakeven, 1),
        "profitable":             net_pnl > 0,
    }

5. Tick Math and Price Conversion in V3

Uniswap V3 does not store prices as floating point numbers. It quantizes the price space into discrete ticks, where each tick corresponds to a price that is exactly 1.0001 times the previous tick. The relationship between tick index i and price is:

P(i) = 1.0001i      i = log(P) / log(1.0001)
Tick-to-price and price-to-tick conversion

Each pool has a tick spacing parameter (1, 10, 60, or 200 depending on fee tier) — positions can only be opened at ticks that are multiples of the spacing. This means your actual range is slightly different from the target price, and agents need to account for rounding.

import math

TICK_BASE = 1.0001

FEE_TIER_TICK_SPACING = {
    100:   1,    # 0.01% — 1 tick spacing
    500:   10,   # 0.05% — 10 tick spacing
    3000:  60,   # 0.30% — 60 tick spacing
    10000: 200,  # 1.00% — 200 tick spacing
}

def price_to_tick(price: float) -> int:
    """Convert a price to the nearest V3 tick index."""
    return int(math.log(price) / math.log(TICK_BASE))

def tick_to_price(tick: int) -> float:
    """Convert a tick index to the corresponding price."""
    return TICK_BASE ** tick

def nearest_usable_tick(price: float, fee_tier: int,
                         round_up: bool = False) -> int:
    """
    Find the nearest tick that is a valid position boundary
    for the given fee tier.
    round_up=True for upper bound, False for lower bound.
    """
    spacing = FEE_TIER_TICK_SPACING.get(fee_tier, 60)
    raw_tick = price_to_tick(price)
    if round_up:
        usable = math.ceil(raw_tick / spacing) * spacing
    else:
        usable = math.floor(raw_tick / spacing) * spacing
    return usable

def ticks_to_price_range(target_lower: float, target_upper: float,
                          fee_tier: int) -> dict:
    """
    Given target prices, find the actual usable tick boundaries
    and their corresponding prices.
    """
    tick_lower = nearest_usable_tick(target_lower, fee_tier, round_up=False)
    tick_upper = nearest_usable_tick(target_upper, fee_tier, round_up=True)
    actual_lower = tick_to_price(tick_lower)
    actual_upper = tick_to_price(tick_upper)

    return {
        "tick_lower":   tick_lower,
        "tick_upper":   tick_upper,
        "price_lower":  round(actual_lower, 4),
        "price_upper":  round(actual_upper, 4),
        "range_width":  round((actual_upper / actual_lower - 1) * 100, 2),
    }

# Example: target [2700, 3300] for ETH/USDC 0.05% (tick spacing 10)
result = ticks_to_price_range(2700, 3300, fee_tier=500)
print(result)
# {'tick_lower': 99400, 'tick_upper': 101200,
#  'price_lower': 2699.88, 'price_upper': 3299.55, 'range_width': 22.21}

6. Range Selection Strategies and Auto-Rebalancing

Range selection is the central LP decision. Narrow ranges maximize fee concentration but increase IL risk and rebalancing frequency. Wide ranges reduce risk but dilute fee income. The optimal range depends on realized volatility, expected holding period, and gas costs.

Volatility-Based Range Sizing

A common approach is to set the range width proportional to N standard deviations of log returns over your expected holding period. A 2-sigma range has roughly a 95% probability of containing the price for one period.

import numpy as np
import requests

def get_realized_vol(price_history: list, window: int = 24) -> float:
    """
    Compute hourly realized volatility (annualized).
    price_history: list of hourly close prices, most recent last.
    """
    prices  = np.array(price_history[-window-1:])
    returns = np.diff(np.log(prices))
    hourly_vol = np.std(returns)
    annualized = hourly_vol * math.sqrt(24 * 365)
    return annualized

def vol_based_range(
    p_current: float,
    price_history: list,
    holding_hours: int = 24,
    sigma_multiplier: float = 2.0
) -> tuple:
    """
    Compute a range that captures sigma_multiplier standard deviations
    of expected price movement over the holding period.

    Returns (p_lower, p_upper).
    """
    hourly_vol = np.std(np.diff(np.log(price_history[-25:])))
    period_vol = hourly_vol * math.sqrt(holding_hours)

    log_center = math.log(p_current)
    log_lower  = log_center - sigma_multiplier * period_vol
    log_upper  = log_center + sigma_multiplier * period_vol

    return round(math.exp(log_lower), 2), round(math.exp(log_upper), 2)

def should_rebalance(
    p_current: float,
    p_lower: float,
    p_upper: float,
    trigger_pct: float = 0.20
) -> tuple:
    """
    Check whether to rebalance.
    Trigger when price is within trigger_pct of range boundary.

    Returns (should_rebalance: bool, reason: str)
    """
    range_width = p_upper - p_lower
    lower_trigger = p_lower + range_width * trigger_pct
    upper_trigger = p_upper - range_width * trigger_pct

    if p_current <= p_lower:
        return True, "OUT_OF_RANGE_LOW"
    if p_current >= p_upper:
        return True, "OUT_OF_RANGE_HIGH"
    if p_current <= lower_trigger:
        return True, "NEAR_LOWER_BOUNDARY"
    if p_current >= upper_trigger:
        return True, "NEAR_UPPER_BOUNDARY"

    pct_through_range = (p_current - p_lower) / range_width * 100
    return False, f"ok — {pct_through_range:.0f}% through range"

Rebalancing Cost Analysis

Rebalancing is not free. On L1, removing and adding V3 liquidity costs around $20-60 in gas. On Arbitrum or Base it costs $0.10-0.50. An agent should only rebalance when the expected fee income improvement exceeds the gas cost. This creates a minimum range-width floor based on gas costs and pool fee income.

Agent tip: On L2s (Base, Arbitrum) with sub-$0.50 gas, you can rebalance every few hours without hurting profitability. On Ethereum L1, rebalancing more than once a week requires a very tight range and high-volume pool to justify the gas.

7. Curve Finance and Balancer: Alternative LP Venues

Curve Finance: The Stablecoin LP Layer

Curve dominates stablecoin liquidity with its StableSwap invariant. For agents holding USDC, DAI, FRAX, or other stable assets, Curve pools offer an alternative to Uniswap where IL risk is minimal — the main risk is de-peg events, not price volatility.

Curve Pool Key Parameters

The amplification parameter A controls how close to a constant-sum curve the pool behaves. USDC/USDT pools typically use A=1500-2000, meaning near-zero slippage for swaps within a few percent of parity. LPs earn trading fees (typically 0.01-0.04%) plus CRV token rewards, which can be boosted up to 2.5x by locking CRV into veCRV. The annualized CRV yield often exceeds the trading fee yield.

def curve_lp_returns(
    capital_usd: float,
    pool_daily_volume: float,
    pool_tvl: float,
    base_fee: float,
    crv_price: float,
    daily_crv_emissions: float,
    boost_multiplier: float = 1.0
) -> dict:
    """
    Estimate returns for a Curve pool LP position.
    boost_multiplier: 1.0 to 2.5 (requires veCRV lock)
    """
    position_share    = capital_usd / pool_tvl
    daily_trading_fee = pool_daily_volume * base_fee * position_share
    annual_trading    = daily_trading_fee * 365

    # CRV rewards scaled by boost
    daily_crv_usd  = daily_crv_emissions * crv_price * position_share * boost_multiplier
    annual_crv_usd = daily_crv_usd * 365

    total_apr = (annual_trading + annual_crv_usd) / capital_usd * 100

    return {
        "trading_fee_apr":  round(annual_trading / capital_usd * 100, 2),
        "crv_reward_apr":   round(annual_crv_usd / capital_usd * 100, 2),
        "total_apr":        round(total_apr, 2),
        "boosted":          boost_multiplier > 1.0,
    }

Balancer: Weighted Pools and Boosted Pools

Balancer generalizes the AMM concept to allow N-token pools with arbitrary weight distributions. A standard 80/20 ETH/USDC pool is much less exposed to IL than a 50/50 pool, because the ETH side only needs to rebalance 20% of the time. This makes Balancer weighted pools attractive for agents that want ETH exposure with reduced IL drag.

Balancer IL vs Pool Weights

For a two-asset weighted pool with weights (w1, w2) and price ratio r, the IL formula generalizes to: IL = (w1 · rw2 + w2) / rw2 - 1. For an 80/20 pool with a 2x price move, IL is only ~0.6% compared to ~5.7% in a 50/50 pool. The trade-off is lower fee income because the 80% token side attracts less volume proportionally.

Balancer Boosted Pools

Boosted pools (e.g., bb-a-USD) lend idle liquidity to Aave while it is not being used for swaps. When a trade comes in, the pool pulls from Aave on demand. This means the LP earns both Aave lending yield and Balancer trading fees simultaneously, typically doubling APY for stable pairs compared to a standard Curve pool.

8. Yield Stacking: LP Fees + Token Rewards + Convex/Aura

def stacked_yield_analysis(
    capital_usd: float,
    base_fee_apr: float,       # e.g., 0.05 for 5%
    crv_apr_unboosted: float,  # e.g., 0.08 for 8%
    convex_boost: float = 2.1, # typically 2.0-2.5x on Convex
    cvx_apr: float = 0.04,    # CVX reward APR on top
    aura_boost: float = 1.0,  # For Balancer pools via Aura
) -> dict:

    Compute stacked yield for a Curve + Convex LP position.
    """
    fee_income     = capital_usd * base_fee_apr
    crv_boosted    = capital_usd * crv_apr_unboosted * convex_boost * aura_boost
    cvx_income     = capital_usd * cvx_apr
    total_annual   = fee_income + crv_boosted + cvx_income
    total_apr      = total_annual / capital_usd

    return {
        "fee_income_usd":      round(fee_income, 2),
        "crv_boosted_usd":    round(crv_boosted, 2),
        "cvx_income_usd":     round(cvx_income, 2),
        "total_annual_usd":   round(total_annual, 2),
        "total_apr_pct":      round(total_apr * 100, 1),
        "daily_income_usd":   round(total_annual / 365, 2),
    }

9. Hedging Impermanent Loss with Options and Perpetuals

IL hedging converts an LP position's directional exposure into a more neutral one. The core insight is that IL is mathematically equivalent to being short gamma — the LP profits when price stays still and loses when it moves. The hedge adds long gamma back.

Delta Hedging with Perpetuals

A V3 LP position's delta (directional exposure to the underlying asset price) changes as price moves through the range. At the lower range boundary, you hold nearly 100% of the risky asset (maximum positive delta). At the upper boundary, you hold nearly 100% stable (zero delta). The average delta of an in-range position is approximately 50% of the ETH notional.

To delta-hedge: open a short perpetual position in ETH equal to roughly half the ETH notional in your LP position. As price moves up and your LP sells ETH automatically (becoming more USDC), you close part of your short. As price moves down, your LP buys ETH (becoming more ETH), and you add to your short. This creates an approximately delta-neutral book.

import requests, math

PURPLE_FLEA_API = "https://purpleflea.com/api/v1"
API_KEY         = "pf_live_your_key_here"

def calc_lp_delta(
    p_current: float,
    p_lower: float,
    p_upper: float,
    lp_eth_amount: float
) -> float:
    """
    Estimate the current ETH delta of a V3 LP position.
    Returns ETH delta (positive = long exposure).
    When in range: delta is between 0 and lp_eth_amount.
    """
    if p_current <= p_lower:
        return lp_eth_amount   # 100% ETH — max long delta
    if p_current >= p_upper:
        return 0.0            # 100% USDC — zero ETH delta

    # In range: linear approximation based on position in range
    pct_through_range = (math.sqrt(p_current) - math.sqrt(p_lower)) / \
                        (math.sqrt(p_upper) - math.sqrt(p_lower))
    return lp_eth_amount * (1 - pct_through_range)

def hedge_lp_position(
    p_current: float,
    p_lower: float,
    p_upper: float,
    lp_eth_amount: float,
    current_short_eth: float = 0.0
) -> dict:
    """
    Calculate the required short perpetual size to delta-hedge the LP.
    Returns the trade needed to reach target hedge.
    """
    lp_delta        = calc_lp_delta(p_current, p_lower, p_upper, lp_eth_amount)
    target_short    = lp_delta  # Short exactly the LP delta to go neutral
    adjustment_eth  = target_short - current_short_eth

    if abs(adjustment_eth) < 0.001:
        return {"action": "no_trade", "reason": "delta within tolerance"}

    action = "increase_short" if adjustment_eth > 0 else "decrease_short"

    return {
        "action":          action,
        "eth_adjustment":  round(abs(adjustment_eth), 4),
        "lp_delta":        round(lp_delta, 4),
        "target_short":    round(target_short, 4),
    }

10. Active LP Management Protocols

Several protocols have emerged to automate Uniswap V3 position management on-chain, which can complement or serve as alternatives to building a custom agent.

Arrakis Finance (formerly G-UNI)

Arrakis turns V3 positions into ERC-20 tokens with automated rebalancing and fee compounding. Vaults follow defined strategies (static range, dynamic range, mean-reverting) and compound fees back into the position. LP agents can deposit into Arrakis vaults instead of managing positions directly, or run their own Arrakis vault strategy contract.

Gamma Strategies

Gamma focuses on actively managed V3 positions for institutional LPs. Their hypervisor contracts handle tick adjustments and fee compounding. Key feature: they offer wide-range "base" positions combined with narrow "limit" positions to capture fees across different volatility regimes. Agent integrations can query Gamma's API for current vault positions before deciding whether to self-manage or delegate.

Sommelier Finance

Sommelier uses an off-chain strategist model: an off-chain compute layer (the "cellar" strategist) sends rebalancing transactions to on-chain vault contracts. The approach is compelling for LP agents because it provides a rebalancing framework that can incorporate off-chain ML signals — similar to what a well-designed autonomous agent would do, but with a proven smart contract layer underneath.

Smart contract risk: Every protocol adds a smart contract layer between you and your funds. Arrakis, Gamma, and Sommelier have all been audited, but bugs have occurred in the DeFi ecosystem. Agents managing funds above $50k should evaluate whether the added yield from protocol integration justifies the additional smart contract surface area.

11. Complete Python LP Management Bot

The following is a production-grade LP management agent that combines position monitoring, range optimization, auto-rebalancing, delta hedging, and fee collection. It uses Purple Flea's Wallet API for on-chain execution and Trading API for perp hedging.

"""
Purple Flea LP Management Bot
Manages a concentrated liquidity V3 position with:
- Volatility-based range sizing
- Auto-rebalance when near boundary
- Delta hedge via Purple Flea perps
- Fee collection and compounding
- Risk circuit breakers
"""

import math, time, requests, logging
import numpy as np
from dataclasses import dataclass, field
from typing import Optional
from datetime import datetime, timezone

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s"
)
log = logging.getLogger("lp-bot")

PF_API      = "https://purpleflea.com/api/v1"
AGENT_ID    = "lp-bot-001"
API_KEY     = "pf_live_your_key"
HEADERS     = {
    "X-Agent-Id":    AGENT_ID,
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type":  "application/json"
}

@dataclass
class LPConfig:
    pool_address:          str   = "0x88e6A0c2dDD26FEEb64F039a2c41296FcB3f5640"
    fee_tier:              int   = 500
    capital_usd:           float = 10_000
    range_sigma:           float = 2.0    # 2-sigma range width
    rebalance_trigger_pct: float = 0.15   # Rebalance at 15% from boundary
    max_il_pct:            float = 6.0    # Hard exit at 6% IL
    hedge_enabled:         bool  = True
    compound_fees:         bool  = True
    vol_window_hours:      int   = 24
    poll_interval_sec:     int   = 60
    max_rebalances_per_day:int   = 12

@dataclass
class PositionState:
    position_id:     Optional[str]   = None
    p_lower:         Optional[float] = None
    p_upper:         Optional[float] = None
    entry_price:     Optional[float] = None
    eth_amount:      float           = 0.0
    usdc_amount:     float           = 0.0
    short_eth:       float           = 0.0    # Current perp short size
    total_fees_usd:  float           = 0.0
    rebalances_today:int             = 0
    last_rebalance:  Optional[str]   = None
    price_history:   list            = field(default_factory=list)

class LPBot:
    def __init__(self, config: LPConfig):
        self.cfg   = config
        self.state = PositionState()

    # ---- Price and Data ----------------------------------------

    def get_eth_price(self) -> float:
        try:
            r = requests.get(
                "https://api.coingecko.com/api/v3/simple/price",
                params={"ids": "ethereum", "vs_currencies": "usd"},
                timeout=5
            )
            price = r.json()["ethereum"]["usd"]
            self.state.price_history.append(price)
            if len(self.state.price_history) > 200:
                self.state.price_history = self.state.price_history[-200:]
            return price
        except Exception as e:
            log.error(f"Price fetch error: {e}")
            return self.state.price_history[-1] if self.state.price_history else 3000

    def compute_vol_range(self, p_current: float) -> tuple:
        if len(self.state.price_history) < 4:
            # Fallback to 10% range if not enough history
            return p_current * 0.90, p_current * 1.10

        prices  = np.array(self.state.price_history[-self.cfg.vol_window_hours-1:])
        returns = np.diff(np.log(prices))
        hourly_vol = np.std(returns) if len(returns) > 1 else 0.005

        # Clamp vol: never narrower than 5% or wider than 40%
        period_vol = max(0.025, min(0.20, hourly_vol * math.sqrt(24)))

        log_center = math.log(p_current)
        p_lower = math.exp(log_center - self.cfg.range_sigma * period_vol)
        p_upper = math.exp(log_center + self.cfg.range_sigma * period_vol)
        return round(p_lower, 2), round(p_upper, 2)

    # ---- IL and Rebalance Check --------------------------------

    def compute_il(self, p_current: float) -> Optional[float]:
        s = self.state
        if s.position_id is None or s.entry_price is None:
            return None

        r = p_current / s.entry_price
        il_full_range = (2 * math.sqrt(r) - 1 - r) / (1 + r)
        eff = 1 / (1 - math.sqrt(s.p_lower / s.p_upper))
        il_concentrated = il_full_range * (eff / 2)  # approx amplification
        return il_concentrated

    def check_rebalance(self, p_current: float) -> tuple:
        s = self.state
        if s.p_lower is None:
            return True, "NO_POSITION"

        range_width = s.p_upper - s.p_lower
        trig_low    = s.p_lower + range_width * self.cfg.rebalance_trigger_pct
        trig_high   = s.p_upper - range_width * self.cfg.rebalance_trigger_pct

        if p_current <= s.p_lower:  return True,  "OUT_OF_RANGE_LOW"
        if p_current >= s.p_upper:  return True,  "OUT_OF_RANGE_HIGH"
        if p_current <= trig_low:   return True,  "NEAR_LOWER_BOUNDARY"
        if p_current >= trig_high:  return True,  "NEAR_UPPER_BOUNDARY"
        return False, "in_range"

    # ---- Position Lifecycle ------------------------------------

    def open_position(self, p_current: float) -> bool:
        p_lower, p_upper = self.compute_vol_range(p_current)
        log.info(f"Opening position at ${p_current:.0f} range [{p_lower:.0f}, {p_upper:.0f}]")

        r = requests.post(f"{PF_API}/wallet/defi/add-liquidity", headers=HEADERS, json={
            "pool": self.cfg.pool_address,
            "fee_tier": self.cfg.fee_tier,
            "price_lower": p_lower,
            "price_upper": p_upper,
            "capital_usd": self.cfg.capital_usd,
        })
        result = r.json()
        if result.get("status") != "ok":
            log.error(f"Failed to open position: {result}")
            return False

        s = self.state
        s.position_id = result["position_id"]
        s.p_lower      = p_lower
        s.p_upper      = p_upper
        s.entry_price  = p_current
        s.eth_amount   = result.get("eth_amount", 0)
        s.usdc_amount  = result.get("usdc_amount", 0)
        log.info(f"Position opened: {s.position_id} — {s.eth_amount:.4f} ETH + ${s.usdc_amount:.2f} USDC")

        if self.cfg.hedge_enabled:
            self.update_hedge(p_current)
        return True

    def close_position(self) -> float:
        s = self.state
        if s.position_id is None:
            return 0.0

        r = requests.post(f"{PF_API}/wallet/defi/remove-liquidity", headers=HEADERS, json={
            "position_id": s.position_id,
            "collect_fees": True,
        })
        result     = r.json()
        fees_usd   = result.get("fees_collected_usd", 0.0)
        s.total_fees_usd += fees_usd
        log.info(f"Position closed. Fees collected: ${fees_usd:.4f} | Total: ${s.total_fees_usd:.2f}")

        s.position_id = None
        s.p_lower = s.p_upper = s.entry_price = None
        s.eth_amount = s.usdc_amount = 0.0
        return fees_usd

    def rebalance(self, p_current: float, reason: str):
        s = self.state
        if s.rebalances_today >= self.cfg.max_rebalances_per_day:
            log.warning("Max rebalances reached today, skipping")
            return

        log.info(f"Rebalancing: {reason} @ ${p_current:.2f}")
        self.close_position()

        if s.short_eth > 0 and self.cfg.hedge_enabled:
            self.close_hedge()

        self.open_position(p_current)
        s.rebalances_today += 1
        s.last_rebalance    = datetime.now(timezone.utc).isoformat()

    # ---- Hedge Management --------------------------------------

    def update_hedge(self, p_current: float):
        s = self.state
        if s.p_lower is None or not self.cfg.hedge_enabled:
            return

        lp_delta    = calc_lp_delta(p_current, s.p_lower, s.p_upper, s.eth_amount)
        target_short = lp_delta
        adjustment   = target_short - s.short_eth

        if abs(adjustment) < 0.001:
            return

        side = "sell" if adjustment > 0 else "buy"
        r = requests.post(f"{PF_API}/trading/order", headers=HEADERS, json={
            "market": "ETH-PERP", "side": side,
            "size": abs(adjustment), "type": "market"
        })
        result = r.json()
        if result.get("status") == "ok":
            s.short_eth = target_short
            log.info(f"Hedge updated: {side} {abs(adjustment):.4f} ETH-PERP | total short: {s.short_eth:.4f}")

    def close_hedge(self):
        s = self.state
        if s.short_eth <= 0:
            return
        requests.post(f"{PF_API}/trading/order", headers=HEADERS, json={
            "market": "ETH-PERP", "side": "buy",
            "size": s.short_eth, "type": "market", "reduce_only": True
        })
        log.info(f"Hedge closed: bought back {s.short_eth:.4f} ETH-PERP")
        s.short_eth = 0.0

    # ---- Main Loop ---------------------------------------------

    def run(self):
        log.info("LP Bot starting...")
        while True:
            try:
                p = self.get_eth_price()
                s = self.state

                # Check IL circuit breaker
                il = self.compute_il(p)
                if il is not None and abs(il) * 100 > self.cfg.max_il_pct:
                    log.warning(f"IL {il*100:.1f}% exceeds limit — emergency exit")
                    self.close_position()
                    self.close_hedge()
                    log.info("Waiting 30 minutes before re-entering...")
                    time.sleep(1800)
                    continue

                # Check rebalance
                do_rebalance, reason = self.check_rebalance(p)
                if do_rebalance:
                    self.rebalance(p, reason)
                else:
                    if self.cfg.hedge_enabled:
                        self.update_hedge(p)

                log.info(
                    f"Price: ${p:.2f} | Range: [{s.p_lower}, {s.p_upper}] | "
                    f"IL: {il*100:.2f}% | Fees: ${s.total_fees_usd:.2f} | Short: {s.short_eth:.3f} ETH"
                    if il is not None else f"Price: ${p:.2f} — no active position"
                )
                time.sleep(self.cfg.poll_interval_sec)

            except KeyboardInterrupt:
                log.info("Bot shutting down — closing all positions")
                self.close_position()
                self.close_hedge()
                break
            except Exception as e:
                log.error(f"Loop error: {e}", exc_info=True)
                time.sleep(30)

if __name__ == "__main__":
    config = LPConfig(
        capital_usd=10_000,
        range_sigma=2.0,
        hedge_enabled=True,
        compound_fees=True,
    )
    bot = LPBot(config)
    bot.run()

LP positions carry multiple distinct risk categories. A production agent needs explicit policies for each.

Smart Contract Risk Tiers

  • Tier 1 (Lowest): Direct interaction with Uniswap V3 core contracts, Curve 3pool — billions in TVL, years of audit history.
  • Tier 2 (Low): Uniswap V4 (new but same team), Balancer V2, Convex (long live track record).
  • Tier 3 (Medium): Arrakis, Gamma, Sommelier vault layer — audited but smaller TVL, shorter history.
  • Tier 4 (High): New farm contracts, point programs, anonymous team pools — treat as speculative.

Liquidity Risk

Providing liquidity in a pool with very low TVL means your own position is a significant fraction of the pool. This creates toxic flow risk: arbitrageurs will specifically trade against your position because they can move the price more cheaply. Always check that your position is less than 5% of pool TVL. For pools under $1M TVL, IL from arbitrage can massively outpace fee income even at high volume.

Concentration Risk from Yield Stacking

Yield stacking feels like "free" additional APY but each layer introduces correlation. During a DeFi stress event (2022-style CRV attack, Curve hack, etc.), all yield layers can fail simultaneously: protocol token rewards crash in price, boost contracts freeze, and fee income collapses as volume dries up. Cap total yield-stacking exposure to 20-30% of portfolio.

class LPRiskMonitor:
    """
    Risk monitoring and circuit breakers for LP positions.
    Plug this into any LP bot as a safety layer.
    """

    def __init__(self):
        self.MAX_IL_PCT          = 6.0
        self.MIN_FEE_APR_PCT     = 15.0
        self.MAX_POSITION_SHARE  = 0.05   # 5% of pool TVL max
        self.MAX_VOL_1H          = 0.08   # 8% hourly vol = pause
        self.MAX_REBALANCES_DAY  = 12
        self.GAS_BUDGET_USD_DAY  = 5.00

    def evaluate(self,
                  il_pct: float,
                  fee_apr_pct: float,
                  pool_tvl_usd: float,
                  position_usd: float,
                  hourly_vol: float,
                  rebalances_today: int,
                  gas_spent_today: float) -> dict:

        flags = []
        should_exit = False

        if abs(il_pct) > self.MAX_IL_PCT:
            flags.append(f"IL {il_pct:.1f}% exceeds {self.MAX_IL_PCT}%")
            should_exit = True

        if fee_apr_pct < self.MIN_FEE_APR_PCT:
            flags.append(f"Fee APR {fee_apr_pct:.1f}% below minimum {self.MIN_FEE_APR_PCT}%")
            should_exit = True

        pos_share = position_usd / max(pool_tvl_usd, 1)
        if pos_share > self.MAX_POSITION_SHARE:
            flags.append(f"Position is {pos_share*100:.1f}% of pool — toxic flow risk")

        if hourly_vol > self.MAX_VOL_1H:
            flags.append(f"High 1h vol {hourly_vol*100:.1f}% — pause rebalancing")

        if rebalances_today >= self.MAX_REBALANCES_DAY:
            flags.append(f"Max daily rebalances reached ({self.MAX_REBALANCES_DAY})")

        if gas_spent_today > self.GAS_BUDGET_USD_DAY:
            flags.append(f"Gas budget ${self.GAS_BUDGET_USD_DAY} exceeded (${gas_spent_today:.2f} spent)")

        return {
            "ok":          len(flags) == 0,
            "should_exit": should_exit,
            "flags":       flags,
        }
