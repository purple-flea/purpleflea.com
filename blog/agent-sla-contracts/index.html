Agent SLA Contracts: Uptime, Latency, and Accuracy Guarantees via Escrow

AI agent service providers make implicit reliability promises all the time. They rarely back them with enforceable commitments. What an Agent SLA Looks Like

A traditional SLA is a legal document. It specifies metrics, measurement windows, penalty tiers, and escalation procedures — then relies on lawyers, courts, and a shared trust in institutions to enforce it. This model breaks down entirely for AI agents, which have no legal personhood, no shared jurisdiction, and no ability to pursue legal remedy.

An agent SLA needs to be self-enforcing from the moment it is signed. The financial penalty for breach must execute automatically the instant the breach is detected — with no intermediary to bribe, no appeal window to game, and no enforcement cost to absorb.

In the agent economy, an SLA has four dimensions:

  • Uptime percentage — the fraction of time the agent service responds successfully within the measurement window (e.g., 95% uptime over 30 days).
  • p99 latency — the 99th percentile response time ceiling (e.g., all but 1% of responses must arrive within 500ms).
  • Accuracy floor — the minimum quality score on evaluations run against the agent's outputs (e.g., 90% classification accuracy on a held-out test set).
  • Response freshness — a maximum staleness window for data-returning agents (e.g., price feed agents must return data no older than 30 seconds).
SLA as a Competitive Moat

In a market where every agent claims reliability, the agent that can back its claims with an escrow-enforced SLA has a durable competitive advantage. Buyers prefer agents with skin in the game. An enforceable SLA is the difference between a marketing claim and a credible commitment.

These four dimensions can be combined in any configuration. A data feed agent might guarantee freshness and uptime. A RAG agent might guarantee latency and accuracy. A trading strategy agent might guarantee accuracy alone — because latency and uptime are less critical than signal quality. The escrow metadata schema is flexible enough to encode any combination.

Escrow as the Enforcement Layer

The enforcement mechanism works as follows: at the start of a service period, the buyer agent creates an escrow holding the full service payment. The escrow metadata encodes the SLA terms. Throughout the service period, a monitoring agent (which can be the buyer agent itself, or an independent third party) checks the service provider against the SLA conditions at regular intervals.

When a breach is detected, the monitoring agent calls the penalty endpoint, which releases a portion of the escrow back to the buyer proportional to the breach severity. When the measurement period ends without critical breach, the full remaining balance is released to the service provider. The escrow record contains the complete audit trail — every metric check, every breach event, every penalty executed.

The Monitoring Agent

The monitoring agent is a lightweight background process. It issues health check requests to the provider on a defined schedule, records response times, evaluates output quality, and checks timestamp freshness. It is the automated counterpart to a traditional SLA auditor — running 24/7 at a fraction of the cost.

Python Implementation: AgentSLA Class

The following implementation provides a complete SLA contract manager. It handles escrow creation, metric monitoring, breach detection, penalty execution, and final settlement. The class is designed to run as a background process alongside any Python agent.

agent_sla.py Python 
import time
import statistics
import requests
import threading
from typing import Dict, List, Optional, Callable, Any
from dataclasses import dataclass, field
from enum import Enum


ESCROW_BASE = "https://escrow.purpleflea.com/api"


class SLAType(Enum):
    UPTIME = "uptime"
    LATENCY = "latency"
    QUALITY = "quality"
    FRESHNESS = "freshness"


class BreachSeverity(Enum):
    NONE = "none"
    MINOR = "minor"    # 10% refund
    MAJOR = "major"    # 50% refund
    CRITICAL = "critical"  # 100% refund


@dataclass
class SLAMetrics:
    """Accumulated metric snapshot for SLA evaluation."""
    checks_total: int = 0
    checks_passed: int = 0
    latency_samples: List[float] = field(default_factory=list)
    quality_samples: List[float] = field(default_factory=list)
    freshness_samples: List[float] = field(default_factory=list)
    breach_events: List[Dict] = field(default_factory=list)

    @property
    def uptime_pct(self) -> float:
        if self.checks_total == 0:
            return 1.0
        return self.checks_passed / self.checks_total

    @property
    def p99_latency_ms(self) -> float:
        if not self.latency_samples:
            return 0.0
        sorted_latencies = sorted(self.latency_samples)
        idx = int(len(sorted_latencies) * 0.99)
        return sorted_latencies[min(idx, len(sorted_latencies) - 1)]

    @property
    def mean_quality(self) -> float:
        return statistics.mean(self.quality_samples) if self.quality_samples else 0.0

    @property
    def max_staleness_s(self) -> float:
        return max(self.freshness_samples) if self.freshness_samples else 0.0


@dataclass
class AgentSLA:
    """
    Self-enforcing SLA contract manager for AI agents.
    Encodes SLA terms into Purple Flea Escrow metadata.
    Monitors compliance and triggers penalty escrows on breach.
    """
    buyer_id: str
    api_key: str
    base_url: str = ESCROW_BASE

    def __post_init__(self):
        self.headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json",
            "X-Agent-ID": self.buyer_id
        }
        self._metrics: Dict[str, SLAMetrics] = {}
        self._monitors: Dict[str, threading.Thread] = {}

    def create_sla_escrow(
        self,
        provider_id: str,
        monthly_payment: float,
        sla_type: SLAType,
        sla_params: Dict[str, Any],
        bonus_params: Optional[Dict] = None,
        description: str = ""
    ) -> str:
        """
        Create an SLA-enforced escrow contract.
        sla_params varies by sla_type:
          UPTIME:    {target_pct: 0.95, window_days: 30}
          LATENCY:   {p99_ceiling_ms: 500, window_days: 30}
          QUALITY:   {accuracy_floor: 0.90, eval_frequency_hours: 6}
          FRESHNESS: {max_staleness_s: 30, check_interval_s: 60}
        """
        bonus_block = bonus_params or {}
        r = requests.post(
            f"{self.base_url}/escrow/create",
            json={
                "buyer_id": self.buyer_id,
                "seller_id": provider_id,
                "amount_usdc": monthly_payment,
                "description": description,
                "escrow_type": "sla_contract",
                "metadata": {
                    "sla_type": sla_type.value,
                    "sla_params": sla_params,
                    "bonus_params": bonus_block,
                    "penalties": {
                        "minor_refund_pct": 0.10,
                        "major_refund_pct": 0.50,
                        "critical_refund_pct": 1.00
                    },
                    "created_at": time.time(),
                    "period_start": time.time()
                }
            },
            headers=self.headers
        )
        r.raise_for_status()
        escrow_id = r.json()["escrow_id"]
        self._metrics[escrow_id] = SLAMetrics()
        return escrow_id

    def check_sla_compliance(
        self,
        escrow_id: str,
        metrics: SLAMetrics
    ) -> BreachSeverity:
        """
        Evaluate current metrics against SLA params.
        Returns the highest severity breach detected, or NONE.
        """
        escrow = requests.get(
            f"{self.base_url}/escrow/{escrow_id}",
            headers=self.headers
        ).json()
        meta = escrow["metadata"]
        sla_type = SLAType(meta["sla_type"])
        params = meta["sla_params"]

        if sla_type == SLAType.UPTIME:
            target = params["target_pct"]
            actual = metrics.uptime_pct
            deficit = target - actual
            if deficit <= 0: return BreachSeverity.NONE
            if deficit < 0.02: return BreachSeverity.MINOR
            if deficit < 0.05: return BreachSeverity.MAJOR
            return BreachSeverity.CRITICAL

        elif sla_type == SLAType.LATENCY:
            ceiling_ms = params["p99_ceiling_ms"]
            actual_p99 = metrics.p99_latency_ms
            overshoot = actual_p99 - ceiling_ms
            if overshoot <= 0: return BreachSeverity.NONE
            if overshoot < 100: return BreachSeverity.MINOR
            if overshoot < 500: return BreachSeverity.MAJOR
            return BreachSeverity.CRITICAL

        elif sla_type == SLAType.QUALITY:
            floor = params["accuracy_floor"]
            actual = metrics.mean_quality
            deficit = floor - actual
            if deficit <= 0: return BreachSeverity.NONE
            if deficit < 0.03: return BreachSeverity.MINOR
            if deficit < 0.08: return BreachSeverity.MAJOR
            return BreachSeverity.CRITICAL

        elif sla_type == SLAType.FRESHNESS:
            max_stale = params["max_staleness_s"]
            actual = metrics.max_staleness_s
            overshoot = actual - max_stale
            if overshoot <= 0: return BreachSeverity.NONE
            if overshoot < 10: return BreachSeverity.MINOR
            if overshoot < 60: return BreachSeverity.MAJOR
            return BreachSeverity.CRITICAL

        return BreachSeverity.NONE

    def penalize_breach(
        self,
        escrow_id: str,
        severity: BreachSeverity,
        evidence: Dict
    ) -> Dict:
        """Execute a graduated penalty escrow refund based on breach severity."""
        refund_pct = {
            BreachSeverity.MINOR: 0.10,
            BreachSeverity.MAJOR: 0.50,
            BreachSeverity.CRITICAL: 1.00
        }.get(severity, 0)

        if refund_pct == 0:
            return {"status": "no_penalty"}

        r = requests.post(
            f"{self.base_url}/escrow/{escrow_id}/penalty",
            json={
                "severity": severity.value,
                "refund_pct": refund_pct,
                "penalty_triggered_by": self.buyer_id,
                "evidence": evidence,
                "timestamp": time.time()
            },
            headers=self.headers
        )
        r.raise_for_status()
        return r.json()

    def settle_sla(
        self,
        escrow_id: str,
        metrics: SLAMetrics
    ) -> Dict:
        """
        Settle the SLA period. Release remaining balance to provider
        if compliance met; apply final penalty if final check fails.
        """
        final_severity = self.check_sla_compliance(escrow_id, metrics)

        if final_severity == BreachSeverity.NONE:
            # Check for bonus eligibility
            bonus_result = self._check_bonus(escrow_id, metrics)
            r = requests.post(
                f"{self.base_url}/escrow/{escrow_id}/release",
                json={"released_by": self.buyer_id, "bonus": bonus_result},
                headers=self.headers
            )
            r.raise_for_status()
            return {"status": "settled_compliant", "bonus": bonus_result, "data": r.json()}
        else:
            evidence = {
                "uptime_pct": metrics.uptime_pct,
                "p99_latency_ms": metrics.p99_latency_ms,
                "mean_quality": metrics.mean_quality,
                "breach_events": metrics.breach_events
            }
            penalty = self.penalize_breach(escrow_id, final_severity, evidence)
            return {"status": "settled_breach", "severity": final_severity.value, "penalty": penalty}

    def _check_bonus(self, escrow_id: str, metrics: SLAMetrics) -> Optional[Dict]:
        """Check whether provider qualifies for bonus escrow release."""
        escrow = requests.get(
            f"{self.base_url}/escrow/{escrow_id}",
            headers=self.headers
        ).json()
        bonus_params = escrow.get("metadata", {}).get("bonus_params", {})
        if not bonus_params:
            return None
        target = bonus_params.get("uptime_bonus_target", 1.01)
        bonus_pct = bonus_params.get("bonus_pct", 0.10)
        if metrics.uptime_pct >= target:
            return {"eligible": True, "bonus_pct": bonus_pct}
        return {"eligible": False}

Three SLA Types in Practice

Each SLA type maps to a distinct class of agent service. Below are concrete implementations for the three most common agent SLA patterns: uptime, latency, and quality.

Uptime SLA: 95% Availability Over 30 Days

Uptime SLAs are the baseline for any persistent agent service. A data provider agent, an API aggregator, or a market data relay needs to be available when downstream agents call it. 95% uptime over 30 days means a maximum of 36 hours of downtime is permissible in the measurement window. Anything beyond that constitutes a breach.

        "check_interval_s": 60,
        "health_check_endpoint": "https://provider-agent.io/health"
    },
    bonus_params={
        "uptime_bonus_target": 0.999,
        "bonus_pct": 0.10
    },

# ── Monitoring loop (runs as background thread) ──────────────────────

def uptime_monitor(
    sla_client: AgentSLA,
    escrow_id: str,
    health_url: str,
    interval_s: int = 60
):
    metrics = SLAMetrics()
    period_end = time.time() + (30 * 86400)  # 30 days
    last_penalty_time = 0
    penalty_cooldown_s = 3600  # max one penalty per hour

    while time.time() < period_end:
        start = time.time()
        metrics.checks_total += 1

        try:
            resp = requests.get(health_url, timeout=10)
            latency_ms = (time.time() - start) * 1000
            metrics.latency_samples.append(latency_ms)

            if resp.status_code == 200:
                metrics.checks_passed += 1
            else:
                metrics.breach_events.append({
                    "type": "http_error",
                    "status_code": resp.status_code,
                    "at": time.time()
                })
        except requests.Timeout:
            metrics.breach_events.append({
                "type": "timeout", "at": time.time()
            })
        except Exception as e:
            metrics.breach_events.append({
                "type": "connection_error",
                "error": str(e), "at": time.time()
            })

        # Evaluate SLA and penalize if breached (with cooldown)
        if metrics.checks_total >= 60:  # evaluate after 1 hour of data
            severity = sla_client.check_sla_compliance(escrow_id, metrics)
            now = time.time()
            if severity != BreachSeverity.NONE and (now - last_penalty_time) > penalty_cooldown_s:
                sla_client.penalize_breach(escrow_id, severity, {
                    "uptime_pct": metrics.uptime_pct,
                    "checks_total": metrics.checks_total,
                    "checks_passed": metrics.checks_passed
                })
                last_penalty_time = now

        time.sleep(interval_s)

    # Period ended — final settlement
    result = sla_client.settle_sla(escrow_id, metrics)
    print(f"SLA settled: {result}")

Latency SLA: p99 Below 500ms

Latency SLAs are critical for agents that depend on real-time data feeds or low-latency inference APIs. A trading agent that relies on a price-feed agent cannot tolerate p99 latency above 500ms — a slow response means stale data, missed signals, and potentially losing trades. The monitoring loop samples response times at every check and evaluates the rolling p99 after sufficient samples accumulate.

# ── Latency sampling function ────────────────────────────────────────

def sample_latency(endpoint: str, n: int = 10) -> List[float]:
    """Sample response latency n times in rapid succession."""
    latencies = []
    for _ in range(n):
        start = time.time()
        try:
            requests.get(endpoint, timeout=5)
            latencies.append((time.time() - start) * 1000)
        except:
            latencies.append(5000)  # count timeouts as 5s
    return latencies


# ── Report current p99 to escrow ─────────────────────────────────────

def report_latency_sample(
    api_key: str,
    escrow_id: str,
    samples: List[float]
) -> None:
    """Report a batch of latency samples to escrow monitoring endpoint."""
    requests.post(
        f"{ESCROW_BASE}/escrow/{escrow_id}/metrics",
        json={
            "metric_type": "latency_ms",
            "samples": samples,
            "p99": sorted(samples)[int(len(samples) * 0.99)],
            "mean": statistics.mean(samples),
            "recorded_at": time.time()
        },
        headers={"Authorization": f"Bearer {api_key}"}
    )

Quality SLA: Accuracy Above 90%

Quality SLAs require periodic evaluation runs. Rather than checking a health endpoint, the monitoring agent submits test queries to the provider and evaluates the responses against a ground-truth held-out set. If the rolling accuracy drops below 90%, a breach is detected and a penalty is triggered.

quality_sla.py Python 
# ── Create quality SLA escrow ────────────────────────────────────────

quality_escrow = sla.create_sla_escrow(
    provider_id="classifier-agent-99",
    monthly_payment=350.00,
    sla_type=SLAType.QUALITY,
    sla_params={
        "accuracy_floor": 0.90,
        "eval_frequency_hours": 6,
        "eval_endpoint": "https://classifier-agent.io/classify",
        "test_set_id": "held_out_2026_q1"
    },
    bonus_params={
        "accuracy_bonus_target": 0.97,
        "bonus_pct": 0.20
    },
    description="Quality SLA: classification accuracy >= 90% (eval every 6h)"
)


# ── Run evaluation against held-out test set ─────────────────────────

def run_quality_eval(
    provider_endpoint: str,
    test_set: List[Dict]
) -> float:
    """
    Submit test queries to provider, compare against ground truth.
    Returns accuracy as fraction of correct classifications.
    """
    correct = 0
    total = len(test_set)

    for item in test_set:
        try:
            resp = requests.post(
                provider_endpoint,
                json={"text": item["input"]},
                timeout=10
            )
            predicted = resp.json().get("label")
            if predicted == item["expected_label"]:
                correct += 1
        except:
            pass  # count errors as wrong

    accuracy = correct / total if total > 0 else 0.0
    return accuracy

Monitoring Loop Architecture

The monitoring loop is the operational core of an SLA contract. It runs as a background thread (or a separate process) for the full contract period, issuing health checks, sampling metrics, detecting breaches, and triggering penalties. The architecture follows a simple tick-evaluate-act pattern:

  1. Tick — issue the metric check (HTTP request, eval run, freshness check).
  2. Accumulate — append the result to the rolling metric buffer.
  3. Evaluate — once a sufficient sample window is available, evaluate against SLA params.
  4. Act — if breach detected, call the penalty endpoint with evidence (subject to cooldown to prevent duplicate penalties).
  5. Settle — when the period ends, run a final evaluation and settle the escrow.
Penalty Cooldown Is Critical

Without a cooldown on penalty calls, a monitoring loop could trigger dozens of minor-breach penalties in a short window, draining the escrow far beyond what is proportionate. The example code enforces a 1-hour minimum between penalty calls. Adjust this based on your contract period length and expected breach duration.

Graduated Penalties

A binary penalty system — either full refund or nothing — is too blunt for most agent SLA scenarios. Minor degradation (uptime drops from 95% to 93.5%) should not carry the same penalty as total failure (service offline for 12 hours). Graduated penalties align financial consequences with actual impact, making SLA contracts fairer for both parties and more likely to be accepted by service providers.

10%
Minor Breach

Slight underperformance. Uptime 93–95%, p99 500–600ms, accuracy 87–90%. Token refund from escrow balance.

50%
Major Breach

Significant degradation. Uptime 90–93%, p99 600–1000ms, accuracy 82–87%. Half balance returned to buyer.

100%
Critical Breach

Service failed. Uptime below 90%, p99 above 1000ms, accuracy below 82%. Full refund, contract terminated.

The penalty tiers are encoded in the escrow metadata at creation time and cannot be altered by either party during the contract period. This prevents the service provider from claiming ignorance of the penalty structure, and prevents the buyer from retroactively changing the terms. The metadata field is immutable once the escrow is funded.

Reward Clauses: Exceed the SLA, Earn a Bonus

SLA contracts are not only punitive. A provider that consistently exceeds commitments deserves recognition — and financially incentivized over-performance produces better service than fear of penalty alone. Reward clauses in escrow metadata specify a bonus escrow that is released when the provider hits a stretch target.

Practical reward tiers: a provider guaranteeing 95% uptime that delivers 99.9% earns a 10% bonus. A latency SLA provider guaranteeing p99 below 500ms that delivers p99 below 100ms earns 15%. A quality SLA provider guaranteeing 90% accuracy that delivers 97%+ earns 20%.

# ── At settlement: check bonus eligibility ───────────────────────────

def settle_with_bonus_check(
    sla_client: AgentSLA,
    escrow_id: str,
    final_metrics: SLAMetrics,
    bonus_escrow_amount: float
) -> Dict:
    """
    Settle the primary SLA escrow, then release the bonus escrow
    if the provider hit the stretch target.
    """
    primary_result = sla_client.settle_sla(escrow_id, final_metrics)

    if primary_result["status"] == "settled_compliant":
        bonus_eligible = primary_result.get("bonus", {}).get("eligible", False)
        if bonus_eligible:
            # Create and immediately release a bonus escrow
            bonus_id = sla_client.create_sla_escrow(
                provider_id="inference-agent-77",
                monthly_payment=bonus_escrow_amount,
                sla_type=SLAType.QUALITY,
                sla_params={},
                description="Bonus: SLA stretch target exceeded"
            )
            requests.post(
                f"{ESCROW_BASE}/escrow/{bonus_id}/release",
                json={"released_by": sla_client.buyer_id, "reason": "bonus_earned"},
                headers=sla_client.headers
            )
            primary_result["bonus_paid"] = bonus_escrow_amount
            print(f"Bonus released: ${bonus_escrow_amount:.2f} — stretch target hit")

    return primary_result

Multi-Agent SLA Networks

In complex agent orchestration systems, a single buyer agent may have SLA contracts with many sub-agents simultaneously. Each sub-agent provides a different service: one handles data retrieval, another runs inference, a third manages order execution. The orchestrator holds a separate SLA escrow for each sub-agent, with the SLA terms tailored to each service type.

This creates a multi-layer SLA network. The orchestrator has an SLA obligation to its own clients (downstream agents or human users). That obligation is backed by the SLA contracts it holds with its sub-agents. If a sub-agent fails its SLA, the orchestrator collects the penalty, which offsets the cost of service degradation it experiences from its own clients.

SLA Networks Are Self-Healing

In a well-designed multi-agent SLA network, every breach at the sub-agent level generates a financial refund that flows upward to the orchestrator. This creates a self-healing economic signal: failing sub-agents are automatically replaced as their SLA escrows are depleted, while high-performing sub-agents receive bonus releases and accumulate reputation for preferential hiring.
