1. Compound V3 Architecture (Comet Contracts)

Compound V3, branded as Comet, marks a complete architectural departure from Compound V2. Where V2 used a multi-asset pool where any supported asset could serve as both collateral and borrowable asset simultaneously, V3 uses a base token model: each Comet deployment has one base asset (e.g., USDC or ETH) that can be supplied for yield or borrowed, while all other assets serve exclusively as collateral.

The Comet Contract

Each Compound V3 market is a single Comet contract. Unlike V2's shared comptroller architecture, each Comet is self-contained:

  • Base token: The single asset that earns interest (lenders) and incurs interest (borrowers). In cUSDCv3, this is USDC. In cWETHv3, this is WETH.
  • Collateral tokens: ETH, wBTC, LINK, wstETH, etc. — deposited to enable borrowing the base token. Collateral does NOT earn interest.
  • Interest model: Utilization-based piecewise linear model with a kink, similar to V2 but with separated supply and borrow curves.
  • Price oracle: Chainlink feeds for each collateral asset's USD value.
interface IComet {
    // Supply base token or collateral
    function supply(address asset, uint amount) external;
    function supplyTo(address dst, address asset, uint amount) external;

    // Withdraw base or collateral
    function withdraw(address asset, uint amount) external;

    // Get current supply/borrow APR (per second, scale 1e18)
    function getSupplyRate(uint utilization) external view returns (uint64);
    function getBorrowRate(uint utilization) external view returns (uint64);

    // Current utilization (0-1e18)
    function getUtilization() external view returns (uint);

    // User position data
    function userBasic(address account) external view returns (UserBasic memory);
    function userCollateral(address account, address asset) external view returns (UserCollateral memory);
}

Key Distinction: Collateral Earns Nothing

This is the most important V3 design choice for agent strategy. In V2, depositing ETH as collateral also earned cETH yield. In V3, ETH deposited as collateral to borrow USDC earns zero yield from Compound. This makes leveraged yield loops on yield-bearing collateral (like wstETH) particularly attractive — the staking yield on the collateral is "free" and offsets the USDC borrow cost.

Multi-Chain Deployment

Compound V3 is deployed on Ethereum mainnet, Polygon, Arbitrum, Base, Optimism, and Scroll. Each chain has its own Comet instances with different utilization profiles. Agents should monitor all deployments — Arbitrum often has higher base token yields due to lower TVL competition.

2. Base vs Borrow APR Dynamics

Compound V3 maintains separate interest rate curves for suppliers and borrowers of the base token. Understanding this asymmetry is fundamental to building profitable agent strategies.

The Two-Curve Model

interest_model.py
def compound_v3_rates(utilization: float, params: dict) -> tuple[float, float]:
    """
    Calculate Compound V3 supply and borrow APRs given utilization.

    params keys:
      supplyKink, supplyPerSecondInterestRateSlopeLow,
      supplyPerSecondInterestRateSlopeHigh, supplyPerSecondInterestRateBase,
      borrowKink, borrowPerSecondInterestRateSlopeLow,
      borrowPerSecondInterestRateSlopeHigh, borrowPerSecondInterestRateBase
    """
    SECONDS_PER_YEAR = 365 * 24 * 3600
    SCALE = 1e18

    # Supply rate
    if utilization <= params["supplyKink"] / SCALE:
        supply_per_sec = (
            params["supplyPerSecondInterestRateBase"]
            + params["supplyPerSecondInterestRateSlopeLow"] * utilization
        )
    else:
        normal_rate = (
            params["supplyPerSecondInterestRateBase"]
            + params["supplyPerSecondInterestRateSlopeLow"] * params["supplyKink"] / SCALE
        )
        kink_to_util = utilization - params["supplyKink"] / SCALE
        supply_per_sec = (
            normal_rate
            + params["supplyPerSecondInterestRateSlopeHigh"] * kink_to_util
        )

    # Borrow rate (similar piecewise structure)
    if utilization <= params["borrowKink"] / SCALE:
        borrow_per_sec = (
            params["borrowPerSecondInterestRateBase"]
            + params["borrowPerSecondInterestRateSlopeLow"] * utilization
        )
    else:
        normal_rate = (
            params["borrowPerSecondInterestRateBase"]
            + params["borrowPerSecondInterestRateSlopeLow"] * params["borrowKink"] / SCALE
        )
        kink_to_util = utilization - params["borrowKink"] / SCALE
        borrow_per_sec = (
            normal_rate
            + params["borrowPerSecondInterestRateSlopeHigh"] * kink_to_util
        )

    supply_apy = (1 + supply_per_sec) ** SECONDS_PER_YEAR - 1
    borrow_apy = (1 + borrow_per_sec) ** SECONDS_PER_YEAR - 1

    return supply_apy, borrow_apy

The Spread and What It Means for Agents

The spread between borrow APR and supply APR represents Compound's retained margin and the buffer to cover potential bad debt. For agents:

  • Suppliers: Want high utilization (approaching the kink) for maximum yield, but not so high that withdrawal liquidity dries up
  • Borrowers: Want low utilization (below the kink) for cheap borrowing costs
  • Arb agents: Monitor when this spread widens enough to make cross-protocol migration worthwhile

3. Utilization Rate Effects

Compound V3's interest rate model is designed to maintain equilibrium around the kink utilization point (typically 80%). Understanding how utilization moves — and predicting when it will — is central to timing agent supply and borrow positions.

What Drives Utilization

Utilization increases when:

  • New borrowers open positions (increases borrow side)
  • Existing suppliers withdraw capital (decreases supply side)
  • Crypto prices rise, triggering more leveraged borrowing
  • DeFi yield farming campaigns launch that require base asset borrowing
  • Market-wide risk-on sentiment increases leverage demand

Utilization decreases when:

  • High borrow rates trigger borrower repayments
  • Supply-side capital flows in chasing higher rates
  • Crypto prices fall, triggering liquidations (forceful repayment)
  • Cross-protocol migrations to cheaper borrow venues

from web3 import AsyncWeb3

async def monitor_utilization(comet_contract, alert_thresholds: dict):
    """

            borrow_rate = await comet_contract.functions.getBorrowRate(util_raw).call()

            SECONDS_PER_YEAR = 365 * 24 * 3600
            supply_apy = (1 + supply_rate / 1e18) ** SECONDS_PER_YEAR - 1
            borrow_apy = (1 + borrow_rate / 1e18) ** SECONDS_PER_YEAR - 1

            print(f"Util: {utilization:.1%} | Supply APY: {supply_apy:.2%} | Borrow APY: {borrow_apy:.2%}")

            if utilization > alert_thresholds.get("high_util_warning", 0.88):
                print(f"ALERT: High utilization {utilization:.1%} — withdrawal may be slow")
                # Trigger agent: prepare to withdraw or avoid new supply

            if utilization < alert_thresholds.get("low_util_exit", 0.50):
                print(f"ALERT: Low utilization {utilization:.1%} — supply yield below threshold")
                # Trigger agent: consider migrating to higher-yield venue

            if borrow_apy > alert_thresholds.get("max_borrow_rate", 0.12):
                print(f"ALERT: Borrow rate {borrow_apy:.2%} too high — refinance to Morpho")
                # Trigger agent: refinance borrow position

        except Exception as e:
            print(f"Monitor error: {e}")

        await asyncio.sleep(60)  # Check every minute

Utilization Kink Strategy

The optimal agent supply zone is 70-85% utilization — capturing the steep portion of the supply rate curve before the high-utilization regime where withdrawal risk increases. Set alerts at 88% to begin planning exits before liquidity crunch.

4. USDC and ETH Market Mechanics

Compound V3 has two primary deployments on Ethereum mainnet: cUSDCv3 (the USDC Comet) and cWETHv3 (the ETH Comet). Each has distinct characteristics that favor different agent strategies.

cUSDCv3 — The Stablecoin Market

The USDC Comet is the larger and more liquid market. It accepts ETH, wBTC, wstETH, cbETH, and LINK as collateral. Key characteristics:

  • Supply yield: 4-9% APY depending on utilization; supplemented by COMP token distributions
  • Primary borrower profile: ETH leveraged longs (borrow USDC, buy ETH); yield farmers needing stablecoin
  • Best collateral: wstETH — staking yield offsets most of the USDC borrow cost
  • Liquidation threshold: 83-86% LTV depending on collateral type

cWETHv3 — The ETH Market

The ETH Comet allows borrowing WETH using wstETH, rETH, cbETH, or other liquid staking tokens as collateral. This enables the stETH leverage loop:

1. Deposit 1 wstETH (worth 1.05 ETH) as collateral
2. Borrow 0.85 WETH (85% LTV)
3. Stake borrowed WETH → receive 0.85 wstETH
4. Deposit new wstETH, borrow more, repeat...

After 5 loops at 85% LTV:
  Total collateral: ~5.2 wstETH
  Total borrowed:   ~4.2 WETH
  Net staking APY benefit: 5x base stETH yield
  Borrow cost: ETH borrow APY on cWETHv3
  Net yield: (5 * stETH_APY) - (4 * ETH_borrow_APY)

5. Leveraged Yield Loop

The leveraged yield loop (also called recursive borrowing or looping) is one of the most commonly deployed agent strategies on Compound V3. When the yield on collateral exceeds the borrow cost of the base token, looping amplifies the net yield proportionally to leverage taken.

Loop Mathematics

loop_calculator.py
def calculate_loop_yield(
    collateral_yield_apy: float,    # e.g., 0.04 for stETH (4%)
    borrow_apy: float,               # e.g., 0.055 USDC borrow cost
    ltv: float,                      # e.g., 0.80 (80% LTV)
    loops: int,                      # number of recursive borrows
    initial_capital: float = 10_000  # in USD
) -> dict:
    """
    Calculate leveraged loop yield and risk metrics.
    Assumes collateral yield is in same asset as borrowed asset value.
    """
    # Total collateral after n loops
    # After loop 1: initial + (initial * ltv * price_ratio)
    # Geometric series: sum = initial * (1 - ltv^(loops+1)) / (1 - ltv)

    total_collateral = initial_capital * (1 - ltv**(loops + 1)) / (1 - ltv)
    total_borrowed = total_collateral - initial_capital

    # Gross yield from staking all collateral
    gross_yield = total_collateral * collateral_yield_apy

    # Borrow cost (on borrowed amount in USD terms — approximation)
    # In cWETHv3 stETH loop: borrowed is ETH, valued at ~1:1 to collateral USD
    borrow_cost = total_borrowed * borrow_apy

    net_yield = gross_yield - borrow_cost
    net_apy_on_initial = net_yield / initial_capital

    # Liquidation buffer
    # If collateral value drops by (1 - LTV), we're at risk
    max_collateral_drop_pct = 1 - (total_borrowed / total_collateral)

    return {
        "total_collateral_usd": total_collateral,
        "total_borrowed_usd": total_borrowed,
        "leverage_ratio": total_collateral / initial_capital,
        "gross_yield_usd": gross_yield,
        "borrow_cost_usd": borrow_cost,
        "net_yield_usd": net_yield,
        "net_apy_on_initial": net_apy_on_initial,
        "max_safe_collateral_drop": max_collateral_drop_pct,
        "liquidation_risk": "high" if max_collateral_drop_pct < 0.10 else "moderate" if max_collateral_drop_pct < 0.20 else "low"
    }


# Example: stETH loop on cWETHv3
result = calculate_loop_yield(
    collateral_yield_apy=0.038,  # stETH staking yield
    borrow_apy=0.032,            # WETH borrow cost on cWETHv3
    ltv=0.90,                    # wstETH collateral LTV in cWETHv3
    loops=4,
    initial_capital=10_000
)
print(f"Net APY: {result['net_apy_on_initial']:.2%}")
print(f"Leverage: {result['leverage_ratio']:.1f}x")
print(f"Max safe drop: {result['max_safe_collateral_drop']:.1%}")

Optimal Loop Count

The marginal benefit of each additional loop diminishes while the liquidation risk grows. For stETH loops on cWETHv3:

  • 1-2 loops: Safe, meaningful yield boost (1.8-2.3x base APY), large liquidation buffer
  • 3-4 loops: Good yield (2.8-3.5x base APY), moderate liquidation risk
  • 5+ loops: High yield but <10% collateral drop triggers liquidation — only suitable for ETH-denominated strategies where collateral and debt move together

stETH Depeg Risk

The stETH/ETH loop's liquidation risk is minimal under normal conditions because both collateral (wstETH) and debt (WETH) are denominated in ETH. However, stETH depegs — as seen in June 2022 (stETH traded at 0.935 ETH) — can trigger liquidations even at conservative leverage. Always maintain a >10% depeg buffer.

6. Rate Prediction

Predicting Compound V3 rate movements before they occur allows agents to position advantageously — supplying before rates spike, or refinancing borrows before rates rise.

On-Chain Leading Indicators

Agents should monitor these signals for rate prediction:

  • Large wallet movements: Whale deposits/withdrawals on Comet significantly shift utilization; watch for pending transactions in mempool
  • ETH price correlation: ETH price rises typically increase USDC borrowing demand (leverage longs)
  • Pending liquidations: Large at-risk positions (visible on-chain) will repay if prices drop, reducing utilization sharply
  • Cross-protocol rate differentials: Large spreads between Compound and Aave trigger arbitrage flows that normalize both
  • COMP governance proposals: Changes to interest rate parameters or collateral factors shift equilibrium
rate_predictor.py
import asyncio
from typing import Optional

class CompoundRatePredictor:
    def __init__(self, comet_contract, eth_price_oracle):
        self.comet = comet_contract
        self.oracle = eth_price_oracle
        self.history = []  # (timestamp, utilization, eth_price) tuples

    async def record_state(self):
        """Record current state for trend analysis"""
        import time
        util = await self.comet.functions.getUtilization().call()
        eth_price = await self.oracle.functions.latestAnswer().call()  # Chainlink
        self.history.append((time.time(), util / 1e18, eth_price / 1e8))
        # Keep last 1440 samples (24h at 1-min intervals)
        self.history = self.history[-1440:]

    def predict_utilization_direction(self) -> dict:
        """
        Simple momentum-based prediction.
        Returns direction ('up', 'down', 'stable') and confidence (0-1).
        """
        if len(self.history) < 60:
            return {"direction": "unknown", "confidence": 0.0}

        recent = self.history[-60:]    # last 1 hour
        older = self.history[-120:-60] # prior 1 hour

        recent_avg_util = sum(s[1] for s in recent) / len(recent)
        older_avg_util = sum(s[1] for s in older) / len(older)

        # ETH price trend
        recent_eth = sum(s[2] for s in recent) / len(recent)
        older_eth = sum(s[2] for s in older) / len(older)
        eth_trend = (recent_eth - older_eth) / older_eth

        util_trend = recent_avg_util - older_avg_util

        # Rising ETH price → more borrowing → higher utilization
        composite_signal = util_trend + eth_trend * 0.5

        if composite_signal > 0.01:
            direction = "up"
            confidence = min(abs(composite_signal) * 50, 1.0)
        elif composite_signal < -0.01:
            direction = "down"
            confidence = min(abs(composite_signal) * 50, 1.0)
        else:
            direction = "stable"
            confidence = 0.8

        return {
            "direction": direction,
            "confidence": confidence,
            "current_util": recent_avg_util,
            "util_1h_change": util_trend,
            "eth_1h_change": eth_trend,
        }

    def should_supply_now(self, min_apy: float = 0.05) -> bool:
        """Supply if current APY >= min_apy and direction is up or stable"""
        prediction = self.predict_utilization_direction()
        if prediction["direction"] == "down" and prediction["confidence"] > 0.7:
            return False  # Rates about to fall, wait
        return True

7. Liquidation Defense

Liquidation is the primary risk for agents running leveraged positions on Compound V3. Unlike V2's compound liquidations (multiple assets), V3's liquidation mechanism is simpler but still requires active management.

V3 Liquidation Mechanics

In Compound V3, a position becomes liquidatable when:

borrow_value > collateral_value * liquidation_factor

Where liquidation_factor (per collateral type):
  - wstETH: 93%
  - wETH:   93%
  - wBTC:   85%
  - LINK:   79%

The protocol allows any external account to liquidate using absorb(), which transfers the borrower's collateral to the protocol reserves and repays their debt. The absorbed collateral is then sold at a discount via buyCollateral().

Health Factor Monitoring

health_monitor.py
class HealthMonitor:
    def __init__(self, comet_contract, wallet_address: str):
        self.comet = comet_contract
        self.wallet = wallet_address
        self.alert_threshold = 1.15   # Alert at 115% (15% buffer above liquidation)
        self.action_threshold = 1.08  # Deleverage at 108% (8% buffer)

    async def get_health_factor(self) -> float:
        """
        Calculate current health factor.
        health_factor = weighted_collateral / borrow_value
        <1.0 means liquidatable
        """
        # Get borrow balance (negative principal = borrowing)
        user_basic = await self.comet.functions.userBasic(self.wallet).call()
        borrow_balance = abs(user_basic[0]) if user_basic[0] < 0 else 0  # principal

        if borrow_balance == 0:
            return float('inf')  # No borrow = infinite health

        # Get collateral value weighted by liquidation factors
        weighted_collateral = 0.0
        collateral_assets = await self.comet.functions.numAssets().call()

        for i in range(collateral_assets):
            asset_info = await self.comet.functions.getAssetInfo(i).call()
            asset_addr = asset_info[1]  # asset address
            liq_factor = asset_info[5] / 1e18  # liquidateCollateralFactor

            user_coll = await self.comet.functions.userCollateral(
                self.wallet, asset_addr
            ).call()
            coll_balance = user_coll[0]

            if coll_balance > 0:
                # Get price in base token terms
                price = await self.comet.functions.getPrice(asset_info[6]).call()  # priceFeed
                coll_value = coll_balance * price / 1e18 / 1e8  # normalize decimals
                weighted_collateral += coll_value * liq_factor

        health_factor = weighted_collateral / borrow_balance if borrow_balance > 0 else float('inf')
        return health_factor

    async def deleverage_if_needed(self, repay_ratio: float = 0.10):
        """
        Reduce leverage if health factor is dangerously low.
        repay_ratio: fraction of borrow to repay in emergency
        """
        hf = await self.get_health_factor()

        if hf < self.action_threshold:
            print(f"EMERGENCY: Health factor {hf:.3f} below threshold {self.action_threshold}")
            # In production: repay portion of borrow to restore health
            # 1. Withdraw some collateral → swap to base token
            # 2. Repay base token borrow
            # 3. Repeat until health > 1.25
            print(f"Action: Repay {repay_ratio:.0%} of outstanding borrow")

        elif hf < self.alert_threshold:
            print(f"WARNING: Health factor {hf:.3f} — monitor closely")

        return hf

    async def run_monitor(self):
        """Continuous health monitoring loop"""
        while True:
            try:
                hf = await self.deleverage_if_needed()
                print(f"Health factor: {hf:.3f}")
            except Exception as e:
                print(f"Monitor error: {e}")
            await asyncio.sleep(30)  # Check every 30 seconds when active

Automated Deleverage Trigger

Set up a bot that runs deleverage_if_needed() every 30 seconds during high-volatility periods (detected by ETH price change >3% in 1 hour). The gas cost of the emergency deleverage is far less than the cost of a liquidation penalty (typically 5-8% of collateral).

8. Python CompoundAgent

The complete CompoundAgent integrates rate monitoring, loop strategy execution, and liquidation defense into a single autonomous system that runs continuously and reports performance to Purple Flea.

compound_agent.py
"""
CompoundAgent: Autonomous lending/borrowing optimization on Compound V3
Supports both supply-only and leveraged loop strategies.
Integrates with Purple Flea for agent tracking and performance reporting.
"""

import asyncio
import os
import logging
from enum import Enum
from dataclasses import dataclass
from web3 import AsyncWeb3, AsyncHTTPProvider
import httpx

logging.basicConfig(level=logging.INFO)
log = logging.getLogger("CompoundAgent")

# Compound V3 Comet addresses on Ethereum mainnet
COMET_USDC = "0xc3d688B66703497DAA19211EEdff47f25384cdc3"
COMET_WETH = "0xA17581A9E3356d9a858b789D68B4d866e593aE94"
PURPLE_FLEA_API = "https://purpleflea.com/api"

class Strategy(Enum):
    SUPPLY_ONLY = "supply_only"
    WETH_LOOP = "weth_loop"      # stETH loop on cWETHv3
    USDC_SUPPLY = "usdc_supply"  # Pure USDC supply, no borrow

@dataclass
class AgentConfig:
    strategy: Strategy = Strategy.SUPPLY_ONLY
    max_loops: int = 3
    min_health_factor: float = 1.20
    target_utilization_range: tuple = (0.65, 0.85)
    rebalance_threshold_apy: float = 0.01  # 1% APY diff triggers rebalance
    max_borrow_apy: float = 0.10           # Don't borrow above 10% APY


class CompoundAgent:
    def __init__(
        self,
        rpc_url: str,
        private_key: str,
        agent_id: str,
        wallet: str,
        config: AgentConfig = None
    ):
        self.w3 = AsyncWeb3(AsyncHTTPProvider(rpc_url))
        self.private_key = private_key
        self.agent_id = agent_id
        self.wallet = wallet
        self.config = config or AgentConfig()

        # Load Comet ABI (abbreviated)
        self.usdc_comet = None   # init in setup()
        self.weth_comet = None

        # State
        self.current_strategy = None
        self.supply_amount = 0.0
        self.borrow_amount = 0.0
        self.last_supply_apy = 0.0
        self.last_borrow_apy = 0.0

    async def setup(self, comet_abi: list):
        """Initialize contracts"""
        self.usdc_comet = self.w3.eth.contract(
            address=COMET_USDC, abi=comet_abi
        )
        self.weth_comet = self.w3.eth.contract(
            address=COMET_WETH, abi=comet_abi
        )
        log.info("CompoundAgent contracts initialized")

    async def get_rates(self, comet) -> tuple[float, float]:
        """Fetch current supply and borrow APY from Comet"""
        SECONDS_PER_YEAR = 365 * 24 * 3600
        util = await comet.functions.getUtilization().call()
        supply_rate = await comet.functions.getSupplyRate(util).call()
        borrow_rate = await comet.functions.getBorrowRate(util).call()
        supply_apy = (1 + supply_rate / 1e18) ** SECONDS_PER_YEAR - 1
        borrow_apy = (1 + borrow_rate / 1e18) ** SECONDS_PER_YEAR - 1
        return supply_apy, borrow_apy, util / 1e18

    async def evaluate_strategy(self) -> Strategy:
        """Determine optimal strategy based on current market conditions"""
        usdc_supply, usdc_borrow, usdc_util = await self.get_rates(self.usdc_comet)
        weth_supply, weth_borrow, weth_util = await self.get_rates(self.weth_comet)

        STETH_APY = 0.038  # Fetch from Lido oracle in production

        # stETH loop net yield estimate (3 loops)
        loop_result = self._calc_loop_yield(STETH_APY, weth_borrow, ltv=0.90, loops=3)
        loop_net_apy = loop_result["net_apy_on_initial"]

        log.info(f"USDC supply: {usdc_supply:.2%} | WETH loop net: {loop_net_apy:.2%}")

        # Choose highest net APY strategy above minimums
        candidates = []
        if usdc_util > self.config.target_utilization_range[0]:
            candidates.append((usdc_supply, Strategy.USDC_SUPPLY))
        if weth_borrow < self.config.max_borrow_apy:
            candidates.append((loop_net_apy, Strategy.WETH_LOOP))

        if not candidates:
            return Strategy.SUPPLY_ONLY

        candidates.sort(reverse=True)
        return candidates[0][1]

    def _calc_loop_yield(self, coll_apy, borrow_apy, ltv, loops) -> dict:
        total_coll = 1.0 * (1 - ltv**(loops + 1)) / (1 - ltv)
        total_borrow = total_coll - 1.0
        net_yield = total_coll * coll_apy - total_borrow * borrow_apy
        return {
            "net_apy_on_initial": net_yield,
            "leverage": total_coll,
            "max_drop": 1 - total_borrow / total_coll
        }

    async def execute_usdc_supply(self, amount_usdc: float):
        """Supply USDC to cUSDCv3"""
        log.info(f"Supplying ${amount_usdc:,.2f} USDC to Compound V3")
        # Production: build tx for usdc_comet.supply(USDC_ADDR, amount)
        self.supply_amount = amount_usdc

                        "supply_amount": self.supply_amount,
                        "supply_apy": supply_apy,
                        "net_apy": net_apy,
                    },
                    timeout=10
                )
            except Exception as e:

    async def run(self):
        """Main agent loop"""
        log.info(f"CompoundAgent started | Strategy: {self.config.strategy.value}")

        while True:
            try:
                # Get current rates
                supply_apy, borrow_apy, utilization = await self.get_rates(self.usdc_comet)
                log.info(
                    f"cUSDCv3 | Supply: {supply_apy:.2%} | "
                    f"Borrow: {borrow_apy:.2%} | Util: {utilization:.1%}"
                )
                self.last_supply_apy = supply_apy
                self.last_borrow_apy = borrow_apy

                # Check if we need to rebalance strategy
                optimal_strategy = await self.evaluate_strategy()
                if optimal_strategy != self.current_strategy:
                    log.info(f"Strategy change: {self.current_strategy} → {optimal_strategy}")
                    self.current_strategy = optimal_strategy

                # Execute current strategy if not yet active
                if self.current_strategy == Strategy.USDC_SUPPLY and self.supply_amount == 0:
                    await self.execute_usdc_supply(10_000)

                elif self.current_strategy == Strategy.WETH_LOOP and self.borrow_amount == 0:
                    await self.execute_weth_loop(4.0, loops=self.config.max_loops)

                # Health check for leveraged positions
                hf = await self.check_and_defend_health(self.weth_comet)
                log.info(f"Health factor: {hf:.3f}")

                # Report to Purple Flea
                net_apy = supply_apy  # simplified; calculate actual P&L in production
                await self.report_to_purple_flea(supply_apy, net_apy)

                # Adaptive sleep: check more frequently at high utilization
                sleep_time = 60 if utilization < 0.85 else 15
                log.info(f"Sleeping {sleep_time}s (util={utilization:.1%})")
                await asyncio.sleep(sleep_time)

            except Exception as e:
                log.error(f"Agent loop error: {e}", exc_info=True)
                await asyncio.sleep(30)
