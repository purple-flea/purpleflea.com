Why Dagster

Asset-Aware Orchestration
for Financial Data

Most orchestrators treat pipelines as procedural scripts. Dagster treats them as data assets with lineage. Your wallet balance is not just a number returned from an API — it is a versioned, observable, re-materializable asset with a known provenance. That is the right mental model for agent finance.

📈
Software-Defined Assets
Declare your wallet balance, referral income, and escrow history as Dagster Assets. Track every materialization, re-compute on demand, and view historical values in the Dagster UI.
🔧
Typed Ops and Configs
Dagster ops accept typed inputs and configs via Pydantic. Pass settlement window size, alert thresholds, and market symbols as structured config — not environment variables.
🔌
Resources for API Keys
The PurpleFleaResource wraps your API key via Dagster's resource system. Inject it into any op or asset with a single type annotation — testable, swappable, safe.
🔋
Sensors on Escrow Events
Dagster sensors poll the Purple Flea escrow API and fire RunRequests the moment a new escrow is released. No cron needed — pipelines run exactly when data arrives.
📊
Full Observability
Every op invocation, asset materialization, and sensor run is logged in the Dagster UI with structured metadata — amounts, escrow IDs, funding rates, timestamps.
⚡
Partition-Aware Backfill
Re-materialize daily wallet balance assets for any historical date range with a single command. Reconstruct missing records without writing custom backfill scripts.

Concepts

Purple Flea Mapped to
Dagster Primitives

Each Purple Flea workflow maps cleanly to a Dagster concept. Understanding this mapping makes the integration feel natural rather than forced.

@op
fetch_escrow_data
A single unit of computation — fetches released escrows from the API, returns a typed list. Composes into jobs. Retryable, testable in isolation.
Asset
wallet_balance
A piece of data that Dagster knows how to produce and track. Wallet balance materialized daily — Dagster stores each snapshot with timestamp, enabling historical queries.
@job
settlement_pipeline
A graph of ops wired together. The settlement job chains fetch_escrow_data → process_payments → calculate_referral_income into a single executable unit.
@sensor
escrow_release_sensor
Polls the escrow API every 30 seconds. When a new released escrow is detected, fires a RunRequest with the escrow ID in RunConfig — no manual trigger needed.
@schedule
hourly_funding_rate
Cron-based execution — runs the funding rate collection job every hour. Generates RunConfig dynamically so each run targets the correct market.
Resource
PurpleFleaResource
Wraps the Purple Flea HTTP session. Injected into ops and assets via type annotation — swap for a mock resource in tests without changing op code.

Python dagster_purple_flea/resources.py 
from dagster import ConfigurableResource, EnvVar
import requests
from typing import Optional

class PurpleFleaResource(ConfigurableResource):
    """
    Dagster resource for the Purple Flea API.
    Inject into ops and assets via type annotation.

    Usage in definitions.py:
        resources={"pf": PurpleFleaResource(
            api_key=EnvVar("PURPLE_FLEA_API_KEY")
        )}
    """
    api_key: str
    base_url: str = "https://purpleflea.com/api"
    escrow_url: str = "https://escrow.purpleflea.com/api"
    faucet_url: str = "https://faucet.purpleflea.com/api"
    timeout: int = 30

    def _session(self) -> requests.Session:
        s = requests.Session()
        s.headers.update({
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json",
            "User-Agent": "PurpleFlea-Dagster/1.0",
        })
        return s

    def get(self, path: str, service: str = "main") -> dict:
        base = {
            "main": self.base_url,
            "escrow": self.escrow_url,
            "faucet": self.faucet_url,
        }[service]
        resp = self._session().get(f"{base}{path}", timeout=self.timeout)
        resp.raise_for_status()
        return resp.json()

    def post(self, path: str, data: dict, service: str = "main") -> dict:
        base = {
            "main": self.base_url,
            "escrow": self.escrow_url,
        }[service]
        resp = self._session().post(
            f"{base}{path}", json=data, timeout=self.timeout
        )
        resp.raise_for_status()
        return resp.json()
Python dagster_purple_flea/ops.py 
from dagster import op, Out, In, Config, OpExecutionContext
from typing import List
from .resources import PurpleFleaResource


class FetchEscrowConfig(Config):
    since_hours: int = 24
    status: str = "released"


@op(out=Out(List[dict]))
def fetch_escrow_data(
    context: OpExecutionContext,
    config: FetchEscrowConfig,
    pf: PurpleFleaResource,
) -> List[dict]:
    """
    Fetch escrow contracts from the Purple Flea escrow API.
    Filters by status and recency window from config.
    Returns list of escrow dicts for downstream processing.
    """
    data = pf.get(
        f"/escrows?status={config.status}&since_hours={config.since_hours}",
        service="escrow"
    )
    escrows = data.get("escrows", [])
    context.log.info(f"Fetched {len(escrows)} {config.status} escrows")
    context.add_output_metadata({
        "escrow_count": len(escrows),
        "status_filter": config.status,
        "since_hours": config.since_hours,
    })
    return escrows


@op(ins={"escrows": In(List[dict])}, out=Out(List[dict]))
def process_payments(
    context: OpExecutionContext,
    escrows: List[dict],
    pf: PurpleFleaResource,
) -> List[dict]:
    """
    For each released escrow, trigger the wallet transfer.
    Returns list of transfer result dicts.
    """
    results = []
    total_usdc = 0.0

    for escrow in escrows:
        eid = escrow["id"]
        try:
            result = pf.post(
                f"/escrows/{eid}/release-to-wallet",
                {"escrow_id": eid},
                service="escrow"
            )
            amount = result.get("amount_usdc", 0.0)
            total_usdc += amount
            results.append(result)
            context.log.info(f"Released escrow {eid}: {amount:.4f} USDC")
        except Exception as e:
            context.log.warning(f"Failed to release escrow {eid}: {e}")

    context.add_output_metadata({
        "processed_count": len(results),
        "total_usdc": total_usdc,
        "failed_count": len(escrows) - len(results),
    })
    return results


class ReferralConfig(Config):
    period_days: int = 7
    referral_rate: float = 0.15  # 15% of escrow fees


@op(ins={"transfers": In(List[dict])}, out=Out(dict))
def calculate_referral_income(
    context: OpExecutionContext,
    transfers: List[dict],
    config: ReferralConfig,
    pf: PurpleFleaResource,
) -> dict:
    """
    Fetch referral stats and calculate income earned
    from the 15% referral fee share on escrow transactions.
    """
    stats = pf.get(f"/referrals/stats?period_days={config.period_days}")

    # Calculate referral income: 15% of 1% fee on each referred escrow
    total_referred_volume = stats.get("total_referred_volume_usdc", 0.0)
    escrow_fee_rate = 0.01  # Purple Flea 1% escrow fee
    referral_income = total_referred_volume * escrow_fee_rate * config.referral_rate

    summary = {
        "total_referrals": stats.get("total_referrals", 0),
        "referred_volume_usdc": total_referred_volume,
        "referral_income_usdc": referral_income,
        "period_days": config.period_days,
        "settlement_transfers": len(transfers),
    }
    context.log.info(f"Referral income: {referral_income:.4f} USDC")
    context.add_output_metadata(summary)
    return summary

from dagster import job, EnvVar
from .ops import fetch_escrow_data, process_payments, calculate_referral_income
from .resources import PurpleFleaResource


@job(
    name="settlement_pipeline",
    description="Full escrow settlement: fetch → process → referral calc",
    resource_defs={
        "pf": PurpleFleaResource.configure_at_launch(),
    },
    tags={
        "team": "agent-finance",
        "service": "purple-flea",
    },
)
def settlement_pipeline():
    """
    Wire ops together. Dagster resolves types and injects resources.
    fetch_escrow_data output feeds into process_payments input.
    process_payments output feeds into calculate_referral_income.
    """
    escrows = fetch_escrow_data()
    transfers = process_payments(escrows=escrows)
    calculate_referral_income(transfers=transfers)

    "resources": {
        "pf": {

                "api_key": {"env": "PURPLE_FLEA_API_KEY"}

Asset dagster_purple_flea/assets.py 
from dagster import (
    asset, AssetExecutionContext, MetadataValue,
    DailyPartitionsDefinition, Output
)
from datetime import datetime
from .resources import PurpleFleaResource

# Partition by calendar day so each materialization = one day's snapshot
daily_partitions = DailyPartitionsDefinition(
    start_date="2026-01-01",
    timezone="UTC"
)


@asset(
    name="wallet_balance",
    group_name="purple_flea_finance",
    partitions_def=daily_partitions,
    description="Daily snapshot of the agent wallet USDC balance",
)
def wallet_balance(
    context: AssetExecutionContext,
    pf: PurpleFleaResource,
) -> Output[dict]:
    """
    Materialize a daily wallet balance snapshot.
    Each partition key is a date string (YYYY-MM-DD).
    Dagster stores the materialization with timestamp for historical queries.
    """
    partition_date = context.partition_key  # e.g. "2026-03-07"
    context.log.info(f"Materializing wallet_balance for {partition_date}")

    data = pf.get("/wallet/balance")
    balance_snapshot = {
        "date": partition_date,
        "usdc_balance": data.get("usdc", 0.0),
        "wallet_address": data.get("address"),
        "pending_escrow_usdc": data.get("pending_escrow_usdc", 0.0),
        "materialized_at": datetime.utcnow().isoformat(),
    }

    return Output(
        value=balance_snapshot,
        metadata={
            "usdc_balance": MetadataValue.float(balance_snapshot["usdc_balance"]),
            "wallet_address": MetadataValue.text(balance_snapshot["wallet_address"]),
            "pending_escrow": MetadataValue.float(balance_snapshot["pending_escrow_usdc"]),
        }
    )


@asset(
    name="referral_income_report",
    group_name="purple_flea_finance",
    deps=[wallet_balance],  # Dagster tracks lineage
    description="Weekly referral income report derived from wallet balance asset",
)
def referral_income_report(
    context: AssetExecutionContext,
    pf: PurpleFleaResource,
) -> Output[dict]:
    """
    Fetch referral stats and compute 15% income from the 1% escrow fee.
    Dagster records this as a downstream asset of wallet_balance.
    """
    stats = pf.get("/referrals/stats?period_days=7")

    referred_volume = stats.get("total_referred_volume_usdc", 0.0)
    # 15% of the 1% escrow fee Purple Flea charges
    income = referred_volume * 0.01 * 0.15

    report = {
        "period_days": 7,
        "total_referrals": stats.get("total_referrals", 0),
        "referred_volume_usdc": referred_volume,
        "referral_income_usdc": income,
        "referral_rate_pct": 15.0,
        "generated_at": datetime.utcnow().isoformat(),
    }

    return Output(
        value=report,
        metadata={
            "referral_count": MetadataValue.int(report["total_referrals"]),
            "income_usdc": MetadataValue.float(income),
            "referred_volume": MetadataValue.float(referred_volume),
        }
    )

@sensor

Escrow Release Sensor
Triggers on New Events

Instead of waiting for a scheduled run, the escrow sensor polls the Purple Flea API continuously. The moment a new escrow is released, it fires a RunRequest with the escrow ID embedded in the run config — no manual trigger, no missed events.

@sensor
escrow_release_sensor
polls every 30s
→
RunRequest
settlement_pipeline
with escrow_id in config
Sensor dagster_purple_flea/sensors.py 
from dagster import (
    sensor, SensorEvaluationContext, RunRequest,
    SkipReason, SensorResult
)
from .resources import PurpleFleaResource
from .jobs import settlement_pipeline
import json


@sensor(
    job=settlement_pipeline,
    minimum_interval_seconds=30,
    description="Fires when a new escrow contract is released",
)
def escrow_release_sensor(
    context: SensorEvaluationContext,
    pf: PurpleFleaResource,
) -> SensorResult:
    """
    Sensor that polls Purple Flea escrow API every 30 seconds.
    Uses cursor to track the last-seen escrow ID so it does not
    re-trigger on already-processed releases.

    Yields one RunRequest per new released escrow.
    """
    last_seen_id = context.cursor or ""

    data = pf.get("/escrows?status=released&limit=50", service="escrow")
    escrows = data.get("escrows", [])

    if not escrows:
        return SensorResult(
            skip_reason=SkipReason("No released escrows found"),
            cursor=last_seen_id,
        )

    # Sort escrows by created_at ascending to process oldest first
    escrows.sort(key=lambda e: e.get("released_at", ""))

    new_escrows = [
        e for e in escrows
        if e["id"] > last_seen_id  # IDs are lexicographically sortable
    ]

    if not new_escrows:
        return SensorResult(
            skip_reason=SkipReason(f"No new escrows since cursor={last_seen_id}"),
            cursor=last_seen_id,
        )

    run_requests = []
    for escrow in new_escrows:
        eid = escrow["id"]
        context.log.info(f"New released escrow detected: {eid}")

        run_config = {
            "ops": {
                "fetch_escrow_data": {
                    "config": {
                        "since_hours": 1,   # narrow window for sensor runs
                        "status": "released",
                    }
                },
                "calculate_referral_income": {
                    "config": {"period_days": 1, "referral_rate": 0.15}
                },
            },
            "resources": {
                "pf": {"config": {"api_key": {"env": "PURPLE_FLEA_API_KEY"}}}
            }
        }

        run_requests.append(RunRequest(
            run_key=f"escrow_release_{eid}",  # idempotency key
            run_config=run_config,
            tags={
                "escrow_id": eid,
                "trigger": "sensor",
                "amount_usdc": str(escrow.get("amount_usdc", "")),
            }
        ))

    newest_id = new_escrows[-1]["id"]
    return SensorResult(
        run_requests=run_requests,
        cursor=newest_id,  # advance cursor past processed escrows
    )
↻
Idempotency via run_key: Each RunRequest uses run_key=f"escrow_release_{eid}". Dagster will never launch a second run with the same key — even if the sensor fires multiple times before the cursor advances. No duplicate settlements.

@schedule

Hourly Funding Rate
Collection Schedule

Schedules in Dagster generate RunRequests on a cron expression. The funding rate schedule runs every hour and passes the target market as a run config value — configurable without redeploying.

Schedule dagster_purple_flea/schedules.py 
from dagster import (
    op, job, schedule, RunRequest,
    ScheduleEvaluationContext, Config,
    OpExecutionContext
)
from .resources import PurpleFleaResource


class FundingRateConfig(Config):
    market: str = "USDC-PERP"
    alert_threshold: float = 0.001
    annualize: bool = True


@op
def collect_funding_rate(
    context: OpExecutionContext,
    config: FundingRateConfig,
    pf: PurpleFleaResource,
) -> dict:
    """Fetch and log the current perpetual funding rate."""
    data = pf.get(f"/trading/funding-rate?market={config.market}")
    rate = data.get("current_rate", 0.0)
    annualized = rate * 8760 if config.annualize else rate

    context.log.info(
        f"Funding rate {config.market}: {rate:.6f} ({annualized:.2%} annual)"
    )

    if abs(rate) > config.alert_threshold:
        context.log.warning(
            f"ALERT: Funding rate {rate:.6f} exceeds threshold {config.alert_threshold}"
        )

    result = {
        "market": config.market,
        "rate": rate,
        "annualized_rate": annualized,
        "above_threshold": abs(rate) > config.alert_threshold,
        "timestamp": data.get("timestamp"),
    }
    context.add_output_metadata(result)
    return result


@job(resource_defs={"pf": PurpleFleaResource.configure_at_launch()})
def funding_rate_job():
    collect_funding_rate()


@schedule(
    job=funding_rate_job,
    cron_schedule="0 * * * *",  # Every hour on the hour
    execution_timezone="UTC",
    name="hourly_funding_rate_schedule",
    description="Collect Purple Flea funding rate every hour",
)
def hourly_funding_rate_schedule(context: ScheduleEvaluationContext):
    """
    Generates a RunRequest with typed run config each hour.
    The market and alert_threshold can be overridden without code changes.
    """
    return RunRequest(
        run_config={
            "ops": {
                "collect_funding_rate": {
                    "config": {
                        "market": "USDC-PERP",
                        "alert_threshold": 0.001,
                        "annualize": True,
                    }
                }
            },
            "resources": {
                "pf": {"config": {"api_key": {"env": "PURPLE_FLEA_API_KEY"}}}
            }
        },
        tags={"market": "USDC-PERP", "schedule": "hourly"}
    )

from dagster import Definitions, EnvVar, load_assets_from_modules
from . import assets
from .jobs import settlement_pipeline
from .schedules import (
    funding_rate_job,
    hourly_funding_rate_schedule,
)
from .sensors import escrow_release_sensor
from .resources import PurpleFleaResource

# Load all @asset-decorated functions from assets module
all_assets = load_assets_from_modules([assets])

# Single Definitions object — Dagster's entry point
defs = Definitions(
    assets=all_assets,
    jobs=[settlement_pipeline, funding_rate_job],
    schedules=[hourly_funding_rate_schedule],
    sensors=[escrow_release_sensor],
    resources={
        "pf": PurpleFleaResource(
            api_key=EnvVar("PURPLE_FLEA_API_KEY")
        )
    },
)
🔒
EnvVar vs hardcoding: EnvVar("PURPLE_FLEA_API_KEY") tells Dagster to read the key at runtime from the environment — never at import time. This means the same code works in local dev, staging, and production without changes. Your key never appears in definitions.py.
●
Testing with mock resources: In tests, pass resources={"pf": MockPurpleFleaResource()} to settlement_pipeline.execute_in_process(). The mock implements the same interface — no real API calls, no test API keys needed.
