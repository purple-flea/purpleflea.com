Decorators

@flow and @task for Purple Flea Operations

Prefect's decorator model maps cleanly onto Purple Flea's service architecture. Each API call becomes a @task with its own retry policy and result caching. Tasks compose into @flow functions that Prefect tracks, schedules, and visualizes end-to-end. No subclassing, no config files — just decorated Python functions.

📋

@task: Atomic API Calls

Each Purple Flea API call — place order, check balance, create escrow — is a @task with its own retries, retry_delay_seconds, and cache_key_fn. Failures are isolated and retried without re-running the whole flow.

🌊

@flow: End-to-End Pipelines

Compose tasks into named flows with @flow(name="trading-pipeline"). Prefect tracks every flow run, logs inputs/outputs, and provides a visual DAG of task execution in the UI.

📅

Scheduling Built In

Deploy any flow with a cron or interval schedule. A DCA flow that runs every 4 hours is three lines of Python with a DeploymentSchedule — no external scheduler needed.

🚨

Automations on Events

Trigger flows automatically when wallet balance drops below a threshold, when a flow run fails, or on any custom event emitted by a Purple Flea API webhook. Fully declarative.

# Purple Flea tasks as Prefect @task functions from prefect import flow, task from prefect.tasks import exponential_backoff import httpx, os BASE = "https://purpleflea.com/api" KEY = os.environ["PURPLE_FLEA_API_KEY"] # pf_live_... HEADERS = {"Authorization": f"Bearer {KEY}"} @task(retries=3, retry_delay_seconds=exponential_backoff(backoff_factor=2)) def get_wallet_balance() -> float: r = httpx.get(f"{BASE}/wallet/balance", headers=HEADERS, timeout=10) r.raise_for_status() return r.json()["balance_usd"] @task(retries=5, retry_delay_seconds=exponential_backoff(backoff_factor=2)) def place_order(asset: str, size_usd: float, direction: str = "long") -> str: r = httpx.post( f"{BASE}/trading/orders", headers=HEADERS, timeout=15, json={"asset": asset, "size_usd": size_usd, "direction": direction} ) r.raise_for_status() return r.json()["order_id"] @task(retries=3, retry_delay_seconds=10) def create_escrow(amount_usd: float, recipient_agent_id: str) -> str: r = httpx.post( f"{BASE}/escrow/create", headers=HEADERS, timeout=15, json={"amount_usd": amount_usd, "recipient": recipient_agent_id} ) r.raise_for_status() return r.json()["escrow_id"] @task(retries=3, retry_delay_seconds=5) def release_escrow(escrow_id: str, release_to: str = "counterparty") -> bool: r = httpx.post( f"{BASE}/escrow/{escrow_id}/release", headers=HEADERS, timeout=10, json={"release_to": release_to} ) return r.status_code == 200
Complete Example

Full trading_flow() with Prefect Decorators

The full trading flow composes balance checks, signal evaluation, order placement, fill confirmation, and escrow settlement into a single observable Prefect flow. Every task result is logged. The flow run timeline is visible in the Prefect UI with task-level timing and retry counts.

from prefect import flow, task, get_run_logger from prefect.artifacts import create_table_artifact from prefect.tasks import exponential_backoff from datetime import datetime import httpx, os, time BASE = "https://purpleflea.com/api" KEY = os.environ["PURPLE_FLEA_API_KEY"] HEADERS = {"Authorization": f"Bearer {KEY}"} @task(retries=3, retry_delay_seconds=exponential_backoff(backoff_factor=2)) def get_wallet_balance() -> float: r = httpx.get(f"{BASE}/wallet/balance", headers=HEADERS) r.raise_for_status() return r.json()["balance_usd"] @task def evaluate_signal(balance: float, strategy: dict) -> dict | None: # Return None to skip, or a signal dict to trade if balance < strategy.get("min_balance_usd", 10): return None return { "asset": strategy["asset"], "size_usd": min(strategy["size_usd"], balance * 0.9), "direction": strategy.get("direction", "long"), } @task(retries=5, retry_delay_seconds=exponential_backoff(backoff_factor=2)) def place_order(signal: dict) -> str: r = httpx.post(f"{BASE}/trading/orders", headers=HEADERS, json=signal) r.raise_for_status() return r.json()["order_id"] @task(retries=12, retry_delay_seconds=10) def await_fill(order_id: str) -> dict: r = httpx.get(f"{BASE}/trading/orders/{order_id}", headers=HEADERS) r.raise_for_status() data = r.json() if data["status"] != "filled": raise RuntimeError(f"Order {order_id} not yet filled: {data['status']}") return data["fill"] @task(retries=3) def create_escrow(amount_usd: float, recipient: str) -> str: r = httpx.post( f"{BASE}/escrow/create", headers=HEADERS, json={"amount_usd": amount_usd, "recipient": recipient} ) r.raise_for_status() return r.json()["escrow_id"] @task(retries=5) def settle_escrow(escrow_id: str, fill: dict) -> dict: r = httpx.post( f"{BASE}/escrow/{escrow_id}/release", headers=HEADERS, json={"release_to": "counterparty", "fill": fill} ) r.raise_for_status() return r.json() @flow(name="purple-flea-trading-pipeline", log_prints=True) def trading_flow(strategy: dict): logger = get_run_logger() start = datetime.utcnow() # 1. Check wallet balance balance = get_wallet_balance() logger.info(f"Wallet balance: ${balance:.2f}") # 2. Evaluate whether to trade this cycle signal = evaluate_signal(balance, strategy) if not signal: logger.info("Signal evaluation: no trade this cycle") return {"status": "skipped"} logger.info(f"Signal: {signal['direction']} {signal['asset']} ${signal['size_usd']}") # 3. Reserve funds in escrow before placing order escrow_id = create_escrow(signal["size_usd"], strategy.get("counterparty_id", "exchange")) logger.info(f"Escrow created: {escrow_id}") # 4. Place order with retry and backoff order_id = place_order(signal) logger.info(f"Order placed: {order_id}") # 5. Wait for fill (12 retries x 10s = 2 minutes max) fill = await_fill(order_id) logger.info(f"Order filled at ${fill['price']} — qty: {fill['qty']}") # 6. Settle escrow on confirmed fill settlement = settle_escrow(escrow_id, fill) elapsed = (datetime.utcnow() - start).total_seconds() # 7. Create a Prefect artifact with trade details create_table_artifact( key="trade-execution-report", table=[{ "Field": k, "Value": str(v) } for k, v in { "Order ID": order_id, "Escrow ID": escrow_id, "Asset": signal["asset"], "Direction": signal["direction"], "Size USD": f"${signal['size_usd']:.2f}", "Fill Price": f"${fill['price']:.4f}", "Elapsed (s)": f"{elapsed:.1f}", "Status": "settled", }.items()], description="Purple Flea trade execution summary", ) return {"status": "settled", "order_id": order_id, "fill": fill} # Run directly or deploy as a Prefect deployment if __name__ == "__main__": trading_flow(strategy={ "asset": "BTC", "size_usd": 100, "direction": "long", "min_balance_usd": 20, })
Prefect Automations

Automations Triggered by Wallet Balance Changes

Prefect Automations let you react to events — including custom events emitted by your Purple Flea integration — without polling. When a balance-monitor flow detects a low-balance condition, it emits a Prefect event that triggers a top-up flow or sends an alert. All declarative, all in Python.

from prefect import flow, task from prefect.events import emit_event from prefect.automations import Automation from prefect.events.schemas.automations import EventTrigger, RunDeployment import httpx, os BASE = "https://purpleflea.com/api" HEADERS = {"Authorization": f"Bearer {os.environ['PURPLE_FLEA_API_KEY']}"} @task(retries=3) def check_balance_and_emit(low_balance_threshold: float = 20.0) -> float: r = httpx.get(f"{BASE}/wallet/balance", headers=HEADERS) r.raise_for_status() balance = r.json()["balance_usd"] if balance < low_balance_threshold: # Emit a Prefect event — triggers the automation below emit_event( event="purple-flea.wallet.low-balance", resource={"prefect.resource.id": "purple-flea-wallet"}, payload={"balance_usd": balance, "threshold": low_balance_threshold}, ) return balance @task(retries=3) def claim_faucet_funds(agent_id: str) -> dict: # Claim free funds from the Purple Flea Faucet r = httpx.post( f"{BASE}/faucet/claim", headers=HEADERS, json={"agent_id": agent_id} ) r.raise_for_status() return r.json() @flow(name="purple-flea-balance-monitor") def balance_monitor_flow(agent_id: str, threshold: float = 20.0): balance = check_balance_and_emit(threshold) print(f"Current balance: ${balance:.2f} (threshold: ${threshold:.2f})") @flow(name="purple-flea-topup") def topup_flow(agent_id: str): # Triggered automatically when low-balance event fires result = claim_faucet_funds(agent_id) print(f"Faucet claim result: {result}") # Define the automation (deploy once to Prefect Cloud/server) low_balance_automation = Automation( name="topup-on-low-balance", trigger=EventTrigger( expect={"purple-flea.wallet.low-balance"}, for_each={"prefect.resource.id"}, posture="Reactive", threshold=1, ), actions=[ RunDeployment( deployment_name="topup-flow/purple-flea-topup", parameters={"agent_id": "my-agent-id"}, ) ], )

Purple Flea Faucet integration: The claim_faucet_funds task is automatically triggered by the low-balance automation. New agents register at purpleflea.com/faucet and receive free funds to get started. The faucet endpoint is idempotent — safe to retry with the same agent ID.

Infrastructure

Work Pools for Agent Infrastructure

Prefect Work Pools abstract the compute layer. You define the pool type (process, Docker, Kubernetes, ECS) and Prefect dispatches flow runs to it. For financial agent fleets, this means spinning up isolated containers per agent without managing scheduling infrastructure manually.

Each Purple Flea agent runs its trading flows in its own Prefect worker process or container. Work Pools enforce resource limits, environment isolation, and concurrency controls — critical for agents sharing rate-limited Purple Flea API quota.

🐳

Docker Work Pool

Each flow run launches in a fresh Docker container with the agent's own environment variables (API key, strategy config). Complete isolation between agents.

☁

Kubernetes Work Pool

Deploy agent flows as Kubernetes Jobs. Auto-scales with cluster resources. Ideal for running dozens of independent Purple Flea trading agents simultaneously.

💻

Process Work Pool

Simplest setup: runs flow runs as local processes on the same machine. Perfect for development and single-agent deployments before moving to containers.

🔧

Push Work Pools

Prefect Cloud pushes work directly to ECS, Cloud Run, or Modal without a long-running worker process. Fully serverless agent execution that scales to zero.

# Deploy trading_flow to a Docker Work Pool # prefect work-pool create purple-flea-agents --type docker from prefect import flow from prefect.deployments import DeploymentSchedule from prefect.client.schemas.schedules import CronSchedule if __name__ == "__main__": trading_flow.deploy( name="purple-flea-btc-dca", work_pool_name="purple-flea-agents", image="my-org/purple-flea-agent:latest", push=True, schedules=[ DeploymentSchedule( schedule=CronSchedule(cron="0 */4 * * *"), # every 4 hours active=True, ) ], parameters={ "strategy": { "asset": "BTC", "size_usd": 50, "direction": "long", "min_balance_usd": 15, } }, job_variables={ "env": { "PURPLE_FLEA_API_KEY": "{{ prefect.blocks.secret.pf-api-key }}" }, "image_pull_policy": "Always", }, ) print("Deployment created: purple-flea-btc-dca")
Rate Limiting

Concurrency Limits for Rate-Limited Purple Flea API

Purple Flea's API has per-key rate limits. When running multiple concurrent agents or high-frequency strategies, Prefect's global concurrency limits act as a distributed semaphore — ensuring your agents never collectively exceed the API rate limit, even when running in separate processes or containers.

from prefect import flow, task from prefect.concurrency.sync import concurrency # pip install prefect # includes concurrency primitives # Create the limit once: # prefect global-concurrency-limit create purple-flea-api --limit 10 --slot-decay-per-second 2 @task(retries=3, retry_delay_seconds=exponential_backoff(backoff_factor=2)) def place_order_rate_limited(signal: dict) -> str: # Acquires 1 slot from the global purple-flea-api limit # Blocks if 10 concurrent API calls are already in flight with concurrency("purple-flea-api", occupy=1): r = httpx.post( f"{BASE}/trading/orders", headers=HEADERS, json=signal ) r.raise_for_status() return r.json()["order_id"] @task def get_balance_rate_limited() -> float: with concurrency("purple-flea-api", occupy=1): r = httpx.get(f"{BASE}/wallet/balance", headers=HEADERS) r.raise_for_status() return r.json()["balance_usd"] # For async tasks (recommended for high-throughput flows): from prefect.concurrency.asyncio import concurrency as async_concurrency import asyncio @task async def place_order_async(signal: dict) -> str: async with async_concurrency("purple-flea-api", occupy=1): async with httpx.AsyncClient() as client: r = await client.post( f"{BASE}/trading/orders", headers=HEADERS, json=signal ) r.raise_for_status() return r.json()["order_id"] @flow(name="parallel-agent-flow") async def run_multiple_agents(signals: list[dict]): # All concurrent — concurrency limit prevents API throttling results = await asyncio.gather(*[ place_order_async(sig) for sig in signals ]) return results

Global vs task-level concurrency: Prefect's global concurrency limits work across all workers and processes — not just within a single flow run. This is what makes them useful for shared Purple Flea API rate limits. Set the slot_decay_per_second to match your API rate limit tier.

Observability

Prefect Artifacts for Trade Execution Reports

Prefect Artifacts let you attach structured data to flow runs — tables, Markdown summaries, key-value pairs, and progress updates. Every Purple Flea trade execution produces a rich artifact visible in the Prefect UI without any external reporting infrastructure.

from prefect.artifacts import ( create_table_artifact, create_markdown_artifact, create_progress_artifact, update_progress_artifact, ) from prefect import flow, task @task def create_trade_report(trade_data: dict) -> str: # Structured table artifact — visible in Prefect UI artifact_id = create_table_artifact( key="trade-execution", table=[ {"Field": "Order ID", "Value": trade_data["order_id"]}, {"Field": "Asset", "Value": trade_data["asset"]}, {"Field": "Direction", "Value": trade_data["direction"]}, {"Field": "Fill Price", "Value": f"${trade_data['fill_price']:.4f}"}, {"Field": "Size USD", "Value": f"${trade_data['size_usd']:.2f}"}, {"Field": "Escrow ID", "Value": trade_data.get("escrow_id", "—")}, {"Field": "P&L USD", "Value": f"${trade_data.get('pnl_usd', 0):.2f}"}, {"Field": "Status", "Value": trade_data["status"]}, ], description="Purple Flea trade execution summary", ) return artifact_id @task def create_daily_summary(trades: list[dict]) -> str: total_vol = sum(t["size_usd"] for t in trades) total_pnl = sum(t.get("pnl_usd", 0) for t in trades) win_rate = len([t for t in trades if t.get("pnl_usd", 0) > 0]) / max(len(trades), 1) markdown = f""" ## Purple Flea Daily Trading Report | Metric | Value | |--------|-------| | Total Trades | {len(trades)} | | Total Volume | ${total_vol:.2f} | | Total P&L | ${total_pnl:.2f} | | Win Rate | {win_rate:.1%} | [View Wallet Balance](https://purpleflea.com/wallet) · [View Escrow History](https://purpleflea.com/escrow) """ artifact_id = create_markdown_artifact( key="daily-report", markdown=markdown, description="End-of-day Purple Flea trading summary", ) return artifact_id @flow(name="purple-flea-daily-close") def daily_close_flow(trades: list[dict]): for trade in trades: create_trade_report(trade) summary_id = create_daily_summary(trades) print(f"Daily report artifact: {summary_id}")
Scheduling

Trading Strategies as Prefect Deployments

Each trading strategy becomes its own Prefect deployment with an independent schedule. Market-making, DCA, arbitrage scanning, and portfolio rebalancing each have different timing requirements — Prefect lets you schedule them independently with cron, interval, or RRule expressions, all managed from a single UI.

DCA: Dollar Cost Average
cron: 0 */4 * * *
Buy a fixed USD amount every 4 hours. Runs as a Prefect deployment with cron schedule. Low execution time, high reliability requirements.
Portfolio Rebalance
cron: 0 2 * * 1
Rebalance to target allocations every Monday at 2am UTC. Reads current holdings, computes deltas, executes trades via Purple Flea trading API.
Arbitrage Scanner
interval: 60 seconds
Scan for arb opportunities every minute. Uses concurrency limits to prevent Purple Flea API overload across multiple concurrent scan tasks.
Balance Monitor
interval: 300 seconds
Check wallet balance every 5 minutes. Emits low-balance Prefect events that trigger the faucet claim automation automatically.
Daily Report
cron: 0 23 * * *
Generate end-of-day trade execution artifact. Summarizes P&L, volume, win rate, and escrow settlements for the day.
Market Making
interval: 30 seconds
Quote refresh every 30 seconds. Uses async tasks with Purple Flea trading API. Concurrency limit prevents rate-limit errors at high frequency.
# Deploy multiple strategies with independent schedules from prefect.client.schemas.schedules import CronSchedule, IntervalSchedule from prefect.deployments import DeploymentSchedule from datetime import timedelta # DCA every 4 hours trading_flow.deploy( name="dca-btc-4h", work_pool_name="purple-flea-agents", schedules=[DeploymentSchedule( schedule=CronSchedule(cron="0 */4 * * *", timezone="UTC"), active=True, )], parameters={"strategy": {"asset": "BTC", "size_usd": 50, "direction": "long"}}, ) # Balance monitor every 5 minutes balance_monitor_flow.deploy( name="balance-monitor-5m", work_pool_name="purple-flea-agents", schedules=[DeploymentSchedule( schedule=IntervalSchedule(interval=timedelta(minutes=5)), active=True, )], parameters={"agent_id": "my-agent-id", "threshold": 20.0}, ) # Daily close report at 23:00 UTC daily_close_flow.deploy( name="daily-report-23h", work_pool_name="purple-flea-agents", schedules=[DeploymentSchedule( schedule=CronSchedule(cron="0 23 * * *", timezone="UTC"), active=True, )], )
Getting Started

From Zero to Deployed Agent in 5 Steps

No infrastructure required to get started. Prefect runs locally with a SQLite backend during development and graduates to Prefect Cloud for production deployments with full UI, automations, and Work Pools.

1

Install Prefect and claim free Purple Flea funds

Run pip install prefect httpx. Register your agent at purpleflea.com/faucet to claim free funds for testing — zero risk, no upfront capital required.

2

Write your first @flow

Copy the trading_flow() example above. Run it directly with python flow.py — Prefect starts a local server and shows the run in a local UI at localhost:4200.

3

Connect to Prefect Cloud

Sign up for free at app.prefect.io. Run prefect cloud login and all subsequent flow runs are tracked in the Cloud UI with full observability and artifact storage.

4

Create a Work Pool and deploy

Create a Process or Docker Work Pool and deploy your flows with schedules. The Prefect worker on your machine (or container) picks up scheduled runs automatically.

5

Set up automations and alerts

Configure the low-balance automation from the example above. Add Slack or email notifications on flow run failures. Your agent runs autonomously with alerts when anything needs attention.
