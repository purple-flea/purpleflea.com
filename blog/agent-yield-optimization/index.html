Yield Optimization for AI Agents: Automate Your Path to Maximum APY

March 6, 2026 Purple Flea Team 7 min read

Introduction

Most agents leave yield on the table. Idle USDC earns 0%. ETH that could be staked for 3-4% APY sits as a base asset. Capital allocated to a single lending protocol earns a fixed rate while better opportunities go untouched on other protocols. A yield optimization agent solves this systematically: it compares all available opportunities across the yield landscape every day, factors in gas costs and risk, and automatically reallocates capital to wherever the net return is highest.

For AI agents that hold financial assets — whether from casino earnings, trading profits, or funded wallets — yield optimization is pure alpha that requires no market prediction. You are not taking directional risk. You are simply ensuring that the same assets are always working as hard as possible.

The optimizer's job is to capture these fluctuations automatically rather than missing them because a human forgot to check.

The Optimizer's Decision Tree

The core logic of any yield optimizer is straightforward: is the gain from rebalancing worth more than the cost of doing it? The decision rule is:

if APY_gain > threshold AND gas_cost < max_gas_fraction:
    rebalance()

A reasonable threshold is 0.5% APY gain. If you have $10,000 deployed and find an opportunity earning 0.5% more per year, that is $50 extra annually. Whether that justifies the gas cost depends on current network fees — which is why gas must be factored into every rebalancing decision, not treated as a fixed cost.

Python Yield Optimizer

The following agent queries Purple Flea's yield API, compares against the current portfolio APY, and executes a rebalance when it finds something meaningfully better:

import requests
import schedule
import time

PF_BASE = "https://purpleflea.com/api"
PF_KEY = "your-api-key"
HEADERS = {"Authorization": f"Bearer {PF_KEY}", "Content-Type": "application/json"}
APY_THRESHOLD = 0.5  # Only rebalance if new APY beats current by > 0.5%

def daily_yield_optimization(wallet: str, total_usd: float):
    # Get current portfolio weighted APY
    portfolio = requests.get(
        f"{PF_BASE}/v1/portfolio/balances",
        params={"wallet": wallet},
        headers=HEADERS
    ).json()

    # Get all yield opportunities up to risk level 5
    opps = requests.get(
        f"{PF_BASE}/v1/yield/opportunities",
        params={"risk_max": 5},
        headers=HEADERS
    ).json()["opportunities"]

    current_apy = portfolio.get("weighted_apy", 0)
    best = max(opps, key=lambda x: x["apy_net"])

    print(f"Current APY: {current_apy:.2f}% | Best available: {best['apy_net']:.2f}%")

    if best["apy_net"] > current_apy + APY_THRESHOLD:
        # Estimate gas cost of rebalancing
        gas_estimate = requests.get(
            f"{PF_BASE}/v1/yield/rebalance-gas-estimate",
            params={"from_protocol": portfolio["current_protocol"], "to_protocol": best["protocol_id"]},
            headers=HEADERS
        ).json()

        annual_gain_usd = total_usd * (best["apy_net"] - current_apy) / 100
        gas_usd = gas_estimate["gas_usd"]

        if annual_gain_usd > gas_usd * 12:  # Breakeven in under 1 month
            result = requests.post(
                f"{PF_BASE}/v1/yield/optimize",
                json={
                    "total_capital": total_usd,
                    "max_positions": 3,
                    "risk_budget": 5
                },
                headers=HEADERS
            ).json()
            print(f"Rebalanced to {result['new_apy']:.2f}% APY (was {current_apy:.2f}%)")
        else:
            print(f"Gas cost ${gas_usd:.2f} not justified by ${annual_gain_usd/12:.2f}/month gain")
    else:
        print("No rebalance warranted — already near optimal")

# Run daily at 00:05 UTC
schedule.every().day.at("00:05").do(daily_yield_optimization, wallet="your-wallet", total_usd=10000)
while True:
    schedule.run_pending()
    time.sleep(60)

Gas Cost Considerations

Gas is the silent yield killer that most naive yield optimizers ignore. A 0.5% APY gain on $10,000 is $50 per year. If the rebalancing transaction costs $40 in gas, you barely break even — and that assumes the new rate holds for the full year, which it often does not.

The rule of thumb used in the code above: only rebalance when the annualized gain covers the gas cost in under one month. That is, annual_gain_usd > gas_usd × 12. For larger capital bases ($100K+), this threshold becomes much easier to hit and rebalancing becomes more frequent.

On L2s like Base or Arbitrum, gas costs are typically 10–50x lower than mainnet Ethereum. Deploying yield optimization strategies on L2s dramatically increases the frequency at which rebalancing is profitable.

Compounding: Reinvesting Yield Earnings

Compounding amplifies the long-run benefit of yield optimization. Rather than letting earned yield accumulate passively, a compounding agent claims yield periodically, adds it to the principal, and re-runs the optimizer on the now-larger capital base.

def weekly_compound(wallet: str):
    """Claim yield, add to principal, reoptimize"""
    # Claim accrued yield from all active positions
    claims = requests.post(f"{PF_BASE}/v1/yield/claim-all",
        json={"wallet": wallet}, headers=HEADERS).json()

    claimed_usd = sum(c["amount_usd"] for c in claims["claims"])
    print(f"Claimed ${claimed_usd:.2f} in yield this week")

    if claimed_usd > 5:  # Only compound if material amount

schedule.every().week.do(weekly_compound, wallet="your-wallet")

At 8% APY with weekly compounding, $10,000 grows to roughly $10,830 after one year. With daily compounding it reaches $10,832 — barely different at these rates. Weekly is sufficient and keeps transaction costs low.

The Stack Strategy: Layered Yield

The most capital-efficient yield approach does not choose between protocols — it uses the same capital in multiple yield layers simultaneously. The stack strategy works like this:

  1. Stake ETH via Lido to receive stETH (earning ~3.5% base staking yield)
  2. Restake stETH via EigenLayer to earn additional AVS validation rewards on top
  3. Tokenize the yield via Pendle: sell future yield as PT tokens at a discount to lock in a fixed rate, or hold YT tokens to speculate on yield increases

Each layer adds yield on top of the previous without requiring new capital. The stack risks are additive — smart contract risk at each layer — so position sizing discipline is essential. An automated agent monitors the total risk-adjusted yield of the stack vs. simpler alternatives and rebalances when the risk premium is no longer adequate.
