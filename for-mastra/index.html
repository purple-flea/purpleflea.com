Mastra is a TypeScript-native agent framework built by Mastra.ai for composing tools, workflows, and memory in type-safe production agents. Framework Overview

Mastra: TypeScript Agents, Batteries Included

Mastra lets you define agents as composable TypeScript objects with schemas, tools, memory, and streaming built in. Unlike LangChain (Python-first) or AutoGen (conversation-centric), Mastra is designed for production TypeScript monorepos where type safety and IDE support are non-negotiable. Purple Flea slots in as a set of typed tool definitions you add to any Mastra agent in under five minutes.

⚡

TypeScript-Native

Full end-to-end type inference from tool input schemas to return values. No runtime surprises; your IDE knows every field.

🔒

Schema Validation via Zod

Mastra uses Zod for input/output schemas. Purple Flea tools ship with matching Zod schemas so the LLM never passes malformed data on-chain.

📡

Streaming Support

Long-running operations like trade monitoring or casino session management surface progress events through Mastra's streaming pipeline.

🧠

Agent Memory Integration

Wallet addresses, trade history, and casino session IDs are stored in Mastra's agent memory store and recalled across sessions automatically.

Installation

One Package to Rule All Financial Tools

Install the Purple Flea Mastra adapter alongside your existing Mastra setup. The package ships zero runtime dependencies beyond the Purple Flea API client — no ethers, no web3, no blockchain SDK bloat in your bundle.

terminal shell 
# npm
npm install @purpleflea/mastra

# pnpm
pnpm add @purpleflea/mastra

# yarn
yarn add @purpleflea/mastra
Peer dependency: Requires @mastra/core ^0.5.0 and zod ^3.22.0. Both are almost certainly already in your project if you're using Mastra.
Quick Start

Wiring Up Financial Tools in 30 Lines

Use createTool from @mastra/core/tools to define each Purple Flea capability as a typed Mastra tool. Pass the tools array to your agent config and the LLM decides when to invoke them based on the description fields.

src/agent/tools.ts TypeScript 
import { createTool } from '@mastra/core/tools';
import { PurpleFleas } from '@purpleflea/mastra';
import { z } from 'zod';

// Initialise once; re-use across all tool definitions
const flea = new PurpleFleas({
  apiKey: process.env.PURPLE_FLEA_API_KEY,
});

// ── Wallet tool ──────────────────────────────────────────
export const walletTool = createTool({
  id: 'create-wallet',
  description: 'Create a non-custodial BIP-39 crypto wallet for the agent',
  execute: async () => flea.wallet.create(),
});

// ── Trade tool ───────────────────────────────────────────
export const tradeTool = createTool({
  id: 'open-trade',
  description: 'Open a perpetual futures position via Hyperliquid DEX',
  inputSchema: z.object({
    market: z.string().describe('e.g. BTC, ETH, SOL'),
    size:   z.number().positive().describe('Position size in USD'),
    side:   z.enum(['long', 'short']),
  }),
  execute: async ({ context }) => flea.trading.openPosition(context),
});

// ── Casino flip tool ─────────────────────────────────────
export const casinoFlipTool = createTool({
  id: 'casino-flip',
  description: 'Flip a provably fair coin. Returns heads or tails plus payout.',
  inputSchema: z.object({
    amount: z.number().positive().describe('Wager in USDC'),
    choice: z.enum(['heads', 'tails']),
  }),
  execute: async ({ context }) => flea.casino.coinFlip(context),
});

// ── Domain check tool ────────────────────────────────────
export const domainCheckTool = createTool({
  id: 'domain-check',
  description: 'Check whether a .crypto / .eth / .x domain name is available',
  inputSchema: z.object({
    name: z.string().describe('Domain name including TLD, e.g. myagent.crypto'),
  }),
  execute: async ({ context }) => flea.domains.check(context.name),
});
src/agent/index.ts TypeScript 
import { Agent } from '@mastra/core';
import { openai } from '@ai-sdk/openai';
import {
  walletTool, tradeTool, casinoFlipTool, domainCheckTool,
} from './tools';

export const financialAgent = new Agent({
  name: 'FinancialAgent',
  instructions: 'You are a crypto-native AI agent. Use the tools available to manage wallets, open trades on Hyperliquid, play provably fair casino games, and register Web3 domains on behalf of your user.',
  model: openai('gpt-4o'),
  tools: {
    walletTool,
    tradeTool,
    casinoFlipTool,
    domainCheckTool,
  },
});

Integration Benefits

Why Mastra and Purple Flea Are a Natural Fit

Mastra's design philosophy — type everything, validate at the boundary, stream by default — maps perfectly onto the requirements of financial infrastructure. Here is why the combination outperforms gluing raw REST calls into a LangChain tool.

🔷

TypeScript End-to-End

Both Mastra and Purple Flea are written in TypeScript. Your editor autocompletes trade parameters, wallet fields, and casino game options with zero additional type declarations needed.

🛡️

Zod Schema Validation at Every Boundary

Purple Flea's Mastra tools use Zod inputSchema so invalid LLM outputs are caught before they reach the blockchain. No more "0x" instead of "0.1" as a trade size.

🌊

Streaming for Long-Running Operations

Crash game multipliers and trade fill updates stream through Mastra's event pipeline so the agent UI reflects live state without polling hacks.

🧠

Persistent Agent Memory

The Mastra memory store persists wallet addresses, open positions, and active casino sessions across conversation turns so the agent never loses context about its on-chain state.

🔁

Workflow Composition

Mastra workflows let you chain Purple Flea tools — check balance, open trade, monitor crash — as a typed async pipeline with retry logic baked in, no external queue required.

🏗️

Production-Ready from Day One

All tools include error codes, rate-limit metadata, and structured error objects that Mastra's retry middleware understands. Deploy with confidence, not hope.
