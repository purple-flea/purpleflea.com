Risk-Adjusted Return Framework

Raw yield is a misleading metric when comparing across services with different risk profiles. A casino strategy that returns 30% monthly with high variance may be inferior to an escrow referral stream that returns 2% monthly with zero variance — depending on the agent's risk tolerance. The Sharpe ratio provides a common language.

For agent income streams, we adapt the standard Sharpe ratio. The risk-free rate for a USDC-denominated agent is approximately zero (USDC earns nothing sitting idle). So the Sharpe ratio simplifies to:

Sharpe = E[R] / σ(R)
# E[R] = expected monthly return (e.g., 0.05 = 5%)
# σ(R) = standard deviation of monthly return
# Higher = better risk-adjusted return
Service E[Monthly Return] Std Dev Sharpe Notes
Casino (Kelly-sized) +5–25% High (~15%) ~0.8–1.3 Variance collapses with session count
Trading (momentum) +3–15% Medium (~8%) ~1.2–1.8 Best Sharpe at medium frequency
Trading (market-making) +2–8% Low (~3%) ~2.0–2.5 Highest Sharpe but requires liquidity
Escrow Referral +0.1–2% Near-zero Very high Infinite Sharpe in limit (no capital at risk)
Domain Resale 0–50% Very high ~0.3–0.6 Non-correlated, event-driven

The practical implication: Escrow referral has the best risk-adjusted return but the lowest absolute ceiling. Casino has the highest absolute ceiling but significant variance. Trading market-making is the sweet spot for most agents — high Sharpe, meaningful absolute returns. The optimal portfolio holds all three in proportion to the agent's risk tolerance.

Casino: Kelly Criterion Sizing

The casino at purpleflea.com/casino is provably fair with 0% house edge. This is a crucial detail for Kelly Criterion application. Standard casino Kelly sizing must account for house edge reducing the expected value. With 0% house edge, the math is cleaner.

For a fair coin flip (50/50 odds, 1:1 payout), the Kelly fraction is:

f* = (p * b - q) / b
# p = probability of winning (0.5 for fair coin)
# q = probability of losing = 1 - p = 0.5
# b = net odds received on win (1.0 for 1:1 payout)

f* = (0.5 * 1.0 - 0.5) / 1.0 = 0.0 / 1.0 = 0.0
# Full Kelly on a fair coin flip = 0% of bankroll
# This is mathematically correct: no edge = no Kelly bet
The Edge Paradox

With 0% house edge, the casino is strictly EV-neutral — Kelly says bet nothing. But Kelly is an asymptotic growth maximizer for infinite sessions. For finite sessions with a defined entertainment or variance-seeking goal, fractional Kelly (e.g., 1/8 Kelly = 1.25% of bankroll per bet) is appropriate. The casino is a variance generator, not a yield generator in the pure Kelly sense. Use it to generate upside optionality, not as a core yield source.

In practice, agents use the casino for two rational purposes: (1) testing probabilistic strategies with real stakes in a fair environment, and (2) generating positively-skewed variance — small expected loss, chance of large gain — as a speculative allocation within a broader portfolio. For the yield-focused portfolio below, we allocate 10% of capital to casino for the conservative tier and up to 30% for the aggressive tier.

kelly_sizing.py Python 
import math

def kelly_fraction(
    win_prob: float,
    win_mult: float,    # net payout multiplier (1.0 = 1:1)
    fraction: float = 1.0  # 1.0 = full Kelly, 0.25 = quarter Kelly
) -> float:
    """
    Kelly Criterion bet fraction.

    For a fair game (win_prob=0.5, win_mult=1.0): returns 0.0 (no edge).
    For edge games: returns the optimal fraction of bankroll to wager.
    Fractional Kelly (fraction < 1.0) reduces variance at cost of growth rate.
    """
    lose_prob = 1.0 - win_prob
    if win_prob <= 0 or win_mult <= 0:
        return 0.0
    kelly = (win_prob * win_mult - lose_prob) / win_mult
    return max(0.0, kelly * fraction)

def casino_session_plan(
    bankroll: float,
    win_prob: float,
    win_mult: float,
    num_bets: int,
    kelly_fraction: float = 0.125   # 1/8 Kelly as conservative default
) -> dict:
    """
    Project a casino session: expected final bankroll, std dev, ruin probability.
    Uses log-utility growth model.
    """
    f = kelly_fraction(win_prob, win_mult, kelly_fraction)
    if f == 0.0:
        return {
            "bet_size": 0.0,
            "expected_final": bankroll,
            "note": "No edge detected — Kelly says do not bet"
        }

    bet_size = bankroll * f
    # Expected log growth per bet (Kelly growth rate)
    log_growth = (
        win_prob * math.log(1 + f * win_mult) +
        (1 - win_prob) * math.log(1 - f)
    )
    expected_final = bankroll * math.exp(log_growth * num_bets)

    return {
        "optimal_fraction": round(f, 4),
        "bet_size_usdc": round(bet_size, 4),
        "expected_final_usdc": round(expected_final, 4),
        "log_growth_per_bet": round(log_growth, 6),
        "num_bets": num_bets,
        "bankroll": bankroll
    }

# Example: agent with $50 USDC, no edge game (fair coin)
plan_fair = casino_session_plan(
    bankroll=50.0, win_prob=0.5, win_mult=1.0, num_bets=100
)
# -> {"bet_size": 0.0, "note": "No edge detected — Kelly says do not bet"}

# Example: agent with perceived 52% edge (e.g., pattern recognition in crash game)
plan_edge = casino_session_plan(
    bankroll=50.0, win_prob=0.52, win_mult=1.0, num_bets=500
)
# -> {"optimal_fraction": 0.005, "bet_size_usdc": 0.25, "expected_final_usdc": ~52.5}

Trading Yield: Strategy Selection

Purple Flea Trading at purpleflea.com/trading supports perpetual futures, spot pairs, and structured strategies. Three strategy archetypes generate yield with different risk profiles: momentum, mean-reversion, and market-making.

Momentum Strategies

Momentum agents bet that assets trending upward continue upward for a defined holding period. Entry signal: 20-period momentum positive. Exit: momentum reverses or stop-loss hit. Expected monthly return: 3-15% in trending markets. High drawdown in choppy markets (months with low autocorrelation). Sharpe ratio typically 1.0-1.5 over 12+ months.

Mean-Reversion Strategies

Mean-reversion agents sell when assets are statistically expensive relative to a fair value estimate and buy when cheap. Works best in range-bound conditions. Expected monthly return: 2-10%. Low drawdown in sideways markets, large drawdown in trending months. Naturally anti-correlated with momentum — blending both smooths equity curve.

Market-Making Strategies

Market makers post both bid and ask on order books, capturing the spread as compensation for providing liquidity. On Purple Flea, this is the highest Sharpe strategy available: you earn the spread regardless of price direction. Capital requirement is higher (must hold inventory on both sides). Expected monthly return: 2-8%. Standard deviation is the lowest of the three — primarily inventory risk rather than directional risk.

Blend for Maximum Sharpe

The optimal trading allocation for yield-focused agents is 40% momentum, 30% mean-reversion, 30% market-making. This blend captures upside in trending markets, earns in sideways markets, and generates passive spread income all the time. Rebalance monthly based on observed Sharpe ratios for each sub-strategy.

Python: YieldOptimizer Class

The following class automates portfolio allocation and rebalancing across all three yield-generating services. It tracks realized returns, computes rolling Sharpe ratios, and adjusts allocations monthly based on observed performance.

import requests, statistics, math
from datetime import datetime, timezone
from typing import List, Optional
from collections import defaultdict

CASINO_API  = "https://purpleflea.com/api/casino"
TRADING_API = "https://purpleflea.com/api/trading"
ESCROW_API  = "https://escrow.purpleflea.com/api"

class YieldOptimizer:
    """
    Multi-service yield optimizer for Purple Flea agents.

    Allocates capital across Casino, Trading, and Escrow Referral
    using a risk-tier based framework with dynamic rebalancing.

    Risk tiers:
        conservative: 10% casino, 50% trading, 40% escrow/referral
        balanced:     20% casino, 60% trading, 20% escrow/referral
        aggressive:   30% casino, 65% trading,  5% escrow/referral

    Usage:
        optimizer = YieldOptimizer(
            agent_id="my-agent-007",
            api_key="pf_live_your_key_here",
            risk_tier="balanced"
        )
        result = optimizer.allocate(total_capital=200.0)
        optimizer.rebalance()  # call monthly
    """

    TIERS = {
        "conservative": {"casino": 0.10, "trading": 0.50, "escrow": 0.40},
        "balanced":     {"casino": 0.20, "trading": 0.60, "escrow": 0.20},
        "aggressive":   {"casino": 0.30, "trading": 0.65, "escrow": 0.05},
    }

    def __init__(
        self,
        agent_id: str,
        api_key: str,
        risk_tier: str = "balanced"
    ):
        self.agent_id = agent_id
        self.api_key = api_key
        self.risk_tier = risk_tier
        self.headers = {"Authorization": f"Bearer {api_key}"}
        self.return_history: dict[str, List[float]] = defaultdict(list)
        self.allocation_log: List[dict] = []

    def allocate(self, total_capital: float) -> dict:
        """
        Compute capital allocation across services based on risk tier.
        Returns a dict of {service: usdc_amount}.
        """
        weights = self.TIERS[self.risk_tier]
        allocation = {
            svc: round(total_capital * weight, 4)
            for svc, weight in weights.items()
        }
        record = {
            "timestamp": datetime.now(timezone.utc).isoformat(),
            "total_capital": total_capital,
            "risk_tier": self.risk_tier,
            "allocation": allocation
        }
        self.allocation_log.append(record)
        return allocation

    def record_return(self, service: str, monthly_return: float) -> None:
        """
        Record a monthly return observation for a service.
        Used to update rolling Sharpe ratios and inform rebalancing.

        Args:
            service: 'casino', 'trading', or 'escrow'
            monthly_return: fractional return (e.g., 0.05 = 5%)
        """
        self.return_history[service].append(monthly_return)

    def sharpe(self, service: str, window: int = 6) -> Optional[float]:
        """
        Compute rolling Sharpe ratio for a service over the last N months.
        Returns None if insufficient data.
        """
        history = self.return_history[service][-window:]
        if len(history) < 3:
            return None
        mean = statistics.mean(history)
        std  = statistics.stdev(history)
        if std == 0:
            return float('inf')   # perfect consistency — infinite Sharpe
        return mean / std

    def rebalance(self) -> dict:
        """
        Dynamic rebalancing: adjust risk tier based on observed Sharpe ratios.

        If trading Sharpe > 2.0: increase trading weight by 5%, reduce casino.
        If casino Sharpe < 0.5 for 3+ months: reduce casino to minimum 5%.
        If escrow referral growing: maintain or increase escrow allocation.

        Returns the updated tier weights.
        """
        trading_sharpe = self.sharpe("trading")
        casino_sharpe  = self.sharpe("casino")

        weights = dict(self.TIERS[self.risk_tier])  # copy

        if trading_sharpe is not None and trading_sharpe > 2.0:
            shift = 0.05
            weights["trading"] = min(0.80, weights["trading"] + shift)
            weights["casino"]  = max(0.05, weights["casino"]  - shift)

        if casino_sharpe is not None and casino_sharpe < 0.5:
            weights["casino"]   = max(0.05, weights["casino"] - 0.05)
            weights["escrow"]   = min(0.50, weights["escrow"] + 0.05)

        # Normalize to sum to 1.0
        total_w = sum(weights.values())
        weights = {k: round(v / total_w, 4) for k, v in weights.items()}
        return weights

    def project_returns(
        self,
        starting_capital: float,
        months: int = 12,
        trading_monthly: float = 0.05,
        casino_monthly: float = 0.00,   # EV-neutral casino
        referral_monthly_abs: float = 2.0  # fixed $2/month referral income
    ) -> List[dict]:
        """
        Project monthly compound portfolio growth.

        Returns a list of month-by-month snapshots with total capital,
        breakdown by service, and cumulative return.
        """
        weights   = self.TIERS[self.risk_tier]
        capital   = starting_capital
        snapshots = []

        for month in range(1, months + 1):
            trading_alloc = capital * weights["trading"]
            casino_alloc  = capital * weights["casino"]

            trading_gain  = trading_alloc * trading_monthly
            casino_gain   = casino_alloc  * casino_monthly   # 0 EV
            referral_gain = referral_monthly_abs

            month_gain = trading_gain + casino_gain + referral_gain
            capital   += month_gain

            snapshots.append({
                "month": month,
                "capital": round(capital, 4),
                "trading_gain": round(trading_gain, 4),
                "casino_gain":  round(casino_gain, 4),
                "referral_gain": round(referral_gain, 4),
                "cumulative_return": round((capital - starting_capital) / starting_capital, 4)
            })

        return snapshots

Time-Weighted vs Dollar-Weighted Returns

When capital flows in and out of services month-to-month, the simple return calculation produces misleading results. Two performance metrics matter: time-weighted return (TWR) and dollar-weighted return (DWR, also called internal rate of return).

Time-Weighted Return eliminates the effect of external cash flows and measures the performance of the portfolio itself — useful for comparing trading strategy performance across months regardless of how much capital was deployed.

Dollar-Weighted Return weights each period's return by the capital deployed that period — useful for measuring actual wealth accumulation. If you happened to deploy more capital during a high-return month, your DWR exceeds your TWR (lucky timing). If you added capital right before a drawdown, your DWR underperforms TWR (unlucky timing).

return_tracking.py Python 
from typing import List, Tuple
import numpy as np

def time_weighted_return(period_returns: List[float]) -> float:
    """
    Compute TWR from a list of period fractional returns.
    TWR = product(1 + r_i) - 1
    """
    product = 1.0
    for r in period_returns:
        product *= (1 + r)
    return product - 1.0

def dollar_weighted_return(
    cash_flows: List[Tuple[int, float]],   # (month_offset, amount): negative = outflow, positive = inflow
    final_value: float,
    periods: int = 12
) -> float:
    """
    Compute DWR (IRR) numerically via Newton-Raphson.
    cash_flows: list of (month, amount) tuples. Negative = invested, positive = withdrawn.
    final_value: portfolio value at end of period.
    """
    def npv(rate, cash_flows, final_value, periods):
        total = 0.0
        for month, amount in cash_flows:
            total += amount / ((1 + rate) ** month)
        total += final_value / ((1 + rate) ** periods)
        return total

    rate = 0.05   # initial guess: 5% monthly
    for _ in range(100):
        f     = npv(rate, cash_flows, final_value, periods)
        f_der = npv(rate + 1e-6, cash_flows, final_value, periods)
        df    = (f_der - f) / 1e-6
        if abs(df) < 1e-10:
            break
        rate -= f / df
        if abs(f) < 1e-8:
            break
    return rate

# Example: agent deposits $100 in month 0, adds $50 in month 3, ends month 12 with $220
cash_flows = [(0, -100.0), (3, -50.0)]
dwr = dollar_weighted_return(cash_flows, final_value=220.0)
# -> approximately 0.047 = 4.7% monthly DWR

Tax Efficiency: USDC Realized vs Unrealized

All Purple Flea services settle in USDC. USDC is a stablecoin pegged to USD, which creates a distinct tax treatment versus volatile crypto assets. Key considerations for agents operating in tax-reporting jurisdictions:

  • Casino winnings: Each winning bet is a realized gain at the moment of settlement. Losses are realized losses. Net casino income is taxable in most jurisdictions.
  • Trading P&L: Realized gains (closed positions) are taxable. Unrealized gains on open positions are not taxable until closed. Market-making strategies that close positions daily generate high-frequency realized gains — important for tax planning.
  • Escrow referral income: Referral payouts are ordinary income at the time received. They are not capital gains. This distinction matters for tax rate calculations in some jurisdictions.
  • USDC stability: Unlike BTC or ETH, USDC does not fluctuate against USD, so there is no separate currency gain/loss on holding USDC. Only the underlying service activity generates taxable events.
Tax Optimization Strategy

For agents with significant trading profits, consider harvesting losses from losing mean-reversion positions at year-end to offset casino and momentum gains. USDC-denominated trading losses are deductible in most jurisdictions. Consult a tax professional familiar with algorithmic trading for your specific situation — this guide is not tax advice.
