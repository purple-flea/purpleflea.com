1. Order Book Anatomy: Bids, Asks, Depth & Spread

An order book is a continuously updated electronic record of all outstanding limit orders for a traded instrument. It has two sides: the bid side (buy orders, sorted highest first) and the ask side (sell orders, sorted lowest first). The gap between them is the spread.

Each entry in the book contains three values: price level, aggregate quantity at that level, and (in Level 3 data) individual order identifiers. When a new market order arrives it consumes limit orders starting at the best price and walking deeper into the book until filled — this "walking the book" is the mechanism behind slippage.

Key structural concepts:

  • Best bid (BB): Highest price any buyer is currently willing to pay.
  • Best ask (BA): Lowest price any seller is currently willing to accept.
  • Mid price: (BB + BA) / 2 — the theoretical fair value between the two sides.
  • Spread: BA - BB in absolute terms; expressed in basis points (bps) = (spread / mid) * 10000.
  • Depth: Total volume available within N price levels on each side. Shallow depth = small market orders cause large moves.
  • Cumulative depth curve: Sum of volume from the best price outward; a visual representation of liquidity at every price.
import requests
from dataclasses import dataclass
from typing import List, Tuple

@dataclass
class BookLevel:
    price: float
    size:  float

@dataclass
class OrderBook:
    symbol: str
    bids: List[BookLevel]  # sorted high → low
    asks: List[BookLevel]  # sorted low  → high

    @property
    def best_bid(self) -> float:
        return self.bids[0].price if self.bids else 0.0

    @property
    def best_ask(self) -> float:
        return self.asks[0].price if self.asks else 0.0

    @property
    def mid_price(self) -> float:
        return (self.best_bid + self.best_ask) / 2

    @property
    def spread(self) -> float:
        return self.best_ask - self.best_bid

    @property
    def spread_bps(self) -> float:
        return self.spread / self.mid_price * 10000 if self.mid_price > 0 else 0.0

    def bid_depth(self, levels: int = 10) -> float:
        return sum(l.size for l in self.bids[:levels])

    def ask_depth(self, levels: int = 10) -> float:
        return sum(l.size for l in self.asks[:levels])

    def cumulative_depth(self, side: str) -> List[Tuple[float, float]]:
        """Return [(price, cumulative_size), ...] for depth curve plotting."""
        levels = self.bids if side == "bid" else self.asks
        cum = 0.0
        result = []
        for l in levels:
            cum += l.size
            result.append((l.price, cum))
        return result

2. Level 1 vs Level 2 vs Level 3 Market Data

Market data comes in three tiers of granularity. Understanding the differences is critical for agents that need to decide how much data to ingest and what signals they can extract from each tier.

Property Level 1 Level 2 Level 3
Also called Top of book, BBO Market depth, L2 snapshot Full order-by-order feed
Contents Best bid, best ask, last trade price, volume All price levels with aggregated quantities Individual order IDs, timestamps, and modifications
Update frequency Every trade / quote change Every change at any level Every order event (new, cancel, modify, fill)
Typical depth 1 level per side 5–500 levels per side Full book (unlimited)
Data volume Very low Medium Very high
Use cases Simple trend following, basic signal feeds Imbalance signals, VWAP, slippage estimation HFT, iceberg detection, queue position tracking

Most agent strategies operate effectively at Level 2. Level 3 is valuable for agents doing market making, where queue position within a price level determines whether you get filled before your order is skipped.

3. Order Book Imbalance Calculations & Price Prediction

Order Book Imbalance (OBI) is the single most studied microstructure signal. The core intuition: if there is much more volume on the bid side than the ask side, buy pressure exceeds sell pressure and the price is more likely to rise in the near future.

The basic formula normalizes the difference between bid and ask volume to the range [-1, +1]:

OBI = (Vbid - Vask) / (Vbid + Vask)

More sophisticated variants weight levels by their distance from the best price (levels close to the spread carry more predictive power) and apply decay functions to avoid giving equal weight to a level 50 ticks away from the best quote.

import math
import numpy as np

def obi_simple(book: OrderBook, levels: int = 5) -> float:
    """Basic OBI over top N levels. Returns value in [-1, +1]."""
    bid_vol = sum(l.size for l in book.bids[:levels])
    ask_vol = sum(l.size for l in book.asks[:levels])
    total   = bid_vol + ask_vol
    return round((bid_vol - ask_vol) / total, 4) if total > 0 else 0.0

def obi_exponential(book: OrderBook, levels: int = 10, decay: float = 0.5) -> float:
    """Exponentially-weighted OBI. Closer levels matter more."""
    bid_w = ask_w = 0.0
    for i, l in enumerate(book.bids[:levels]):
        w      = math.exp(-decay * i)
        bid_w += l.size * w
    for i, l in enumerate(book.asks[:levels]):
        w      = math.exp(-decay * i)
        ask_w += l.size * w
    total = bid_w + ask_w
    return round((bid_w - ask_w) / total, 4) if total > 0 else 0.0

def obi_price_weighted(book: OrderBook, levels: int = 10) -> float:
    """
    Price-distance weighted OBI.
    Weight = 1 / (1 + |level_price - mid|).
    Levels at the spread get near-unit weight; outliers get near-zero.
    """
    mid = book.mid_price
    bid_w = ask_w = 0.0
    for l in book.bids[:levels]:
        w      = 1.0 / (1.0 + abs(l.price - mid))
        bid_w += l.size * w
    for l in book.asks[:levels]:
        w      = 1.0 / (1.0 + abs(l.price - mid))
        ask_w += l.size * w
    total = bid_w + ask_w
    return round((bid_w - ask_w) / total, 4) if total > 0 else 0.0

def obi_signal(obi: float) -> str:
    if   obi >  0.60: return "strong_buy"
    elif obi >  0.20: return "mild_buy"
    elif obi < -0.60: return "strong_sell"
    elif obi < -0.20: return "mild_sell"
    else:             return "neutral"

def obi_mid_price_prediction(obi: float, spread: float) -> float:
    """
    Roll & Stoll (1990) variant: estimate short-term mid-price drift.
    Returns expected mid-price change in same units as spread.
    Positive = mid expected to rise; negative = expected to fall.
    """
    # Scaling factor 0.5 derived empirically; tune per market
    return obi * spread * 0.5

book = fetch_order_book("ETH-USDC")
obi   = obi_exponential(book)
drift = obi_mid_price_prediction(obi, book.spread)
print(ff"OBI={obi:.3f}  Signal={obi_signal(obi)}  Predicted drift={drift:+.4f}")

4. VWAP and TWAP Execution Algorithms

When an agent needs to execute a large order, placing it all at once causes excessive slippage. Execution algorithms split the parent order into smaller child orders spread across time. TWAP (Time-Weighted Average Price) and VWAP (Volume-Weighted Average Price) are the two foundational approaches.

TWAP

  • Divides order equally across fixed time intervals
  • Simple to implement; predictable
  • Does not adapt to liquidity conditions
  • Best when volume is flat across the day
  • Benchmark: average of all mid-prices in window

VWAP

  • Sizes child orders proportional to expected volume
  • Trades more when the market is active
  • Requires historical volume profile per symbol
  • Benchmark: volume-weighted average fill price
  • Outperforms TWAP in high-variance volume environments
import time, requests, asyncio
from typing import List

# ─── TWAP Executor ───────────────────────────────────────────────────

class TWAPExecutor:
    """
    Time-Weighted Average Price executor.
    Splits a parent order into equal child orders at regular intervals.
    """

    def __init__(self, symbol: str, total_qty: float,
                 duration_secs: int, num_slices: int, api_key: str):
        self.symbol        = symbol
        self.total_qty     = total_qty
        self.duration      = duration_secs
        self.num_slices    = num_slices
        self.slice_qty     = round(total_qty / num_slices, 6)
        self.interval      = duration_secs / num_slices
        self.api_key       = api_key
        self.fills: List[dict] = []

    def _place_order(self, qty: float, side: str) -> dict:
        resp = requests.post(
            "https://purpleflea.com/api/v1/orders",
            headers={"Authorization": ff"Bearer {self.api_key}"},
            json={
                "symbol": self.symbol,
                "type":   "market",
                "side":   side,
                "qty":    qty,
            },
            timeout=5
        )
        return resp.json()

    def run(self, side: str = "buy"):
        print(ff"TWAP: {self.total_qty} {self.symbol} in {self.num_slices} slices")
        for i in range(self.num_slices):
            fill = self._place_order(self.slice_qty, side)
            self.fills.append(fill)
            print(ff"  Slice {i+1}/{self.num_slices}: {fill.get('fill_price','?')} @ {self.slice_qty}")
            if i < self.num_slices - 1:
                time.sleep(self.interval)
        return self._summary()

    def _summary(self) -> dict:
        prices = [f.get("fill_price", 0) for f in self.fills if f.get("fill_price")]
        return {
            "avg_fill_price": sum(prices) / len(prices) if prices else 0,
            "slices_executed": len(self.fills),
            "total_filled":   self.slice_qty * len(self.fills),
        }


# ─── VWAP Executor ───────────────────────────────────────────────────

class VWAPExecutor:
    """
    Volume-Weighted Average Price executor.
    Uses historical volume profile to schedule child order sizes.
    """

    def __init__(self, symbol: str, total_qty: float,
                 volume_profile: List[float], duration_secs: int, api_key: str):
        # volume_profile: list of fractional weights (must sum to 1.0)
        self.symbol   = symbol
        self.total_qty = total_qty
        self.profile   = volume_profile
        self.duration  = duration_secs
        self.api_key   = api_key
        self.interval  = duration_secs / len(volume_profile)
        self.fills: List[dict] = []

    def default_volume_profile(n_slices: int) -> List[float]:
        """
        Approximate intraday U-shaped volume profile for crypto.
        More volume at open and close, quieter in the middle.
        """
        import numpy as np
        t      = np.linspace(0, 1, n_slices)
        # U-shape: high at 0, dip in middle, high at 1
        weight = 1.0 - 0.6 * np.sin(np.pi * t)
        weight = weight / weight.sum()
        return weight.tolist()

    def run(self, side: str = "buy"):
        n = len(self.profile)
        print(ff"VWAP: {self.total_qty} {self.symbol} across {n} volume-proportional slices")
        for i, weight in enumerate(self.profile):
            qty  = round(self.total_qty * weight, 6)
            fill = self._place_order(qty, side)
            self.fills.append({**fill, "target_weight": weight, "qty": qty})
            print(ff"  Slice {i+1}/{n}: weight={weight:.3f} qty={qty}")
            if i < n - 1:
                time.sleep(self.interval)

    def _place_order(self, qty, side):
        return requests.post(
            "https://purpleflea.com/api/v1/orders",
            headers={"Authorization": ff"Bearer {self.api_key}"},
            json={"symbol": self.symbol, "type": "market", "side": side, "qty": qty},
            timeout=5
        ).json()

5. Detecting Iceberg Orders & Hidden Liquidity

Iceberg orders (also called "reserve orders") display only a small visible quantity while hiding a much larger total size. Exchanges replenish the visible portion automatically each time it fills. If you see a price level repeatedly reload to the same size after each trade, an iceberg is very likely present.

Detection heuristics agents use:

  • Reload pattern: A level disappears after a trade but reappears at the same price within 1-3 order book updates.
  • Constant clip size: Repeated fills of exactly the same quantity at the same price is a strong signal.
  • Trade-to-depth ratio anomaly: Trade volume at a level far exceeds the depth that was displayed — hidden liquidity absorbed the extra.
  • Short time between fill and reload: Human orders don't get replaced in milliseconds; automated icebergs do.
from collections import defaultdict, deque
import time

class IcebergDetector:
    """
    Detects iceberg orders by tracking level reload behavior.
    Requires a stream of (book_snapshot, timestamp) pairs.
    """

    def __init__(self, reload_window_ms: float = 500, min_reloads: int = 3):
        self.reload_window = reload_window_ms / 1000
        self.min_reloads   = min_reloads
        # price → deque of (disappeared_at, reappeared_at, size) tuples
        self._level_history: dict = defaultdict(deque)
        self._last_book: dict = {}    # price → size
        self._disappeared: dict = {}  # price → timestamp it disappeared
        self._ice_scores: dict = defaultdict(int)

    def update(self, book: OrderBook):
        now   = time.time()
        sizes = {l.price: l.size for l in book.asks}

        # Detect disappearances
        for price, prev_size in self._last_book.items():
            if price not in sizes:
                self._disappeared[price] = (now, prev_size)

        # Detect reloads
        for price, size in sizes.items():
            if price in self._disappeared:
                gone_at, gone_size = self._disappeared.pop(price)
                elapsed = now - gone_at
                if elapsed < self.reload_window:
                    # Quick reload: candidate iceberg
                    clip = round(gone_size, 4)
                    self._level_history[price].append((gone_at, now, clip))
                    # Score based on repeating clip sizes
                    clips = [h[2] for h in self._level_history[price]]
                    if len(clips) >= self.min_reloads:
                        unique_clips = len(set(clips))
                        if unique_clips == 1:
                            self._ice_scores[price] += 2
                        else:
                            self._ice_scores[price] += 1

        self._last_book = sizes

    def iceberg_levels(self, threshold: int = 5) -> List[float]:
        """Return price levels with iceberg score above threshold."""
        return [p for p, s in self._ice_scores.items() if s >= threshold]

    def has_support_iceberg(self, book: OrderBook) -> bool:
        """True if an iceberg is sitting near the best ask (strong seller)."""
        icebergs = set(self.iceberg_levels())
        return book.best_ask in icebergs

detector = IcebergDetector(reload_window_ms=200, min_reloads=4)
# In your polling loop:
# detector.update(book)
# print("Icebergs at:", detector.iceberg_levels())

Iceberg detection is probabilistic — fast market makers legitimately post and cancel repeatedly. Always combine iceberg signals with trade flow direction before acting; a reload at the ask into strong buy OBI is a different situation than a reload at the ask into strong sell OBI.

6. Market Impact Estimation: Almgren-Chriss Model

The Almgren-Chriss (AC) model from 2001 is the canonical framework for optimal execution. It models market impact as having two components: temporary impact (price moves while your order is being absorbed, recovers afterward) and permanent impact (the market adjusts to your information, never fully recovering).

The model minimizes a cost function that trades off execution shortfall against the risk (variance) of price movement during execution. The risk-aversion parameter lambda controls how aggressively the agent front-loads trades to reduce variance at the cost of higher impact.

Cost = E[Implementation Shortfall] + λ × Var[Implementation Shortfall]
Temporary impact: η × (dq/dt)    Permanent impact: γ × q 
import numpy as np

class AlmgrenChriss:
    """
    Almgren-Chriss optimal execution model.

    Parameters:
      total_qty    : shares / contracts to execute
      T            : execution horizon in seconds
      n_intervals  : number of child orders
      sigma        : annualised volatility (e.g., 0.90 for 90% annual vol)
      eta          : temporary impact coefficient (price moves per unit per-sec rate)
      gamma        : permanent impact coefficient (price moves per unit total)
      lam          : risk-aversion parameter (0=pure cost min, high=front-load)
    """

    def __init__(self, total_qty: float, T: float, n_intervals: int,
                 sigma: float, eta: float, gamma: float, lam: float = 1e-6):
        self.X   = total_qty
        self.T   = T
        self.N   = n_intervals
        self.tau = T / n_intervals
        self.sigma  = sigma
        self.eta    = eta
        self.gamma  = gamma
        self.lam    = lam

    def optimal_schedule(self) -> np.ndarray:
        """
        Returns optimal holding trajectory x[0..N] where x[0]=total_qty, x[N]=0.
        Child order at slice k = x[k] - x[k+1].
        """
        from math import sinh, cosh

        # AC closed-form: x(t) = X * sinh(kappa*(T-t)) / sinh(kappa*T)
        kappa_sq = (self.lam * self.sigma**2) / self.eta
        kappa    = np.sqrt(kappa_sq)

        times = np.linspace(0, self.T, self.N + 1)
        denom = sinh(kappa * self.T)

        if denom < 1e-10:
            # Degenerate case: uniform schedule (kappa ≈ 0)
            return self.X * np.linspace(1, 0, self.N + 1)

        holdings = self.X * np.array([sinh(kappa * (self.T - t)) / denom for t in times])
        holdings[-1] = 0.0
        return holdings

    def child_order_sizes(self) -> np.ndarray:
        """Returns array of N child order quantities that sum to total_qty."""
        x = self.optimal_schedule()
        return np.diff(-x)   # positive values = shares sold/bought each slice

    def expected_cost(self) -> dict:
        """Compute expected execution cost and its variance."""
        x = self.optimal_schedule()
        v = np.diff(-x) / self.tau  # trading rate per slice

        temp_cost  = self.eta * np.sum(v**2) * self.tau
        perm_cost  = self.gamma * np.sum(x[:-1] * np.diff(-x))
        variance   = self.sigma**2 * self.tau * np.sum(x[:-1]**2)

        return {
            "temporary_impact":  round(float(temp_cost), 6),
            "permanent_impact":  round(float(perm_cost), 6),
            "total_expected_cost": round(float(temp_cost + perm_cost), 6),
            "variance":          round(float(variance), 6),
        }

# Example: buy 100 ETH over 1 hour in 12 slices
ac = AlmgrenChriss(
    total_qty=100.0,
    T=3600,
    n_intervals=12,
    sigma=0.90,      # 90% annualised vol
    eta=0.0001,      # temporary impact coefficient
    gamma=0.00005,   # permanent impact coefficient
    lam=1e-6         # low risk aversion = spread evenly
)

7. Bid-Ask Spread Analysis & Market Maker Behavior

The bid-ask spread is not random — it encodes information about inventory risk, adverse selection risk, and competitive pressure among market makers. Agents can use spread dynamics as a signal in their own right.

The three classic components of the spread (Glosten-Milgrom and Kyle models):

  • Order processing component: Pure transaction cost — the market maker's operational cost per trade, which is near-zero on automated platforms.
  • Inventory component: The market maker widens spread when their inventory is skewed. A lopsided position creates directional risk, so they require compensation via a wider spread.
  • Adverse selection component: The market maker's compensation for the risk of trading against an informed agent. When informed traders are active (high VPIN), market makers widen spreads to protect themselves.
import numpy as np
from typing import List

def roll_spread_estimator(prices: List[float]) -> float:
    """
    Roll (1984) estimator: infer effective spread from price autocorrelation.
    Effective spread = 2 * sqrt(-Cov(dP_t, dP_{t-1}))
    Works even when you only have trade prices, not quotes.
    """
    changes = np.diff(prices)
    cov = np.cov(changes[:-1], changes[1:])[0][1]
    if cov >= 0:
        return 0.0   # No negative autocorrelation => cannot estimate
    return 2 * np.sqrt(-cov)

def quoted_vs_effective_spread(book: OrderBook, fill_price: float) -> dict:
    """
    Compare quoted spread (visible) vs effective spread (actual cost).
    If effective > quoted, trades are consuming liquidity beyond the spread.
    """
    quoted   = book.spread
    mid      = book.mid_price
    effective = 2 * abs(fill_price - mid)
    price_improvement = max(0, quoted - effective)

    return {
        "quoted_spread":      round(quoted, 6),
        "effective_spread":   round(effective, 6),
        "price_improvement":  round(price_improvement, 6),
        "spread_capture_pct": round(effective / quoted * 100, 2) if quoted > 0 else 0,
    }

def spread_regime(spread_bps: float) -> str:
    """Classify spread tightness. Typical ranges for liquid crypto perpetuals."""
    if   spread_bps < 2:   return "very_tight"   # institutional-grade liquidity
    elif spread_bps < 5:   return "tight"         # good for takers
    elif spread_bps < 15:  return "normal"        # typical retail market
    elif spread_bps < 50:  return "wide"          # elevated vol or thin book
    else:                   return "very_wide"     # crisis / illiquid conditions

8. Trade Flow Toxicity & Adverse Selection (VPIN)

Volume-synchronized Probability of Informed Trading (VPIN) is an order flow toxicity metric. High VPIN means one side of the market is systematically dominating volume — a signature of informed traders with directional conviction. Market makers who fail to detect this end up trading against agents that know something they don't.

VPIN uses volume buckets rather than time intervals, making it robust to the variable-rate nature of crypto markets. Each bucket collects a fixed quantity of volume, then measures the imbalance between buy-classified and sell-classified trades within it.

from collections import deque
import numpy as np

class VPINCalculator:
    """
    VPIN estimator using tick-rule trade classification.
    Tick rule: price up = buyer-initiated, price down = seller-initiated.

    bucket_size : volume per bucket (tune to ~1/50 of average daily volume)
    n_buckets   : rolling window for VPIN (typically 50)
    """

    def __init__(self, bucket_size: float = 100, n_buckets: int = 50):
        self.bucket_size   = bucket_size
        self.n_buckets     = n_buckets
        self._buy_vols     = deque(maxlen=n_buckets)
        self._sell_vols    = deque(maxlen=n_buckets)
        self._cur_buy      = 0.0
        self._cur_sell     = 0.0
        self._prev_price   = None

    def add_trade(self, price: float, volume: float):
        if self._prev_price is not None:
            if   price > self._prev_price: self._cur_buy  += volume
            elif price < self._prev_price: self._cur_sell += volume
            else:
                # No tick: split 50/50 (Lee-Ready rule alternative)
                self._cur_buy  += volume / 2
                self._cur_sell += volume / 2
        self._prev_price = price

        while (self._cur_buy + self._cur_sell) >= self.bucket_size:
            total = self._cur_buy + self._cur_sell
            ratio = self.bucket_size / total
            b     = self._cur_buy  * ratio
            s     = self._cur_sell * ratio
            self._buy_vols.append(b)
            self._sell_vols.append(s)
            self._cur_buy  -= b
            self._cur_sell -= s

    def vpin(self) -> float:
        """VPIN in [0, 1]. Values above 0.35 indicate elevated toxicity."""
        n = len(self._buy_vols)
        if n < 5:
            return 0.5
        buys   = np.array(self._buy_vols)
        sells  = np.array(self._sell_vols)
        totals = buys + sells
        imbalances = np.abs(buys - sells)
        safe_totals = np.where(totals > 0, totals, 1)
        return float(np.mean(imbalances / safe_totals))

    def toxicity_regime(self) -> str:
        v = self.vpin()
        if   v < 0.15: return "very_low"
        elif v < 0.25: return "low"
        elif v < 0.35: return "moderate"
        elif v < 0.50: return "high"
        else:           return "extreme"

# Market-maker position sizing based on VPIN
def vpin_adjusted_size(base_size: float, vpin_score: float,
                        max_reduction: float = 0.9) -> float:
    """
    Scale down position size as VPIN rises.
    At VPIN=0.5 (extreme), size is reduced to (1 - max_reduction) of base.
    """
    reduction = min(max_reduction, vpin_score * max_reduction / 0.5)
    return base_size * (1.0 - reduction)

10. Optimal Execution: IS, POV, and Adaptive Algorithms

Beyond TWAP and VWAP, agents that need best execution use more adaptive algorithms:

  • Implementation Shortfall (IS): Minimizes the gap between the decision price and average fill price, accounting for both market impact and timing risk. This is the Almgren-Chriss objective.
  • Percentage of Volume (POV): Continuously participates as a fixed percentage of market volume. Adapts naturally to liquidity — trades fast in active markets, slow in quiet ones.
  • Arrival Price (AP): Targets the mid-price at the time the parent order arrives. Accepts more variance than IS but simpler to benchmark.
  • Adaptive algorithms: Monitor real-time signals (OBI, spread, VPIN) and accelerate or slow execution based on current conditions.
class POVExecutor:
    """
    Percentage-of-Volume executor.
    Participates at `pov_rate` fraction of observed market volume.
    Stops when total_qty is fully executed.
    """

    def __init__(self, symbol: str, total_qty: float,
                 pov_rate: float = 0.05, api_key: str = ""):
        self.symbol      = symbol
        self.remaining   = total_qty

        self.api_key     = api_key

    def on_trade_event(self, market_volume: float, side: str):
        """Call this whenever a market trade occurs. Participates proportionally."""
        if self.remaining <= 0:
            return

        if target > 0:
            self._place(target, side)
            self.remaining -= target
            self.executed  += target

    """
    Adaptive TWAP that accelerates when OBI is favourable and slows
    when VPIN is elevated. Never executes into a wide spread.
    """

    def __init__(self, symbol: str, total_qty: float, base_slices: int,
                 side: str, api_key: str):

        self.remaining = total_qty

        self.side      = side
        self.api_key   = api_key
        self.executed  = 0.0
        self.vpin_calc = VPINCalculator()

    def tick(self, book: OrderBook):
        """Call this at each scheduled interval."""
        if self.remaining <= 0:
            return

        obi  = obi_simple(book, levels=5)
        vpin = self.vpin_calc.vpin()

        # Base per-slice quantity
        base_qty = self.remaining / max(1, self.base_slices)

        # Speed-up factor: favourable OBI → execute more this tick
        if self.side == "buy":
            obi_multiplier = 1.0 + max(0, obi) * 0.5
        else:
            obi_multiplier = 1.0 + max(0, -obi) * 0.5

        # Slow-down when VPIN is high (bad conditions for market orders)
        vpin_factor = max(0.2, 1.0 - vpin * 1.5)

        # Skip if spread is too wide
        if book.spread_bps > 20:
            print(f"Tick skipped: spread {book.spread_bps:.1f}bps too wide")
            return

        qty = min(self.remaining, base_qty * obi_multiplier * vpin_factor)
        self._place(round(qty, 6))
        self.remaining -= qty
        self.executed  += qty
        self.base_slices = max(1, self.base_slices - 1)

    def _place(self, qty: float):
        requests.post(
            "https://purpleflea.com/api/v1/orders",

// JavaScript — real-time order book with local state maintenance
const WebSocket = require('ws');

class LiveOrderBook {
  constructor(symbol) {
    this.symbol = symbol;
    this.bids   = new Map();  // price → size
    this.asks   = new Map();
    this.ws     = null;
    this.listeners = [];
  }

  connect() {
    const url = `wss://purpleflea.com/ws/orderbook?symbol=${this.symbol}`;
    this.ws   = new WebSocket(url);

    this.ws.on('message', (raw) => {
      const msg = JSON.parse(raw);

      if (msg.type === 'snapshot') {
        // Full book snapshot on connect
        this.bids.clear();
        this.asks.clear();
        msg.bids.forEach(([p, s]) => this.bids.set(+p, +s));
        msg.asks.forEach(([p, s]) => this.asks.set(+p, +s));
      } else if (msg.type === 'delta') {
        // Incremental update: size=0 means level deleted
        msg.bids.forEach(([p, s]) => {
          if (+s === 0) this.bids.delete(+p);
          else          this.bids.set(+p, +s);
        });
        msg.asks.forEach(([p, s]) => {
          if (+s === 0) this.asks.delete(+p);
          else          this.asks.set(+p, +s);
        });
      }

      this._notify();
    });

    this.ws.on('close', () => {
      console.log('WS closed — reconnecting in 2s');
      setTimeout(() => this.connect(), 2000);
    });
  }

  bestBid() { return Math.max(...this.bids.keys()); }
  bestAsk() { return Math.min(...this.asks.keys()); }
  midPrice() { return (this.bestBid() + this.bestAsk()) / 2; }
  spreadBps() {
    const mid = this.midPrice();
    return (this.bestAsk() - this.bestBid()) / mid * 10000;
  }

  obi(levels = 5) {
    const sortedBids = [...this.bids.entries()].sort((a,b) => b[0]-a[0]);
    const sortedAsks = [...this.asks.entries()].sort((a,b) => a[0]-b[0]);
    const bVol = sortedBids.slice(0, levels).reduce((s,[,v]) => s+v, 0);
    const aVol = sortedAsks.slice(0, levels).reduce((s,[,v]) => s+v, 0);
    const total = bVol + aVol;
    return total > 0 ? (bVol - aVol) / total : 0;
  }

  onUpdate(fn) { this.listeners.push(fn); }
  _notify()   { this.listeners.forEach(fn => fn(this)); }
}

12. Building a Limit Order Book Simulator

A realistic order book simulator is essential for backtesting microstructure strategies without expensive real-market data. The core data structure is a sorted dictionary: bids sorted descending by price, asks sorted ascending. Matching logic walks the opposite side when market orders arrive.

import uuid, time
from sortedcontainers import SortedDict
from dataclasses import dataclass, field
from typing import Optional, List

@dataclass
class Order:
    order_id: str
    side:     str         # "buy" or "sell"
    price:    Optional[float]  # None = market order
    qty:      float
    filled:   float = 0.0
    ts:       float = field(default_factory=time.time)

    @property
    def remaining(self): return self.qty - self.filled
    @property
    def is_market(self):  return self.price is None

class LimitOrderBook:
    """
    Minimal matching-engine limit order book.
    Supports market orders, limit orders, and cancellations.
    Price-time priority within each level.
    """

    def __init__(self):
        # SortedDict with negated keys for bids (highest bid = lowest neg key)
        self._bids: SortedDict = SortedDict(lambda k: -k)
        self._asks: SortedDict = SortedDict()
        self._orders: dict = {}  # order_id → Order
        self.trades: List[dict] = []

    def submit(self, side: str, qty: float,
               price: float = None) -> Order:
        o = Order(str(uuid.uuid4()), side, price, qty)
        self._orders[o.order_id] = o
        if o.is_market:
            self._match_market(o)
        else:
            self._match_limit(o)
            if o.remaining > 0:
                self._rest(o)
        return o

    def cancel(self, order_id: str) -> bool:
        o = self._orders.get(order_id)
        if not o or o.remaining <= 0:
            return False
        self._remove_resting(o)
        return True

    def _match_market(self, o: Order):
        book = self._asks if o.side == "buy" else self._bids
        while o.remaining > 0 and book:
            best_price = next(iter(book))
            queue      = book[best_price]
            while o.remaining > 0 and queue:
                resting = queue[0]
                fill    = min(o.remaining, resting.remaining)
                o.filled       += fill
                resting.filled += fill
                self.trades.append({
                    "price":  best_price,
                    "qty":    fill,
                    "taker": o.order_id,
                    "maker": resting.order_id,
                    "ts":    time.time()
                })
                if resting.remaining <= 0:
                    queue.pop(0)
            if not queue:
                del book[best_price]

    def _match_limit(self, o: Order):
        if o.side == "buy":
            while o.remaining > 0 and self._asks:
                best = next(iter(self._asks))
                if best > o.price: break
                self._fill_at(o, self._asks, best)
        else:
            while o.remaining > 0 and self._bids:
                best = next(iter(self._bids))
                if best < o.price: break
                self._fill_at(o, self._bids, best)

    def _fill_at(self, taker, book, price):
        queue = book[price]
        while taker.remaining > 0 and queue:
            maker = queue[0]
            fill  = min(taker.remaining, maker.remaining)
            taker.filled += fill; maker.filled += fill
            self.trades.append({"price": price, "qty": fill})
            if maker.remaining <= 0: queue.pop(0)
        if not queue: del book[price]

    def _rest(self, o: Order):
        book = self._bids if o.side == "buy" else self._asks
        if o.price not in book:
            book[o.price] = []
        book[o.price].append(o)

    def _remove_resting(self, o: Order):
        book = self._bids if o.side == "buy" else self._asks
        if o.price in book:
            book[o.price] = [x for x in book[o.price] if x.order_id != o.order_id]
            if not book[o.price]: del book[o.price]

    @property
    def best_bid(self): return next(iter(self._bids), None)
    @property
    def best_ask(self): return next(iter(self._asks), None)

13. Latency & Infrastructure Considerations

Order book strategies are sensitive to latency. Even a simple imbalance momentum trade degrades rapidly if order delivery lags book updates by more than a few hundred milliseconds. Key latency sources for agents running on Purple Flea:

Latency Source Typical Range Mitigation
Network round-trip (REST) 20–150ms Use WebSocket for book; REST only for order submission
WebSocket tick-to-process 1–5ms Keep handler code minimal; offload heavy computation
Agent decision logic Variable Pre-compute thresholds; avoid blocking I/O in tick handler
Order submission 10–80ms Submit async; don't wait for ack before updating local state
Exchange matching 0.1–5ms Cannot control; factor into slippage estimates

For latency-sensitive strategies, prefer the following architecture:

  • Maintain the full order book in-process as a local in-memory structure (updated via WebSocket deltas).
  • Compute all microstructure signals on each tick synchronously in O(N) time — avoid database reads in the hot path.
  • Submit orders asynchronously; never await an order acknowledgment before computing the next signal.
  • Track your own open orders locally; reconcile against the exchange state periodically (every 1–5 seconds) rather than on every tick.
  • Add circuit breakers: if latency between consecutive book updates exceeds a threshold, pause trading and reconnect.
import asyncio, json, time
import websockets, aiohttp

class LatencyMonitor:
    """Tracks WebSocket message latency and fires circuit breaker if stale."""

    def __init__(self, stale_threshold_ms: float = 500):
        self.threshold = stale_threshold_ms / 1000
        self._last_msg = time.time()
        self.stale_count = 0

    def on_message(self):
        now = time.time()
        gap = now - self._last_msg
        self._last_msg = now
        if gap > self.threshold:
            self.stale_count += 1
            print(ff"STALE: {gap*1000:.0f}ms gap — count={self.stale_count}")
            return True
        return False

    def should_halt(self, max_stale: int = 3) -> bool:
        return self.stale_count >= max_stale

14. Backtesting Order Book Strategies

Backtesting microstructure strategies is harder than backtesting OHLCV-based strategies because order book data is high-frequency and the simulation must handle partial fills, queue position, and market impact realistically. The key principles:

  • Use tick-level data. OHLCV bars erase the intrabar microstructure that drives your signals. Store raw book snapshots or deltas at each update.
  • Model fill probability. A limit order at the best bid is not guaranteed to fill even if a trade prints at that price — it depends on queue position. Approximate with a probabilistic fill model.
  • Apply realistic latency. Add a simulated network delay of 20-100ms between signal generation and simulated order submission. OBI signals often decay within 200ms.
  • Avoid look-ahead bias. Never use the book state at time T to construct signals that are supposed to arrive at time T-1.
  • Account for market impact in the simulation. Your simulated trades should move the book, at least temporarily, to avoid unrealistic fill assumptions.
import pandas as pd
import numpy as np

class OBIBacktest:
    """
    Simple OBI momentum backtest over a list of historical book snapshots.
    Each snapshot: dict with 'bids', 'asks', 'ts' keys.
    Signals open/close positions at each tick.
    """

    def __init__(self, entry_threshold: float = 0.55,
                 exit_threshold: float = 0.15,
                 position_size: float = 1.0,
                 latency_ticks: int = 2,
                 fee_rate: float = 0.001):
        self.entry_th   = entry_threshold
        self.exit_th    = exit_threshold
        self.pos_size   = position_size
        self.latency    = latency_ticks  # ticks of simulated delay
        self.fee_rate   = fee_rate
        self.position   = 0.0
        self.entry_price = 0.0
        self.pnl_history: List[float] = []
        self._pending: list = []         # pending orders (latency queue)

    def run(self, snapshots: list) -> pd.DataFrame:
        records = []
        signals = []

        # Pre-compute signals with latency offset
        for i, snap in enumerate(snapshots):
            bids = [(BookLevel(float(p), float(s))) for p, s in snap["bids"][::1]]
            asks = [(BookLevel(float(p), float(s))) for p, s in snap["asks"][::1]]
            ob   = OrderBook(snap.get("symbol", "UNK"), bids, asks)
            signals.append({
                "obi":  obi_exponential(ob),
                "mid":  ob.mid_price,
                "spread_bps": ob.spread_bps,
            })

        for i in range(self.latency, len(signals)):
            sig  = signals[i - self.latency]  # signal from N ticks ago
            now  = signals[i]
            obi  = sig["obi"]
            mid  = now["mid"]

            if now["spread_bps"] > 25:
                records.append({"i": i, "action": "skip", "pos": self.position, "pnl": 0})
                continue

            pnl = 0.0
            if self.position == 0:
                if   obi > self.entry_th:  self._open(1, mid)
                elif obi < -self.entry_th: self._open(-1, mid)
            else:
                # Close when OBI weakens
                if (self.position > 0 and obi < self.exit_th) or \
                   (self.position < 0 and obi > -self.exit_th):
                    pnl = self._close(mid)

            records.append({"i": i, "mid": mid, "obi": obi,
                             "pos": self.position, "pnl": pnl})

        return pd.DataFrame(records)

    def _open(self, direction: int, price: float):
        self.position    = direction * self.pos_size
        self.entry_price = price * (1 + direction * self.fee_rate)

    def _close(self, price: float) -> float:
        exit_price  = price * (1 - np.sign(self.position) * self.fee_rate)
        pnl         = self.position * (exit_price - self.entry_price)
        self.pnl_history.append(pnl)
        self.position    = 0.0
        self.entry_price = 0.0
        return pnl

    def summary(self) -> dict:
        h = np.array(self.pnl_history)
        if len(h) == 0: return {"trades": 0}
        wins  = h[h > 0]
        total = h.sum()
        sharpe = h.mean() / h.std() * np.sqrt(252) if h.std() > 0 else 0
        return {
            "trades":     len(h),
            "win_rate":   round(len(wins) / len(h), 3),
            "total_pnl":  round(float(total), 4),
            "sharpe":     round(float(sharpe), 3),
            "max_win":    round(float(wins.max()) if len(wins) > 0 else 0, 4),
        }
