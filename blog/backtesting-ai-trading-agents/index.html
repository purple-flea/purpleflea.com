Backtesting AI Trading Agents:
How to Test Before You Trade Live

March 4, 2026 Purple Flea Team 9 min read

Every AI agent developer has the same impulse: the strategy looks compelling, the code is clean, so why not just deploy it? The answer is that markets are adversarial environments where your intuitions are systematically wrong until proven otherwise. Backtesting is the proof.

An agent that deploys without backtesting is gambling with real capital. An agent that backtests properly — with realistic fees, slippage, and out-of-sample validation — knows exactly what to expect before any money is at risk. This guide shows you how to build that process from scratch.

Why Backtesting Matters for AI Agents

Human traders have intuition, market experience, and can shut down a losing strategy in real time. AI agents typically run unattended — sometimes for hours or days. A flawed strategy deployed at 3 AM can drain a wallet before anyone notices. Backtesting is the circuit breaker you build before deployment, not after.

Three specific failure modes that backtesting catches:

  • The strategy has negative expectancy. It looks good in your head but loses money in actual historical data. Backtesting reveals this in seconds.
  • The strategy cannot survive drawdowns. Even profitable strategies go through extended losing periods. A 40% drawdown may require your agent to operate for 6 months before recovering — is that acceptable?
  • Fees eliminate the edge. A strategy that trades 20 times per day may show +30% annual returns before fees, and -5% after. Backtesting with realistic cost assumptions prevents this surprise.

A Simple Python Backtesting Framework From Scratch

Before using a library, build a minimal backtester yourself. Understanding the mechanics prevents misuse of more complex tools later.

Python — Minimal backtester
import pandas as pd
import numpy as np
from dataclasses import dataclass, field
from typing import List, Optional

@dataclass
class Trade:
    entry_price: float
    exit_price: float
    size: float
    direction: str  # 'long' or 'short'
    fee_pct: float = 0.0005  # 0.05% taker fee

    @property
    def pnl(self) -> float:
        raw = (self.exit_price - self.entry_price) / self.entry_price
        if self.direction == "short":
            raw = -raw
        fees = self.fee_pct * 2  # entry + exit
        return (raw - fees) * self.size

@dataclass
class BacktestResult:
    trades: List[Trade]
    equity_curve: List[float]
    initial_capital: float

    @property
    def total_return_pct(self):
        return (self.equity_curve[-1] - self.initial_capital) / self.initial_capital * 100

    @property
    def win_rate_pct(self):
        wins = sum(1 for t in self.trades if t.pnl > 0)
        return wins / len(self.trades) * 100 if self.trades else 0

    @property
    def max_drawdown_pct(self):
        peak = self.equity_curve[0]
        max_dd = 0
        for v in self.equity_curve:
            peak = max(peak, v)
            dd = (v - peak) / peak * 100
            max_dd = min(max_dd, dd)
        return max_dd

    @property
    def sharpe_ratio(self):
        daily_returns = pd.Series(self.equity_curve).pct_change().dropna()
        if daily_returns.std() == 0:
            return 0
        return (daily_returns.mean() / daily_returns.std()) * np.sqrt(365)


def run_backtest(
    candles: pd.DataFrame,
    strategy_fn,
    initial_capital: float = 1000.0,
    position_size_pct: float = 0.10,  # 10% per trade
    fee_pct: float = 0.0005,
) -> BacktestResult:
    equity = initial_capital
    equity_curve = [equity]
    trades = []
    position: Optional[dict] = None

    for i in range(1, len(candles)):
        row = candles.iloc[i]
        history = candles.iloc[:i]

        signal = strategy_fn(history)

        if position and signal == "close":
            trade = Trade(
                entry_price=position["entry"],
                exit_price=row["close"],
                size=position["size"],
                direction=position["direction"],
                fee_pct=fee_pct,
            )
            equity += trade.pnl
            trades.append(trade)
            equity_curve.append(equity)
            position = None

        elif not position and signal in ("long", "short"):
            size = equity * position_size_pct
            position = {"entry": row["close"], "size": size, "direction": signal}

    return BacktestResult(trades=trades, equity_curve=equity_curve, initial_capital=initial_capital)

Backtesting a Moving Average Crossover on BTC/USDC

The MA crossover is the canonical first strategy: buy when a fast moving average crosses above a slow one (golden cross), sell when it crosses below (death cross). It is simple enough to understand fully, and complex enough to reveal real backtesting issues.

Python — MA crossover strategy + fetch data
import requests
import pandas as pd

def fetch_candles(market: str, interval: str = "1h", limit: int = 5000) -> pd.DataFrame:
    # Use Purple Flea Trading API for historical OHLCV
    r = requests.get(
        "https://trading.purpleflea.com/v1/candles",
        params={"market": market, "interval": interval, "limit": limit},
    )
    r.raise_for_status()
    df = pd.DataFrame(r.json()["candles"])
    df["ts"] = pd.to_datetime(df["ts"], unit="ms")
    df = df.set_index("ts").sort_index()
    for col in ["open", "high", "low", "close", "volume"]:
        df[col] = df[col].astype(float)
    return df

def ma_crossover_strategy(history: pd.DataFrame) -> str:
    """Returns 'long', 'short', 'close', or 'hold'."""
    if len(history) < 50:
        return "hold"

    closes = history["close"]
    ma20_now = closes.iloc[-20:].mean()
    ma50_now = closes.iloc[-50:].mean()
    ma20_prev = closes.iloc[-21:-1].mean()
    ma50_prev = closes.iloc[-51:-1].mean()

    golden_cross = (ma20_prev < ma50_prev) and (ma20_now >= ma50_now)
    death_cross  = (ma20_prev > ma50_prev) and (ma20_now <= ma50_now)

    if golden_cross:
        return "long"
    if death_cross:
        return "close"
    return "hold"

# Run it
df = fetch_candles("BTC-PERP", interval="1h", limit=5000)
result = run_backtest(df, ma_crossover_strategy, initial_capital=1000)

print(f"Total return:  {result.total_return_pct:+.1f}%")
print(f"Sharpe ratio:  {result.sharpe_ratio:.2f}")
print(f"Max drawdown:  {result.max_drawdown_pct:.1f}%")
print(f"Win rate:      {result.win_rate_pct:.1f}%")
print(f"Total trades:  {len(result.trades)}")

Key Metrics and What They Tell You

Total Return
Net profit/loss as a percentage of initial capital. Necessary but not sufficient — a 200% return with a 90% drawdown is not deployable.
Sharpe Ratio
Annualized return divided by annualized volatility. Above 1.0 is acceptable; above 2.0 is excellent. This normalizes return by risk taken.
Max Drawdown
Largest peak-to-trough decline in portfolio value. If your agent can't survive the worst historical drawdown psychologically and financially, the strategy is not suitable.
Win Rate
Percentage of trades that are profitable. A 40% win rate can still be highly profitable if winners average 3x the size of losers. Never evaluate win rate in isolation.

Common Backtesting Pitfalls

  • Look-ahead bias: Using data that wasn't available at the time of the signal. The most common example: computing a daily RSI using the day's close and placing the order at the same day's open. The close wasn't known when the order was placed. Always ensure signals are computed strictly from data available at the bar's open time.
  • Overfitting: Tuning parameters until they perfectly fit historical data. A 20/50 MA crossover found through testing 100 parameter combinations will almost certainly fail on new data. Use out-of-sample testing: train on 60% of data, validate on the remaining 40%, and do not adjust after seeing validation results.
  • Ignoring transaction costs: A strategy trading 10 times daily at 0.05% fee pays 18% annually in fees alone. Include maker fees, taker fees, funding rates, and slippage in every backtest.
  • Ignoring slippage: Your market order does not fill at the close price. In thin markets, a $5,000 order may move price by 0.1–0.3% against you. Add 2–5 bps of slippage to every simulated trade.
  • Single-period testing: A strategy that works in a bull market may be catastrophic in a bear market. Test across multiple regime types: 2022 bear, 2023 recovery, 2024 bull run.

import requests

TRADING_API = "https://trading.purpleflea.com"
API_KEY = "YOUR_API_KEY"

def paper_trade_signal(signal: str, market: str = "BTC-PERP"):
    """Execute signal with minimum position size for paper trading."""
    if signal not in ("long", "close"):
        return

    # Get current price
    info = requests.get(
        f"{TRADING_API}/v1/markets/{market}",
        headers={"Authorization": f"Bearer {API_KEY}"},
    ).json()
    mark_price = float(info["mark_price"])

    # Open with $1 notional (minimum paper position)
    size = 1.0 / mark_price

    if signal == "long":
        requests.post(
            f"{TRADING_API}/v1/orders",
            json={"market": market, "side": "buy", "size": size, "type": "market"},
            headers={"Authorization": f"Bearer {API_KEY}"},
        )
        print(f"PAPER: Opened long {size:.6f} BTC @ ${mark_price:,.2f}")

    elif signal == "close":
        positions = requests.get(
            f"{TRADING_API}/v1/positions",
            headers={"Authorization": f"Bearer {API_KEY}"},
        ).json()["positions"]
        btc_pos = next((p for p in positions if p["market"] == market), None)
        if btc_pos:
            requests.post(
                f"{TRADING_API}/v1/orders",
                json={"market": market, "side": "sell", "size": btc_pos["size"], "type": "market"},
                headers={"Authorization": f"Bearer {API_KEY}"},

            print(f"PAPER: Closed long, PnL: ${btc_pos['unrealized_pnl']:+.4f}")

Transition to Live Trading

Once a strategy has passed three validation gates — in-sample backtest, out-of-sample backtest, and two weeks of paper trading — it is ready for cautious live deployment.

The recommended scaling path:

  1. Start at 10% of intended capital for the first two weeks of live trading
  2. Compare live results to paper trade results daily — if they diverge significantly, investigate before scaling
  3. Scale to 50% of capital after two weeks of live results matching backtest expectations
  4. Reach full capital allocation only after four weeks of consistent live performance
