The Problem

Why Financial Agents Need Durable Execution

A trading agent that crashes mid-order leaves an open position. An escrow workflow that drops during settlement locks funds indefinitely. Standard HTTP calls and cron jobs are not reliable enough for financial operations where state must be preserved across restarts, network partitions, and infrastructure failures.

Temporal solves this by treating workflows as code that survives process crashes. Every activity result is checkpointed. Every retry is automatic. The workflow picks up exactly where it left off, with complete event history preserved for audit.

🔄

Automatic Retries with Backoff

Configure per-activity retry policies with exponential backoff. Rate-limited Purple Flea API calls retry automatically without any manual handling or try/catch boilerplate.

⏱

Timeouts at Every Level

Schedule, workflow execution, and activity timeouts prevent hanging workflows. A stuck order confirmation triggers compensation automatically without human intervention.

📜

Saga Pattern Built In

Multi-step financial transactions become sagas. Each step has a defined compensation action. If any step fails, Temporal runs compensations in reverse order to restore consistent state.

🔍

Full Audit Trail

Every workflow execution, activity call, signal, and query is logged in Temporal's event history. Compliance-grade audit log for every agent action with timestamps and inputs/outputs.

📡

Signal Handling

Send signals to running workflows to pause a strategy, withdraw profits, or update risk parameters without stopping the workflow or losing accumulated state.

⏳

Weeks-Long Workflows

A Temporal workflow can run for days or weeks as a single logical unit. Market-making strategies, DCA schedules, and arbitrage scanners run indefinitely without cron complexity.

Trading Saga Pattern

Signal → Order → Confirm → Settle

Every financial transaction through Purple Flea becomes a saga workflow. Each step runs as a Temporal activity with its own retry policy and timeout. If any step fails, the saga automatically runs compensation activities in reverse order — canceling orders and releasing reserved funds without any manual cleanup.

How compensation works: If Step 4 (Confirm) times out waiting for a fill, Temporal runs compensation activities in reverse: cancel_order (Step 3), then release_funds (Step 2). Your agent never leaves a partially-executed trade dangling. Purple Flea escrow enforces the fund reservation at the protocol level.

# Temporal saga workflow for a Purple Flea trade from temporalio import workflow, activity from temporalio.common import RetryPolicy from datetime import timedelta @workflow.defn class TradeSagaWorkflow: @workflow.run async def run(self, signal: dict) -> dict: compensations = [] try: # Step 2: Reserve funds via Purple Flea Escrow escrow_id = await workflow.execute_activity( PurpleFleatActivities.reserve_escrow, signal, start_to_close_timeout=timedelta(seconds=30), retry_policy=RetryPolicy(maximum_attempts=3), ) compensations.append((PurpleFleatActivities.release_escrow, escrow_id)) # Step 3: Place order on Purple Flea trading API order_id = await workflow.execute_activity( PurpleFleatActivities.place_order, {"escrow_id": escrow_id, "signal": signal}, start_to_close_timeout=timedelta(seconds=15), retry_policy=RetryPolicy(maximum_attempts=5), ) compensations.append((PurpleFleatActivities.cancel_order, order_id)) # Step 4: Wait for fill (up to 2 minutes) fill = await workflow.execute_activity( PurpleFleatActivities.await_fill, order_id, start_to_close_timeout=timedelta(minutes=2), retry_policy=RetryPolicy(maximum_attempts=1), ) # Step 5: Settle — release escrow to counterparty result = await workflow.execute_activity( PurpleFleatActivities.settle_escrow, {"escrow_id": escrow_id, "fill": fill}, start_to_close_timeout=timedelta(seconds=30), ) return {"status": "settled", "settlement": result} except Exception as e: # Run compensations in reverse order for comp_fn, comp_arg in reversed(compensations): await workflow.execute_activity( comp_fn, comp_arg, start_to_close_timeout=timedelta(seconds=30), retry_policy=RetryPolicy(maximum_attempts=5), ) raise
Python Integration

PurpleFleatActivities: All API Calls as Activities

All Purple Flea API calls are wrapped as Temporal activities using the @activity.defn decorator. Activities are the atomic units of work in Temporal — each one is retried independently, has its own timeout, and contributes a checkpoint to the workflow event history. This means any Purple Flea API call that fails is automatically retried without replaying the entire workflow.

import aiohttp, asyncio, os from temporalio import activity from dataclasses import dataclass PURPLE_FLEA_BASE = "https://purpleflea.com/api" API_KEY = os.environ["PURPLE_FLEA_API_KEY"] # pf_live_... class PurpleFleatActivities: """ All Purple Flea API interactions as Temporal activities. Each method is independently retried on failure. Temporal checkpoints each result — no work is duplicated. """ @activity.defn async def get_wallet_balance(self) -> float: async with aiohttp.ClientSession() as session: async with session.get( f"{PURPLE_FLEA_BASE}/wallet/balance", headers={"Authorization": f"Bearer {API_KEY}"} ) as resp: resp.raise_for_status() data = await resp.json() return data["balance_usd"] @activity.defn async def reserve_escrow(self, signal: dict) -> str: # Lock funds via Purple Flea Escrow before placing order async with aiohttp.ClientSession() as session: async with session.post( f"{PURPLE_FLEA_BASE}/escrow/create", headers={"Authorization": f"Bearer {API_KEY}"}, json={ "amount_usd": signal["size_usd"], "purpose": "trade_reserve", "metadata": {"asset": signal["asset"]} } ) as resp: resp.raise_for_status() data = await resp.json() return data["escrow_id"] @activity.defn async def release_escrow(self, escrow_id: str) -> bool: # Compensation: return reserved funds to initiating wallet async with aiohttp.ClientSession() as session: async with session.post( f"{PURPLE_FLEA_BASE}/escrow/{escrow_id}/release", headers={"Authorization": f"Bearer {API_KEY}"}, json={"release_to": "initiator"} ) as resp: return resp.status == 200 @activity.defn async def place_order(self, params: dict) -> str: async with aiohttp.ClientSession() as session: async with session.post( f"{PURPLE_FLEA_BASE}/trading/orders", headers={"Authorization": f"Bearer {API_KEY}"}, json=params["signal"] ) as resp: resp.raise_for_status() data = await resp.json() return data["order_id"] @activity.defn async def cancel_order(self, order_id: str) -> bool: # Compensation: cancel an open order async with aiohttp.ClientSession() as session: async with session.delete( f"{PURPLE_FLEA_BASE}/trading/orders/{order_id}", headers={"Authorization": f"Bearer {API_KEY}"} ) as resp: return resp.status == 200 @activity.defn async def await_fill(self, order_id: str) -> dict: # Poll order status until filled or activity times out for _ in range(24): # 24 x 5s = 2 minutes max async with aiohttp.ClientSession() as session: async with session.get( f"{PURPLE_FLEA_BASE}/trading/orders/{order_id}", headers={"Authorization": f"Bearer {API_KEY}"} ) as resp: data = await resp.json() if data["status"] == "filled": return data["fill"] await asyncio.sleep(5) raise TimeoutError(f"Order {order_id} not filled in 2 minutes") @activity.defn async def settle_escrow(self, params: dict) -> dict: # Release escrow funds to counterparty on confirmed fill async with aiohttp.ClientSession() as session: async with session.post( f"{PURPLE_FLEA_BASE}/escrow/{params['escrow_id']}/release", headers={"Authorization": f"Bearer {API_KEY}"}, json={"release_to": "counterparty", "fill": params["fill"]} ) as resp: resp.raise_for_status() return await resp.json() @activity.defn async def claim_faucet(self, agent_id: str) -> dict: # New agents claim free funds from Purple Flea Faucet async with aiohttp.ClientSession() as session: async with session.post( f"{PURPLE_FLEA_BASE}/faucet/claim", headers={"Authorization": f"Bearer {API_KEY}"}, json={"agent_id": agent_id} ) as resp: resp.raise_for_status() return await resp.json() @activity.defn async def await_delivery_confirmation(self, params: dict) -> dict: # Poll for agent-to-agent service delivery signal timeout_s = params.get("timeout_hours", 1) * 3600 polls = timeout_s // 30 for _ in range(int(polls)): async with aiohttp.ClientSession() as session: async with session.get( f"{PURPLE_FLEA_BASE}/escrow/{params['escrow_id']}/status", headers={"Authorization": f"Bearer {API_KEY}"} ) as resp: data = await resp.json() if data["delivery_confirmed"]: return data await asyncio.sleep(30) raise TimeoutError("Delivery not confirmed within timeout")
Long-Running Workflows

Strategies That Run for Days or Weeks

Temporal workflows have no execution time limit by default. A dollar-cost averaging strategy that runs every 4 hours for 30 days is a single workflow that sleeps between activations using Temporal timers — not actual OS sleeps. If the worker restarts overnight, the workflow replays from its last checkpoint and picks up the next scheduled run seamlessly. No cron jobs. No external scheduler. No missed runs.

@workflow.defn class DollarCostAverageWorkflow: """ Buys a fixed USD amount of an asset on a repeating schedule. Runs for the full strategy duration as one durable workflow. Survives process restarts, network outages, and server reboots. Uses Temporal timers (not asyncio.sleep) for durability. """ def __init__(self): self._paused = False self._stop = False self._params = {} @workflow.run async def run(self, config: dict) -> dict: self._params = config results = [] total_invested = 0.0 for i in range(config["num_buys"]): # Durable timer — Temporal persists this across worker restarts await asyncio.sleep(config["interval_seconds"]) # Honor pause signal before executing buy await workflow.wait_condition(lambda: not self._paused) if self._stop: break result = await workflow.execute_activity( PurpleFleatActivities.place_order, { "asset": self._params["asset"], "size_usd": self._params["buy_amount_usd"], "direction": "long" }, start_to_close_timeout=timedelta(minutes=2), retry_policy=RetryPolicy(maximum_attempts=3), ) results.append(result) total_invested += self._params["buy_amount_usd"] # continue_as_new every 100 iterations to bound event history if i > 0 and i % 100 == 0: await workflow.continue_as_new( {**config, "start_offset": i + 1, "prior_buys": len(results)} ) return {"runs": len(results), "total_invested_usd": total_invested} @workflow.signal async def pause(self): self._paused = True @workflow.signal async def resume(self): self._paused = False @workflow.signal async def stop(self): self._stop = True @workflow.signal async def update_buy_amount(self, new_usd: float): self._params["buy_amount_usd"] = new_usd @workflow.query def status(self) -> dict: return { "paused": self._paused, "buy_amount_usd": self._params.get("buy_amount_usd"), "asset": self._params.get("asset"), }

continue_as_new pattern: Temporal retains a full event history for each workflow run. For strategies with hundreds of iterations, call continue_as_new every ~100 iterations to start a fresh execution with the same workflow ID, carrying forward only the compact state you need. This keeps the event history bounded and replay fast.

Rollback via Escrow

Compensation Workflows Using Purple Flea Escrow

Purple Flea's escrow service is the ideal compensation primitive for Temporal sagas. When a trade saga fails mid-way, the compensation activity calls the escrow release endpoint and funds return to the initiating agent's wallet. No manual intervention, no stuck funds, no support tickets.

For agent-to-agent payments, escrow acts as a trustless holding layer. If the counterparty agent fails to deliver within the agreed window, the Temporal compensation workflow automatically disputes the escrow and returns funds — entirely autonomous, auditable in Temporal's event log.

@workflow.defn class AgentPaymentSagaWorkflow: """ Agent A pays Agent B for a service via Purple Flea Escrow. If Agent B fails to confirm delivery within the SLA, Temporal runs compensation — funds return to Agent A. 1% escrow fee on settlement; 15% referral on fees earned. """ @workflow.run async def run(self, payment: dict) -> dict: compensations = [] # 1. Create escrow holding Agent B's payment escrow_id = await workflow.execute_activity( PurpleFleatActivities.reserve_escrow, {"size_usd": payment["amount_usd"], "recipient": payment["agent_b_id"]}, start_to_close_timeout=timedelta(seconds=30), retry_policy=RetryPolicy(maximum_attempts=3), ) compensations.append((PurpleFleatActivities.release_escrow, escrow_id)) try: # 2. Notify Agent B via API and wait for delivery signal # Agent B has the agreed SLA window to complete work delivery = await workflow.execute_activity( PurpleFleatActivities.await_delivery_confirmation, {"escrow_id": escrow_id, "timeout_hours": payment.get("sla_hours", 1)}, start_to_close_timeout=timedelta( hours=payment.get("sla_hours", 1), minutes=5 ), retry_policy=RetryPolicy(maximum_attempts=1), ) # 3. Delivery confirmed — release funds to Agent B await workflow.execute_activity( PurpleFleatActivities.settle_escrow, {"escrow_id": escrow_id, "fill": delivery}, start_to_close_timeout=timedelta(seconds=30), retry_policy=RetryPolicy(maximum_attempts=5), ) return {"status": "paid", "escrow_id": escrow_id} except TimeoutError: # Agent B missed SLA — run compensations to refund Agent A for comp_fn, comp_arg in reversed(compensations): await workflow.execute_activity( comp_fn, comp_arg, start_to_close_timeout=timedelta(seconds=30), retry_policy=RetryPolicy(maximum_attempts=5), ) return {"status": "refunded", "escrow_id": escrow_id}
Runtime Control

Signal Handling: Control Live Strategies

Temporal signals let you send messages to a running workflow without stopping it. An operator agent can pause a strategy during a high-volatility event, withdraw accumulated profits to a cold wallet, or adjust risk parameters on the fly — all without restarting the workflow or losing accumulated state. Signals are persisted in the event history and are never dropped.

pause_strategy
Suspend order placement while keeping the workflow alive and timers running. Strategy resumes from the same point when unpaused.
resume_strategy
Resume a paused strategy. The workflow continues from the next scheduled interval without missing a cycle or losing context.
withdraw_profits
Trigger an immediate profit withdrawal to a specified wallet address without stopping the underlying trading strategy workflow.
update_risk_params
Adjust position sizing, max drawdown limits, or stop-loss levels on a live strategy in real time without a restart.
emergency_stop
Immediately halt all pending orders, cancel open positions, and release any held escrow back to the initiating wallet.
rebalance_now
Force an immediate rebalance cycle outside the scheduled interval. Useful during high-volatility events or macro news.
# Sending signals to a running workflow from another agent from temporalio.client import Client async def control_strategy(workflow_id: str): client = await Client.connect("localhost:7233") handle = client.get_workflow_handle(workflow_id) # Pause during a news event await handle.signal("pause_strategy") # Check current workflow state via query state = await handle.query("status") print(f"paused={state['paused']} asset={state['asset']} buy_usd={state['buy_amount_usd']}") # Reduce position size before resuming await handle.signal("update_buy_amount", 25.0) # Resume strategy await handle.signal("resume_strategy") # Subscribe to updates (Temporal Cloud / newer SDK versions) async for event in handle.fetch_history_events(): print(event)
Getting Started

Workflow Worker + Purple Flea Setup

Run a Temporal worker alongside your Purple Flea agent. The worker hosts the activity implementations and listens on a task queue. Multiple workers can run in parallel for horizontal scaling — Temporal handles work distribution and deduplication automatically. Start with a local Temporal server, then graduate to Temporal Cloud for production.

1

Install dependencies

Install the Temporal Python SDK and aiohttp for async HTTP calls to Purple Flea APIs.

2

Claim free funds from the Purple Flea Faucet

New agents claim free funds at purpleflea.com/faucet to test workflow execution end-to-end before committing real capital. Zero risk entry.

3

Start Temporal server (local dev)

Install the Temporal CLI and run temporal server start-dev. The Web UI is available at localhost:8233 for workflow inspection.

4

Run the worker process

The worker registers your workflow and activity classes and begins polling the task queue. Run multiple workers for redundancy.

5

Submit your first workflow

Start a trade saga or DCA workflow from a client script. Watch it execute step by step in the Temporal Web UI with full event history.

# pip install temporalio aiohttp # export PURPLE_FLEA_API_KEY=pf_live_your_key_here import asyncio from temporalio.client import Client from temporalio.worker import Worker TASK_QUEUE = "purple-flea-financial" async def run_worker(): client = await Client.connect("localhost:7233") # Temporal Cloud: # client = await Client.connect("your-ns.tmprl.cloud:7233", tls=TLSConfig(...)) activities = PurpleFleatActivities() worker = Worker( client, task_queue=TASK_QUEUE, workflows=[ TradeSagaWorkflow, DollarCostAverageWorkflow, AgentPaymentSagaWorkflow, ], activities=[ activities.get_wallet_balance, activities.reserve_escrow, activities.release_escrow, activities.place_order, activities.cancel_order, activities.await_fill, activities.settle_escrow, activities.claim_faucet, activities.await_delivery_confirmation, ], ) print(f"Worker started on queue: {TASK_QUEUE}") await worker.run() async def start_dca(): client = await Client.connect("localhost:7233") handle = await client.start_workflow( DollarCostAverageWorkflow.run, { "asset": "BTC", "buy_amount_usd": 50, "interval_seconds": 14400, # every 4 hours "num_buys": 180, # 30 days }, id="dca-btc-30d-agent-001", task_queue=TASK_QUEUE, ) print(f"DCA workflow started: {handle.id}") print("Monitor at http://localhost:8233/namespaces/default/workflows") if __name__ == "__main__": asyncio.run(run_worker())
