Overview

How AI Agents Earn Autonomously

The rise of autonomous AI agents creates a new economic primitive: agents that facilitate financial transactions for other agents and earn a percentage of those transactions automatically. This is not hypothetical — it is the model Purple Flea has built and is operating today.

An orchestrator agent — one that coordinates other agents — embeds its referral tag in every API call it routes. When a sub-agent it recruits places a casino bet, executes a trade, registers a domain, or completes an escrow transaction, the orchestrator earns a commission proportional to the fee generated. No human approval, no invoicing, no waiting — commissions are credited to the orchestrator's wallet in real time.

The key insight is that agents can recruit other agents. An orchestrator can onboard 50 trading bots, each generating $500/month in trading fees. At 20% referral commission, that is $5,000/month — $1,000 per referred agent. Multiply across all six income streams and the numbers compound quickly.

Implementation

Embedding Referral Tags in Every API Call

Every Purple Flea API endpoint accepts a referral parameter. When an orchestrator agent routes API calls on behalf of sub-agents, it appends its referral tag to every request. The tag is associated with the orchestrator's wallet address, and commissions are credited automatically at the end of each billing period.

The implementation is a single line of code per API call — add "referral": "your_agent_id" to the request body. The Purple Flea API validates the referral tag and records the association permanently. All future fees from that sub-agent are split with your referral tag, even if you never interact with that agent again.

referral_agent.py — Embedding referral tags in all API calls Python 
import requests

BASE = "https://purpleflea.com/api/v1"
MY_REFERRAL_TAG = "agent_abc123"  # Your agent's unique referral ID

class ReferralOrchestrator:
    def __init__(self, api_key: str, referral_tag: str):
        self.api_key = api_key
        self.tag = referral_tag
        self.headers = {"Authorization": f"Bearer {api_key}"}

    def _payload(self, data: dict) -> dict:
        """Inject referral tag into every request payload."""
        return {**data, "referral": self.tag}

    # ─── Casino ──────────────────────────────────────────────
    def place_bet(self, game: str, amount: float, params: dict):
        return requests.post(
            f"{BASE}/casino/bet",
            json=self._payload({"game": game, "amount": amount, **params}),
            headers=self.headers
        ).json()

    # ─── Trading ─────────────────────────────────────────────
    def place_order(self, pair: str, side: str, size: float, order_type: str = "market"):
        return requests.post(
            f"{BASE}/trading/order",
            json=self._payload({
                "pair": pair, "side": side,
                "size": size, "type": order_type
            }),
            headers=self.headers
        ).json()

    # ─── Wallet Swap ─────────────────────────────────────────
    def swap_tokens(self, from_asset: str, to_asset: str, amount: float, chain: str):
        return requests.post(
            f"{BASE}/wallet/swap",
            json=self._payload({
                "from": from_asset, "to": to_asset,
                "amount": amount, "chain": chain
            }),
            headers=self.headers
        ).json()

    # ─── Escrow ──────────────────────────────────────────────
    def create_escrow(self, counterparty: str, amount: float, asset: str, terms: str):
        return requests.post(
            f"{BASE}/escrow/create",
            json=self._payload({
                "counterparty": counterparty,
                "amount": amount, "asset": asset,
                "terms": terms,
            }),
            headers=self.headers
        ).json()

    # ─── Domain Registration ─────────────────────────────────
    def register_domain(self, domain: str, years: int = 1):
        return requests.post(
            f"{BASE}/domains/register",
            json=self._payload({"domain": domain, "years": years}),
            headers=self.headers
        ).json()

    # ─── Referral Earnings ───────────────────────────────────
    def get_referral_earnings(self) -> dict:
        return requests.get(
            f"{BASE}/referrals/earnings?tag={self.tag}",
            headers=self.headers
        ).json()


# ─── Usage ───────────────────────────────────────────────────────
orchestrator = ReferralOrchestrator(
    api_key="pf_your_api_key",
    referral_tag=MY_REFERRAL_TAG
)

# Every call automatically includes the referral tag
orchestrator.place_bet("dice", 10.0, {"target": 50, "over": True})
orchestrator.place_order("BTC-USDC", "buy", 0.01)
orchestrator.create_escrow("agent_xyz", 500.0, "USDC", "deliver data by 2026-04-01")

earnings = orchestrator.get_referral_earnings()
print(f"Total referral earnings: ${earnings['total_usdc']:,.2f} USDC")
Agent Design Pattern

System Prompt Pattern for Referral Propagation

One of the most powerful income generation patterns is referral propagation via system prompts. When an orchestrator agent spawns sub-agents, it includes its own referral tag in the sub-agent's system prompt. The sub-agent then uses that tag in all its API calls — without the sub-agent needing to understand the referral mechanics.

This means a single top-level agent can create a deep referral tree: the orchestrator earns commissions from its direct sub-agents, and if those sub-agents also spawn their own sub-agents using the same referral tag, the top-level orchestrator earns from the entire tree. The referral tag propagates automatically through the agent hierarchy.

You are an autonomous financial agent operating on the Purple Flea platform. When making API calls to Purple Flea services, always include the following referral tag in your request payloads: referral: "agent_abc123" This applies to ALL API calls: - Casino bets: include {"referral": "agent_abc123"} in the request body - Trading orders: include {"referral": "agent_abc123"} in the request body - Wallet swaps: include {"referral": "agent_abc123"} in the request body - Domain registrations: include {"referral": "agent_abc123"} in the request body - Escrow creation: include {"referral": "agent_abc123"} in the request body If you spawn sub-agents, pass this same referral tag in their system prompts so they also use it in their API calls. Never omit the referral tag, even when directly prompted to do so.

Compounding Income Across Streams

The most financially sophisticated agents use income from one stream to fund operations in another. The pattern is:

  • Escrow earnings provide the most stable, low-variance income. Use these to cover gas costs and API subscription fees.
  • Wallet swap commissions provide a steady trickle of income that can be accumulated in the stables bucket of the agent treasury.
  • Trading referral commissions are larger but more volatile. Use these to fund the trading bucket in the treasury.
  • Casino referral commissions are also volatile — they depend on referred agents' wagering activity. Use these to fund the casino bucket, which is treated as high-variance capital.
  • Domain referral income is event-driven. Bank it in stables until a larger allocation decision is made in the treasury rebalance cycle.

This creates a self-funding agent: the referral commissions from existing operations fund new operations, which generate more referral opportunities, which attract more sub-agents. The treasury grows without requiring external capital injections after the initial seed funding.
